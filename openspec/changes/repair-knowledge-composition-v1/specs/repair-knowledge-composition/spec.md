## ADDED Requirements

### Requirement: Source-bound maintenance knowledge
The builder MUST accept only version-bound pre-repair corpus, preserve exact excerpts, prerequisites and claim roles, and reject reference, hidden and future assets.
#### Scenario: Current buggy behavior
- **WHEN** a source code fact is extracted
- **THEN** it is existing_behavior rather than an asserted correct invariant.

### Requirement: Shared retrieval and distinct set selection
M and H SHALL share state, obligations, units, candidates, rendering, message level and budget. M SHALL use MMR .7. H SHALL use the Goal coverage objective, redundancy and exposure, positive gain per token and best-singleton comparison.
#### Scenario: Repeated coverage
- **WHEN** multiple units cover one obligation
- **THEN** only maximum coverage contributes for that obligation.
#### Scenario: Ablations
- **WHEN** H-no-gap or H-no-exposure is selected
- **THEN** only its declared objective term changes.

### Requirement: Fixed real paired study
The study MUST freeze source/mechanism order before samples, use first native repeat E1/E2, actually continue N/G/L/M/H twice, preserve attempts, and condition confirmation only on the preregistered content-route rule.
#### Scenario: Interrupted attempt
- **WHEN** a reserved cell has no completed result
- **THEN** it remains unknown and is not resampled.

### Requirement: Functional attribution
The report SHALL derive success solely from target behavior and protected regression, separately reporting H-M, content route, costs and six posthoc legacy checks.
#### Scenario: Coverage-only improvement
- **WHEN** H improves coverage but no functional outcomes
- **THEN** no functional benefit is claimed and no default changes.
