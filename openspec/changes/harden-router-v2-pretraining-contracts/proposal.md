## Why

Router Training Data V2 now emits a prompt-only qualification candidate, but the real pretraining and routing path still has a split contract: `embedding_training`, `EmbeddingRouter`, keyword/hybrid/gated verification, the cross-encoder, and the Stage 2 core router can still consume benchmark metadata, while the trainer has no controlled, hash-bound input gate. This final pretraining-contract repair is required before any separately authorized reviewed-data or training work so prompt-only semantics and training admission fail closed end to end.

## What Changes

- Add one shared `router_query_text(prompt)` contract whose only argument is the loader-normalized prompt string and whose result is exactly that string, so the API structure cannot accept task metadata. Route every real core router/query consumer through it: embedding-pair export, `EmbeddingRouter`, `KeywordRouter`, `HybridRouter`, verification-gated scoring, cross-encoder scoring, and Stage 2 core routed prediction export. With the prompt string held constant, changes to task ID, category, difficulty, robustness tags, split, or family metadata MUST NOT change model/query inputs, router scores, or ranking decisions; record identity and structured provenance may still retain those fields.
- **BREAKING**: advance the qualification policy, candidate-row, qualification-report, and manifest contracts from v2 to v3. V3 binds the qualification pack to the shared prompt-only query contract and independently reports `unique_prompt_count=12`, train-policy unique prompt count `8`, missing family values as `null` / `UNAVAILABLE` without inference, and per-skill unique train-positive counts for all 16 skills, including five explicit zero counts.
- Add a trainer-controlled, versioned input package and row schema with package/row hash binding and formal review metadata. Only formally accepted positives and human-reviewed hard negatives may pass the gate; no reviewed data or trainer-ready package is generated by this change.
- Validate the complete package before any Torch import, model construction/loading, output-directory creation, or checkpoint write. One invalid row or package field rejects the entire input. Legacy pair formats, provisional candidates, cross-category easy negatives, reserved source-test rows, blind-derived or Phase 16-derived rows, and rows with missing or invalid review evidence MUST be rejected rather than filtered, inferred, or partially consumed.
- Keep the canonical qualification decision blocked as `REVIEW_REQUIRED`, `KEEP_BASELINE`, and `can_start_training=false`; this contract repair does not supply the missing human acceptance, reviewed hard negatives, family metadata, independent calibration data, reject examples, or target-positive coverage.
- Preserve the committed Phase 14–18 and blind evidence trees with zero modification. No blind-v2 dataset, blind mining, blind rerun, or replacement evidence is created.
- Repair the current pack README and Human Brief wording that still describes a proposal HEAD or an uncommitted apply diff, solely to reflect the existing local commit `f996690700a79ab4c065ed8523340d2fd387f6b9`. This is truth-surface maintenance, not a new evidence or lifecycle phase.
- Keep this as one bounded final pretraining-contract change rather than a numbered phase series. It does not train a model, generate reviewed data, run a GPU/A100 job, create a checkpoint, publish blind-v2 data, change router performance claims, push, open a PR, merge, archive, tag, or release.
- Record remote-validation truth explicitly: remote CI cannot run while the branch is unpushed, and local validation MUST NOT be represented as remote CI.

## Capabilities

### New Capabilities

- `router-query-contract`: Defines the shared prompt-only router query and metadata-invariance requirements across all real core router, reranker, verification, training-export, and Stage 2 routing paths.
- `router-training-input-gate`: Defines the trainer-controlled package and row schemas, hash binding, accepted-positive/reviewed-hard-negative evidence, all-or-nothing validation, and rejection before framework/model/output side effects.

### Modified Capabilities

- `router-training-data-v2-qualification-pack`: Advances the prompt-only qualification artifacts and policy to v3, adds independently computed prompt/family/per-skill statistics, preserves blocked readiness, and keeps protected historical evidence immutable.

## Impact

- Runtime and trainer surfaces: shared query extraction, core routers and verification/reranking helpers, embedding training export, Stage 2 routed prediction export, and the embedding trainer input boundary.
- Qualification and human truth surfaces: the existing candidate/report/manifest/policy artifacts move to v3, and only stale lifecycle wording in the current README/brief is corrected.
- Validation: metadata-invariance, independent-statistic, package/schema/hash, whole-input rejection, pre-framework side-effect, Stage 2, and protected-evidence identity checks are required locally; remote CI remains unavailable without a later push.
- Systems and lifecycle: no new training run, reviewed dataset, dependency installation, network/GPU/A100 use, checkpoint, blind access, evidence rewrite, publication, integration, archive, or release is part of this proposal.
