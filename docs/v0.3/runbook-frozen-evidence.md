# Hermes SkillEval v0.3 Frozen Evidence Runbook

Status: evidence-collection runbook after v0.3 infrastructure completion

Date: 2026-06-28

This runbook starts the next stage after PR-1 through PR-7 infrastructure.
It is for frozen evidence collection only. It does not add infrastructure,
train routers, tune thresholds, promote routers, or claim a full real benchmark
result before frozen runs complete.

## Hard Boundaries

- Do not start PR-8 during this stage.
- Do not modify `src/` or the PR-1 through PR-7 infrastructure to collect
  evidence.
- Do not train, fine-tune, tune thresholds, mine hard negatives, promote a
  router, or add new router variants during evidence collection.
- Do not run a full live-agent benchmark automatically from this runbook.
- Keep SkillRouter official metrics, Hermes diagnostics, and live-agent verifier
  outcomes in separate report sections.
- Default final decision remains `KEEP_BASELINE` unless all validity and
  promotion guardrails pass.
- No full real benchmark result is claimed until the frozen external and frozen
  live-agent runs have completed and passed the evidence gate.

## Artifact Layout

Use one immutable run ID for each collection stage:

```bash
export RUN_ID="v0.3-frozen-YYYYMMDD"
export ARTIFACT_ROOT="artifacts/v0.3/${RUN_ID}"
mkdir -p "${ARTIFACT_ROOT}"
```

Do not commit full external datasets, credentials, raw private traces, model
checkpoints, embedding caches, or unredacted logs. Commit only redacted,
reviewable summaries when explicitly approved.

## 1. Tag Current Protocol Branch

Tag the merged v0.3 infrastructure state before evidence collection:

```bash
git checkout codex/v0.3-pr0-protocol
git pull --ff-only origin codex/v0.3-pr0-protocol
git status --short
git tag -a v0.3.0-infra -m "Hermes SkillEval v0.3 infrastructure complete"
git push origin v0.3.0-infra
```

If `git status --short` is not clean, stop and resolve the dirty state before
tagging.

## 2. Run Real SkillRouter External Evidence

Set paths to the real external data root and frozen prediction files. These
must already exist and must not be generated by tuning on scored labels.

```bash
export SKILLROUTER_DATA_ROOT="/path/to/skillrouter_eval_core"
export EXTERNAL_OUT="${ARTIFACT_ROOT}/skillrouter-external"
mkdir -p "${EXTERNAL_OUT}"
```

Validate the real SkillRouter layout and provenance:

```bash
PYTHONPATH=src python -m hermes_skilleval.cli external-validate \
  --benchmark skillrouter \
  --data-root "${SKILLROUTER_DATA_ROOT}" \
  --output-dir "${EXTERNAL_OUT}/validation" \
  --upstream-ref "<immutable-upstream-commit-or-release-ref>" \
  --license-note "<license-note>"
```

Write the frozen external matrix plan before running the scored matrix:

```bash
PYTHONPATH=src python -m hermes_skilleval.cli external-plan \
  --benchmark skillrouter \
  --data-root "${SKILLROUTER_DATA_ROOT}" \
  --output "${EXTERNAL_OUT}/plan.json" \
  --upstream-ref "<immutable-upstream-commit-or-release-ref>" \
  --license-note "<license-note>" \
  --run-id "${RUN_ID}-skillrouter" \
  --router-config "baseline-minilm:name_only:/path/to/baseline-name-only-predictions.json" \
  --router-config "baseline-minilm:metadata:/path/to/baseline-metadata-predictions.json" \
  --router-config "baseline-minilm:full_body:/path/to/baseline-full-body-predictions.json" \
  --router-config "finetuned-embedding:name_only:/path/to/finetuned-name-only-predictions.json" \
  --router-config "finetuned-embedding:metadata:/path/to/finetuned-metadata-predictions.json" \
  --router-config "finetuned-embedding:full_body:/path/to/finetuned-full-body-predictions.json" \
  --matrix-output "${EXTERNAL_OUT}/matrix.json"
```

Run the frozen external matrix from the plan:

```bash
PYTHONPATH=src python -m hermes_skilleval.cli external-matrix \
  --benchmark skillrouter \
  --plan "${EXTERNAL_OUT}/plan.json" \
  --output "${EXTERNAL_OUT}/matrix.json"
```

## 3. Run Evidence Gate On External Artifacts

Run the unified gate on the external artifacts:

```bash
PYTHONPATH=src python -m hermes_skilleval.cli v0.3-evidence-gate \
  --output "${EXTERNAL_OUT}/evidence-gate.json" \
  --markdown-output "${EXTERNAL_OUT}/evidence-gate.md" \
  --external-plan "${EXTERNAL_OUT}/plan.json" \
  --external-report "${EXTERNAL_OUT}/matrix.json"
```

Expected status at this point is usually `REVIEW_REQUIRED`, because live-agent
evidence is intentionally absent and should be marked field-level
`UNAVAILABLE`. Do not treat external-only evidence as final v0.3 benchmark
evidence or router-promotion approval.

## 4. Run Small SkillsBench/Codex Pilot

Run a small real Codex pilot before freezing the live-agent evaluation:

- 4 selected SkillsBench tasks;
- 3 conditions per task: `no-skill`, `routed-skill`, `oracle-skill`;
- 1 trial per condition;
- deterministic verifiers only;
- no private credentials;
- no uncontrolled network;
- isolated Codex evidence mode with clean global capability inventory.

The pilot is a wiring and safety check. It is not the frozen live-agent
benchmark.

Prepare the pilot plan:

```bash
export SKILLSBENCH_DATA_ROOT="/path/to/skillsbench-selected"
export PILOT_OUT="${ARTIFACT_ROOT}/skillsbench-pilot"
mkdir -p "${PILOT_OUT}"

PYTHONPATH=src python -m hermes_skilleval.cli skillsbench-plan \
  --data-root "${SKILLSBENCH_DATA_ROOT}" \
  --output "${PILOT_OUT}/plan.json" \
  --upstream-ref "<immutable-skillsbench-commit-sha>" \
  --license-note "<license-note>" \
  --run-id "${RUN_ID}-skillsbench-pilot" \
  --mode pilot \
  --selected-task-id "<task-1>" \
  --selected-task-id "<task-2>" \
  --selected-task-id "<task-3>" \
  --selected-task-id "<task-4>" \
  --routed-predictions "${PILOT_OUT}/routed-predictions.json" \
  --oracle-qualification "${PILOT_OUT}/oracle-qualification.jsonl" \
  --matrix-output "${PILOT_OUT}/matrix.json" \
  --workspace-root "${PILOT_OUT}/workspaces" \
  --router-top-k 1 \
  --skillrouter-data-root "${SKILLROUTER_DATA_ROOT}"
```

Run the 4 x 3 x 1 pilot using the approved real Codex live-agent runner path for
this repository. Do not substitute fake-runner artifacts for final evidence.
Preserve redacted `live-agent.v1` traces and preflight/global capability
inventory in the pilot artifact directory.

## 5. Run Evidence Gate On Pilot Artifacts

Run the gate with both external and pilot live-agent artifacts:

```bash
PYTHONPATH=src python -m hermes_skilleval.cli v0.3-evidence-gate \
  --output "${PILOT_OUT}/evidence-gate.json" \
  --markdown-output "${PILOT_OUT}/evidence-gate.md" \
  --external-plan "${EXTERNAL_OUT}/plan.json" \
  --external-report "${EXTERNAL_OUT}/matrix.json" \
  --live-plan "${PILOT_OUT}/plan.json" \
  --live-report "${PILOT_OUT}/matrix.json"
```

If the pilot gate is `INVALID_EVIDENCE`, stop and inspect the check records. Do
not expand to frozen live-agent evaluation until pilot artifacts are valid or
the review-required gaps are explicitly accepted as non-final pilot limitations.

## 6. Prepare Frozen Live-Agent Evaluation

Only after pilot evidence is acceptable, prepare the frozen live-agent
evaluation:

- 8 to 12 selected SkillsBench tasks;
- 3 conditions per task: `no-skill`, `routed-skill`, `oracle-skill`;
- 3 trials per condition;
- same prompt hash across all conditions for each task;
- fresh workspace per run;
- deterministic verifier pass/fail is the only task-success source;
- isolated Codex evidence mode;
- clean user/admin/workspace-parent skill inventory;
- no private credentials or uncontrolled network;
- no router or threshold changes after the plan is frozen.

Write a new frozen plan under a new artifact directory, for example:

```bash
export FROZEN_OUT="${ARTIFACT_ROOT}/skillsbench-frozen"
mkdir -p "${FROZEN_OUT}"

PYTHONPATH=src python -m hermes_skilleval.cli skillsbench-plan \
  --data-root "${SKILLSBENCH_DATA_ROOT}" \
  --output "${FROZEN_OUT}/plan.json" \
  --upstream-ref "<immutable-skillsbench-commit-sha>" \
  --license-note "<license-note>" \
  --run-id "${RUN_ID}-skillsbench-frozen" \
  --mode frozen \
  --selected-task-id "<task-1>" \
  --selected-task-id "<task-2>" \
  --selected-task-id "<task-3>" \
  --selected-task-id "<task-4>" \
  --selected-task-id "<task-5>" \
  --selected-task-id "<task-6>" \
  --selected-task-id "<task-7>" \
  --selected-task-id "<task-8>" \
  --routed-predictions "${FROZEN_OUT}/routed-predictions.json" \
  --oracle-qualification "${FROZEN_OUT}/oracle-qualification.jsonl" \
  --matrix-output "${FROZEN_OUT}/matrix.json" \
  --workspace-root "${FROZEN_OUT}/workspaces" \
  --router-top-k 1 \
  --skillrouter-data-root "${SKILLROUTER_DATA_ROOT}"
```

Run the frozen live-agent evaluation only after a human confirms the frozen
plan, task list, oracle qualification, runner settings, and artifact directory.

## 7. Final Gate And Decision Boundary

After frozen external and frozen live-agent artifacts exist, run:

```bash
PYTHONPATH=src python -m hermes_skilleval.cli v0.3-evidence-gate \
  --output "${ARTIFACT_ROOT}/evidence-gate-final.json" \
  --markdown-output "${ARTIFACT_ROOT}/evidence-gate-final.md" \
  --external-plan "${EXTERNAL_OUT}/plan.json" \
  --external-report "${EXTERNAL_OUT}/matrix.json" \
  --live-plan "${FROZEN_OUT}/plan.json" \
  --live-report "${FROZEN_OUT}/matrix.json"
```

The final decision remains `KEEP_BASELINE` unless the Benchmark Validity Gate is
valid and all preregistered promotion guardrails pass. A valid evidence packet
does not by itself imply promotion.

## Claim Boundary

Until frozen external and frozen live-agent runs complete and the final evidence
gate is reviewed, the only supported claim is:

> v0.3 infrastructure is complete and ready for frozen evidence collection.

Do not claim a full real benchmark result, a live-agent pass-rate result, or a
router promotion before the frozen evidence artifacts and final gate report are
complete.
