# Conditional pointwise support model

This is a local weak-label research pilot. It estimates textual applicability and conditional task specificity, not expected patch success. The original rank adapter and Gate remain frozen; this model does not promote `auto` or change the default strategy.

The base is the locally cached `pipizhao/SkillRouter-Reranker-0.6B`, revision `78986e1142d12857cfd85b8005e62902cd42d858`. `base-identity.json` lists freshly checked model/tokenizer file SHA-256 values. The new adapters are private; public artifacts record their content hashes and recipe, not weights. The existing causal final-token yes-minus-no scorer, outer template and program-owned structured input are reused. User-provided marker strings are ordinary section content.

Two instructions share one independent LoRA: applicability, and specificity given applicability. APPLICABLE includes GENERAL_WORKFLOW; NOT_APPLICABLE/CONFLICT are applicability negatives; UNKNOWN is masked. Specificity is supervised only for known applicable rows. No label, quote annotation, experiment ID, group or split enters prediction. The natural skill name/body remain visible, so content-level shortcuts remain possible.

Two preregistered candidates differ only in auxiliary weight (lambda 0 or 1). Both use seed 7170, three epochs, LoRA rank 8/alpha 16/dropout .05 on q_proj/v_proj, AdamW learning rate 2e-5, microbatch one and accumulation eight, float32 MPS and gradient checkpointing. No class resampling, seed search or check-driven early stopping is used. The normalized masked training objective follows the active Goal; main metrics normalize known rows within each mechanism hierarchy. Epoch selection is independently recomputed from all saved model-dev predictions, using applicability log-loss and the stated specificity tie-break. Original masked development losses remain in the training history rather than being overwritten.

Full support inputs use a maximum 8192 tokens, with truncation recorded and disallowed in training. The frozen-base support comparison uses exactly those instructions and budget. The separate original-rank B2/C2 comparison retains its old adapter and 1024-token budget, records truncation, and never treats rank scores as calibrated probabilities. B2 and C2 share that rank order; only C2 adds support qualification. New `p_app * p_specific_given_applicable` sorting is reported separately as a textual priority proxy.

All candidate epochs must be saved and reloaded in new processes; logits and compact input identities must match their pre-save model-dev records. The final selected scorer, all comparison arms, old rank, source data, package bodies, tokenizer/model hashes and code are frozen before cal/check inference. Runtime and offline evaluation use the same identity-bound calibration and acceptance function. Missing models explicitly fall back; mismatched calibration fails closed.

Independent cal fits at most positive slope plus intercept for each eligible axis. The frozen operating rule requires precision >= .90, at least three accepted mechanism groups and six accepted rows, known coverage >= .10 and zero accepted UNKNOWN. Partial/unavailable context, unknown conditions, invisible critical text or explicit contradictions block acceptance. A null threshold remains null; check cannot loosen it. Calibration cannot supply semantics absent from the trained model.

Limits: 24 purposively selected public issues and a known ten-skill catalog, model-generated labels without human review, four mechanisms per evaluation split, possible shared annotator bias and base-model pretraining exposure. This does not establish unseen-skill generalization, natural-traffic performance, natural-conflict recall, environmental safety or repair utility. Removing context is an inference ablation, not independent retraining. For lambda zero, the specificity instruction has no direct supervised loss and any resulting specificity ranking is interpreted accordingly.

Actual checkpoint, reload, measured cost and check outcomes are reported in [results.md](results.md) and the bound JSON artifacts. No positive outcome is assumed by this recipe.

The actual isolated library/runtime versions are in `runtime-versions.json`; package minimum-version extras are installation conveniences rather than an exact environment lock. Training/scoring loop timers exclude model loading, file hashing and some preparation. Driver-allocation samples and process RSS are different memory measures and must not be added as if they were disjoint physical memory.
