# Fixed scope before new scores

Use: isolated source maintenance / skill advice, with no repair Agent or skill
example execution. The four cal task revisions and ten original skill package
identities are fixed in [profile.json](../../../configs/environment-readiness-v1/profile.json).
All four source snapshots exist locally; each is verified against saved context
file hashes, and its full tree is bound before copying into a build context.

Required for every candidate: Linux Python 3.12, target distribution installed
at its exact source version, import originating in that source, declared package
dependencies consistent, target CLI help usable, a minimal task-relevant library
capability, and an offline read-only isolated runner with temporary writes only.
The two SQLite tasks probe SQLite trigger introspection and ATTACH respectively;
csvkit probes CSVLook construction; csv-diff probes load_csv/compare on a tiny
in-memory unique-key fixture. None tests the requested repair or assumes base green.

The ten skills are read as development guidance. Their example commands are not
scheduled: remote database backends, optional FTS indexes, Excel inputs and CLIs
of *other* repositories are NOT_REQUIRED_FOR_SCOPE, never reported installed.
Target package dependencies/entrypoints remain required. This scope is fixed
before any new scores or dependency observations; it does not introduce a
text-only calibration exception. No execution authorization results from facts.

SATISFIED requires successful matching observations; an observed missing command,
wrong module origin/version or unsupported capability is UNSATISFIED. Preparation
failure, timeout, malformed output and absent observation are UNKNOWN. `pip check`
alone is insufficient: the distribution and source import must also be confirmed.
Requirements and results are separate; summaries are recomputed from all required
items. Records cannot certify arbitrary environments: before use, rerun the
bounded probe after reconstructing the fixed offline recipe from the pinned base, exact source and explicit local wheel assets; compare image/dependency/source identity.
Hashes establish consistency, not trust in a source or permission to execute it.

Preparation can download public dependencies inside a dedicated Docker build.
Probe runs have no network, no host mounts, no socket or credentials, read-only
rootfs, dropped capabilities, non-root uid, and bounded memory/time/output.
This reuses the existing maintenance runner's isolation policy without invoking
its Agent transport. Installation may create metadata in the image only; the
original snapshots are not edited.
