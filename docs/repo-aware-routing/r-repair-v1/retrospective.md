# 五个面试问题的证据边界

**为什么 pairwise 排序变好，支持门槛仍全部拒绝？**
Pairwise 只约束分差，对共同平移不敏感；绝对 sigmoid 阈值会受平移影响。
此外，旧支持指令在真正 token 输入中丢失。修复后 rank 用冻结秩代理，
support 用专用输入与独立绝对标签拟合含截距映射，但数据仍未支持有效操作点。
不能说输入修复就自动带来校准成功。

**支持某一步与修好整个 issue 有什么不同？**
CLI/API 一致性检查可具体帮助验证，但不保证找到事务缺陷或独立完成修复。
100 条标签是两个模型的原文判断，75 条正例不是 75 次成功修复，9 条分歧归未知。
`p_text` 不表示代码修复成功率。

**大文件怎样提供关键事实？**
先定位公开请求符号，再在独立字节/时间预算内扫描，提取带路径、行号、原文
和已读范围身份的片段。正向机制案例是原先跳过的 `db.py` 中 `delete_where`
进入实际 token。超预算未读范围、截断声明和关键覆盖不确定仍如实标注，
不能把原文窗口称完整 AST，也不缓存不可验证的整文件状态。

**B2/C2 改了什么，Agent 真看到不同技能了吗？**
B2 冻结相关性 Top-2，C2 要求校准支持再选恰好两份完整包。
本次 B2 物化 import-data/cli-api 两包并观测到 cli-api 读取；C2 无有效操作点，
回退全五包。因此只有 rank-only 的真实两包执行，没有受支持 C2 非空分支。
同一族三次补丁都通过，不足以隔离随机波动或证明收益。合理拒绝案例就是
C2：不能用单族 1.0 精度绕过至少两正例族及 0.90 的冻结要求。

**为什么新 R 不能用旧 Gate？**
上下文、可见输入、支持目标和集合语义改变了；旧 Gate 反馈对应旧决策分布。
新身份绑定这些源文件、模型、校准和选择配置，旧 Gate 明确版本不匹配。
后续只有先验证受支持真实分支与研究价值，才考虑独立采集新反馈；本轮未做。
