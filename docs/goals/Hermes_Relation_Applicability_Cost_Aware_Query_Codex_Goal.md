# Hermes：关系级适用性排序与成本感知查询

> **完整 Codex Goal｜先验证“什么关系值得查”，再考虑下一轮代码修复实验。**
> 本轮只改进并检验关系获取策略、批处理和截止决策；不增加 gain/wait、RL、模型层或审计平台。
> 范围内持续授权、连续实施，不逐阶段申请批准，不设置固定工程排障次数。
> 这是依据 PR #54 审阅制定的新研究设计，不是对已实现能力、未来收益或学术首创的声明。

## 0. 一页合同：唯一主线与最终交付

**唯一主线：在同一公开要求与候选来源下，用关系级适用性而非单纯的宽区间决定查询优先级，并根据实际批次成本决定查多少、何时停止。**

必须回答：

1. 相比旧区间优先级、简单逐要求相关性和固定顺序，新策略是否更早取得有来源依据的关系？
2. 改进来自查询顺序，还是会话/批量实现？两者必须分别比较。
3. 得到的关系是否真正影响了知识包选择，而不只是得到更多 JSON 行？

执行链：

```text
复现旧优先级的退化情况与实际调用开销
  → 固定公开状态、候选与配对诊断面板
  → 关系级适用性特征与简单强基线
  → 同模型的会话生命周期/批量预演
  → 软优先级与保守上下界分离
  → 同一封存关系表上的查询顺序比较
  → 固定预算下的真实关系获取与独立来源核对
  → 报告查询、关系、知识包和限制，停止
```

本轮**不启动 Coding Agent 修复、不生成新补丁、不调用目标/保护验收、不重判旧补丁**。真实模型调用只用于来源关系分析、独立核对和接口测量；这不是“零模型实验”。

这是有意收窄的机制研究，项目长期目标仍是功能修复收益。关系发现改善最多支持“值得进入下一轮功能实验”，不能改写成“本轮修复率提高”。

## 4. 两类不确定性彻底分开

### 4.1 保守范围：用于表达尚未取得的标签

继续使用现有关系状态与上下界。未分析、传输缺失、明确语义未知不等于不相关；它们保留原有范围，不能因软分数低就变成 `[0,0]`。

### 4.2 软优先级：用于决定先问谁

允许根据要求与来源的文字、符号、条件和实际成本生成一个排序分数 `z(r,u)`。它不是校准概率、形式证明或真实修复价值。

**软优先级再高，也不能直接写入正关系；软优先级再低，也不能收紧数学上界。**只有实际返回并通过来源/角色校验的模型提议，才按旧关系类型进入集合目标。即使通过机械校验，语义正确性仍须独立核对。

用针对性测试固定：改变 `z` 可以改变请求顺序，但不能改变尚未查询关系的状态、上下界或历史标签。

## 7. 简单强基线 R：逐要求相关性

复用冻结 MiniLM 与已有词法/符号组件。先计算便宜的配对分数：

\[
z_{ru}=0.50v_{ru}+0.20b_{ru}+0.20s_{ru}+0.10c_{ru}.
\]

- `v`：完整合法文本分块后的非负余弦，相似度不是正确性。
- `b`：同一要求对当前24来源的归一化BM25；该要求所有分数为0时保持0。
- `s`：实际公共符号/路径/可解析一跳关联的固定匹配分，不用隐式答案位置。
- `c`：原文中显式条件线索的固定重合分，不输出蕴含真值。

各项取 `[0,1]`。无特征时取中性0并记录缺失，不偷偷用其他模型补出有利分数。默认不按事后关系标签搜索系数；实现修复与系数调参必须分开。

R按 `w_r * z_ru` 排序，并沿用每第三个位置对分析较少要求的探索分配。它**不需要另一个LLM先解释全部关系**，否则只是把原开销搬到前面。

这个R必须作为主要对手，不得只与固定ID顺序比较。

## 8. 对照 A0：旧区间优先级不能被故意实现得更差

复制或适配现有 `ExactSelector.requests()` 的旧规则：

\[
p_0(r,u)=\frac{w_r(U_{ru}-L_{ru})
 (1+I[u\in A_M]+I[u\in A_L]+I[u\in A_U])}{\widehat c(r,u)}.
\]

同一共同账本、候选、关系存储、求解器、预算、计时和新传输适配用于 A0/R/V。A0没有得到关系级软分数，是本轮要分析的因素，而不是让它继续使用已知坏的传输实现。

保存旧冻结源码的离线数值例子作一致性检查；不将新适配上的A0耗时称为 #54 原环境耗时复现。

## 9. 主方法 V：适用性调制的成本感知查询

主方法在旧规则中显式加入关系级适用性：

\[
p_V(r,u)=p_0(r,u)\,[0.05+0.95z_{ru}].
\]

0.05是预定探索底值，不是成功概率。它避免低软分直接失去全部探索机会。继续每第三个位置对分析较少的要求轮转；轮转内部仍按同一方法分数选来源。

这里新增的是**对具体配对的内容敏感性**，不是更窄的真假界限，也不是已经学到的信息价值。保守包/乐观包的初始化可以相同，不要求人为制造它们不同。

选择器在每批合法结果后用原集合目标更新可返回包，保留MMR后备规则。不能为了展示新算法参与，删除“存在合法正关系”的条件或强制换包。

这个V可以输给简单R；如果R已经够好，本轮应明确保留R为更简单的候选路线。

## 12. 参考提议与独立核对：不让调度器给自己打分

对面板每对建立两份分开的材料：

- **提议表Q**：冻结关系模型对该配对的来源关系提议，用于封存表查询回放。
- **核对表J**：另一新上下文仅看相同公开要求、原文和必要合法上下文，先独立作类别/适用性/引用判断，不看Q标签、方法名、排序分、查询次序。

默认使用已有合法关系模型；核对者可以是同基础模型的独立上下文。必须写 `human_reviewer_count=0` 与同模型相关错误风险，不能叫人工gold、第三方真值或形式证明。

再由固定规则比较Q/J，输出：

```text
SUPPORTED_POSITIVE：正关系及其条件/角色得到核对支持
CORROBORATED_ZERO：无正支持结论得到核对支持
DISPUTED：分类/条件/角色发生实质冲突
REVIEW_UNKNOWN：语义无法判断或核对缺失
```

规范、实现上下文、前提和验证模式不能互相替代。当前实现可能有bug，不能自动获得规范支持；泛型helper与目标具体异常/类型的可达性也必须有来源。

机械引用通过与语义核对支持分开记录。Q的有效正关系可以驱动待测算法；J用于离线评价，不能在运行中成为新的筛选门禁。

只对缺失或格式失败续接，已有效的零/正/语义未知不重复抽到一致。分歧不是要求模型再次“修正答案”的授权。

## 13. 面板回放如何公平地比较查询顺序

查询算法只得到公开特征与自己的已揭示记录。完整Q/J由独立只读回放器保管，不能把全部标签传入排序器后仅在报告里声称“逐项揭示”。

### 查询数口径

在每个面板内，所有方法共享同一个可请求域 `E_panel`，每次请求只揭示其Q结果。比较8/16/24/32个不同请求位置；重复/坏行/未知都记录，不能只对成功响应计预算。

主指标在第18节。此表隔离查询顺序，不包含真实API延迟。

### 集合选择口径

所有方法仍共享原24候选与完整要求权重。面板外关系保持未分析；不能补成零后声称获得完整最优包。

可以比较各方法在**相同部分关系**下实际产生的知识包、相对MMR的变化，以及面板内已核对支持的覆盖。F差只能叫该有限参照中的计算差，不叫完整关系后悔值或修复遗憾。

Q缺失时也缺失，不能让S/V以不同“完备表”比较。J未知不删出分母。

官方文档区分连接初始化、thread和turn，并提供中断/输出结构接口 [R1]。先检查本机已安装协议。仅复用可实测能力，不升级Codex或修改全局账户配置来完成本轮。

如果进程复用不可用，保留冷启动路径与实际成本，其他排序/回放工作仍应继续；不得把“会话热复用”当作已经存在的性能事实。

## 15. 预演中必须真正测量的阶段

按实际可观测边界分开记录：

```text
本地序列化/准备
进程与连接初始化
模型目录查询/线程创建
模型响应等待与可观测输出
解析与逐行校验
取消和结束清理
完整调用耗时、输入/输出用量、完成/缺失/异常
```

不能把首token时间当完整关系完成时间；没有暴露首token事件时该字段留空。

同一进程的初始化成本在一条序列中只发生一次，但正式策略独立实例都应承担自己的启动费用，不能所有策略都借用一个免费的预热实例。

不把2个重复报成可靠p95。用原始值、范围和保守预算估计描述；网络/服务波动仍存在。

只根据开发阶段的有效输出率、用时及同内容返回情况选择共同适配；不能依据哪种配置更支持V来选。

## 16. 批次成本与启动规则

默认正式获取预算仍为**每状态每策略每重复60秒**，最多48个不同配对。这个60秒是**来源获取子任务预算**，不是本轮又做了一次600秒修复部署评测。

候选批量从预演实际支持的集合中选择，默认 `{2,8}`。不足2个待查配对可使用1对，其未测成本保守参照2对批次并明确标记；不得为了凑批量虚构关系或截掉来源必要条件。

以预演的完整请求长度、批量和生命周期拟合非负成本近似，或在数据不足时直接使用同类成功批次的保守时间包络：

\[
\widehat t(B)=t_{setup}\,I_{cold}+\alpha+\beta L_{unique}(B)+\gamma |B|.
\]

这里允许拟合几个非负计时系数，不是新神经模型。样本不足、共线或不稳定时不硬拟合，退到有记录的包络估计。

计划用时取预测与最近可比成功耗时的较大者，再乘预先固定的1.25余量；超时样本是耗时下界/删失观察，不能当成快速完成样本。

**仅当计划用时＋结束余量5秒不超过真实剩余预算时才发起该批。**优先选择当前排序前缀中可容纳的最大已验证批量；同分规则冻结。

不把计划用时当硬保证；实际超时仍需中断、计费、保留部分合法行。若剩余2.7秒而同类批次需要十几秒，应正常返回当前包，停止原因写 `NO_AFFORDABLE_BATCH`，不是报模型不可用。

正式阶段三种排序共享这套批次可启动性和传输实现。V的成本分母按同一计时模型估计，不能给V免费启动、让R承担冷启动。

## 17. 失败续接：保留结果，不靠延时拼出好标签

复用 `RelationStore`、`MethodBudget` 与已有部分JSON解析，做必要薄适配。

- 有效行逐条接受，第一次合法语义结果不可改写。
- 传输缺失/格式坏行可在剩余时间内续接；语义UNKNOWN、有效零、被来源规则拒绝的提议不作为“再抽一遍”的对象。
- 允许一次调用失败后按预算和实际错误类型决定继续，而不是无条件 `break`；也不能同一失效环境下忙循环。
- 发生可恢复连接问题，先确认旧请求终止，再按原配对输入身份恢复；恢复成本不退还。
- 续接时共享批内上下文改变须记录。已返回有效行不重新评分，未返回行的新请求不冒称完全相同的模型内部状态。
- 截止后到达的结果只进late记录，不改变已锁定包。

格式完整性不能替代语义有效性。不得给未返回的关系填TOPICAL_ONLY或正支持。

## 18. 三组指标：不再只报“查了几对”

### A. 查询策略——阶段主要指标

在同请求数和真实时间预算两种口径下分别报告：

1. `SupportedPositive@k / @60s`：实际取得且获独立核对支持的正关系数量，另分规范/验证/前提/实现上下文。
2. `CorroboratedRelation@k / @60s`：正关系及明确零关系分别有多少得到核对支持。发现负关系也可能排除竞争包，不直接视为无用。
3. 得到正支持的不同公开要求数及加权占比；计权仍按原完整账本，不因拆句或查询不到而改分母。
4. DISPUTED、REVIEW_UNKNOWN、TRANSPORT_MISSING、NOT_ANALYZED原始计数。

面板上的关系yield分母是**请求位置数**，同时给出有效返回行数。未核对或争议不能排除后计算漂亮精度。

### B. 方法对输出的实际影响

保存起始MMR、每批后的实际包、最终包及回退原因；统计第一次合法正关系、第一次非MMR包的查询位置/实测时刻。

未发生就报未发生。相同包不表示保留了所有知识；非MMR包也不代表更好。

独立核对每种最终包的来源是否直接支持具体要求、只是实现上下文或仅主题相关。审阅者看原文，不看方法名和F分数。

### C. 获取成本

有效返回/请求数、每批实际时间、完整序列费用、截止/重试/剩余但不可用时间、启动开销占比、预算超出情况分别列出。

同时展示“取得更多支持”与“耗时更少”，不把只返回大量零或UNRESOLVED的吞吐增加当作有用关系效率提高。

本轮 `functional_repair_gain = NOT_TESTED_THIS_STAGE`。旧P/C结果只能作为历史背景，不能给新V背书。

## 19. 开发、冻结、核对的先后顺序

1. 固定四状态、所有原文、候选、面板抽样规则和种子。
2. 在两个开发状态实现特征、A0/R/V/S、直接反例、传输预演、恢复与计时。
3. 只打开开发面板Q/J，允许修复引用错位、错误归一化、错误路径解析等实现问题；不搜索有利系数。
4. 冻结算法、提示、共同适配、成本初值、批量/截止、检查状态与重复数。
5. 对宏/缓存生成新的参考Q/J，独立保存；查询运行器无读取权限，不通过上下文注入完整标签。
6. 完成封存面板回放与正式在线获取；在线获取从空的新store开始，不预装参考标签或其他策略返回。
7. 锁定所有获取轨迹和最终包后，统一开展在线结果来源核对并生成比较表。

宏/缓存虽属于冻结后检查，仍是旧项目已观察题，不称严格独立测试。最终结果揭晓后不换系数、模型、候选或截止再覆盖原表。

## 20. 真实在线获取：只用两个状态、三种排序

正式在线设计：

```text
2个固定状态 × A0 / R / V × 2次获取重复 = 12条真实获取轨迹
每轨迹60秒、最多48个不同配对
不生成新Coding Agent前缀，不生成修复补丁
```

每条从相同公开状态、相同24候选、相同空关系表、相同MMR包出发。两重复与跨策略的模型响应可以不同，因此封存表回放负责隔离纯排序因素；在线表负责展示真实接口与预算下的整体获取结果。

物理可缓存相同原文embedding，计时按共同预登记约定记录。不能将其他策略的合法关系缓存免费提供给后跑的方法；运行顺序按固定种子交错。

R先查的关系与V重叠时，在线仍是各自独立真实调用；若为节约费用实际复用，只能另标共享表实验，不能冒称独立在线结果。

有合法来源和可用模型就运行预登记获取，不要求先观察到V获胜、非空正例或改包。没有正支持也如实完成这一小型诊断，不扩大到更多修复题。

## 21. 在线核对如何避免只审核“成功关系”

合并12条获取轨迹请求过的配对，按**原文身份**去重；同一配对的多次提议保留各自结果。默认所有被请求配对均进入一次盲化原文核对，再将核对与每次提议分别匹配。

为了避免核对工作无限增加，首次冻结时可以声明至多256个不同配对的核对额度。超过时用固定种子按状态分层无放回抽样，不能只选V的正提议；未入样配对统一为REVIEW_NOT_SAMPLED。

主表保留全请求分母，并分别给已核对支持下界与未核对范围；抽样结果不能写成全部关系准确率。有限核对覆盖不足时优先报告不确定，不改变抽样方案获得更有利结论。

核对者可以读取公开原文及必要base上下文，不看参考修复/隐藏测试，也不替Agent解决任务。若只有同模型核对，明确限制；不得声称已经有人类专家介入。

## 23. 必须避免的几种“看似提升”

- V更快但没有收到可核对关系：只能说执行开销变化，不说有用信息获取改善。
- 所有方法得到同一MMR包：可以完成获取对照，不能说新语义策略影响了修复。
- V仅超过固定S、不超过R：不能说复杂决策项必要。
- V在自己F下分数更高：不能代替独立来源核对。
- 面板没有正关系：不能人为生成正例、删除零关系或换状态，记录该面板信号不足；这不证明完整E无正关系。
- 角色/引用检查通过：只能说明提议形式合法，不证明semantic truth。
- 去掉未知后精度升高：禁止；未知、争议和未抽样都保留。
- 热进程更快：不能将基础设施改善全部归因于查询排序。
- 降低辅助模型/effort后更快：不属于本轮同模型对照，需另立明确实验，不静默实施。
- 有来源正关系或新的知识包：仍不表示功能修复救回，本轮不生成这种结论。

## 28. 面试与复盘只写能支持的结论

一页中文复盘应回答：
