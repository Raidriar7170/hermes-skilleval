# Hermes ASI v2：真实功能失败的增益学习与同状态机制验证

> **完整 Codex Goal；算法与机制验证优先。**
> 唯一主线：学习外部技能指导相对原生继续的**功能修复增益**，并用同一执行状态、同一候选集合验证动态表示和等待决策是否真正有用。
> 激活后连续实施，不等待下一份 Goal，不逐阶段申请批准，不设置固定工程排障次数。
> 本文不要求制造正结果；要求不把文件合规、成本下降、CI 通过或模型接线成功替代功能修复收益。

---

## 0. 一页目标合同：先固定“到底要证明什么”

本轮依次回答四个问题：

1. 真实的代码维护任务中，是否存在“同一可观察执行前缀下，技能改变最终功能结果”的学习信号？
2. 用这些真实分支结果训练的增益模型，能否比零增益、技能/阶段先验等简单方法更好地选择动作？
3. 固定同一个状态和候选清单后，动态错误/源码/进展特征是否改变了有用的选择？
4. 同一状态下，等待是否真的比立即注入更好，而不只是“当前增益非正，所以没有注入”？

执行主链：

```text
旧训练/开发记录的功能、合规、成本分解
  → 来源明确的新功能缺陷与任务族划分
  → 自然执行状态及不干预/技能/普通提醒的真实配对尾程
  → 纯功能增益监督 + 同候选表示消融
  → 纯功能等待价值，模型及策略冻结
  → 新测试任务上的端到端比较
  → 同一原生状态上的动作表与等待/立即注入对照
  → 功能主表 + 机制结论 + 次要合规/成本附表
```

不新增多智能体、在线 RL、技能生成器、产品前端、通用安全审计或新的发布系统。
复用 ASI v1 已有执行分叉、隔离、补丁捕获和确定性验收，只补本轮必需接口。

**验收对象是完整且不漂移的研究，不是预设“必须提升”。**
“研究执行完成”“模型真实训练”“功能收益成立”“状态机制成立”“等待机制成立”必须分别报告。
没有收益可以完成研究；核心训练或真实对照没做，不能仅凭工程绿灯标成算法任务完成。


`objective-lock`须被数据构建、训练、评价入口实际读取。仅检查几项关键字段，不造新的证明平台。
进度文件最多再用一张任务表和一个变更记录；不以全仓重复扫描/哈希数量作为主要交付。

必须实现的断言：

- 只改变 policy 字段，功能标签与功能增益不变。
- 只改变时间/token，功能标签、训练目标、功能胜负和功能收益状态不变。
- 功能失败但文件合规，不能得到正功能质量；功能通过但文档路径违规，不自动得到功能失败。
- 若所有目标/回归都通过，所有同状态纯功能差为 0，绝不能报告功能修复提升。
- 对同一个机制检查点，所有表示消融共享候选 ID、顺序、正文、前缀、源码和剩余预算。
- 无等待模型与完整模型使用同一份功能增益权重；不同自然轨迹的注入数差不能代替同状态证据。

## 4. 明确不允许的目标替换

| 遇到的情况 | 允许的处理 | 禁止的替换 |
|---|---|---|
| 功能全部持平，文件合规改善 | 次表如实报告，主结论无功能增益 | 将合规乘回训练 y 或把合格交付率改称修复率 |
| 功能无差异但更省 token | 次要成本观察 | 用净成本效用作为本轮成功主指标 |
| 所有技能增益非正 | 保留不干预，完成适用的已冻结比较 | 调低阈值直到发生注入 |
| 等待没有改变正增益动作 | 标等待机制未被当前样本识别 | 报等待调用次数当机制收益 |
| 状态模型不如先验 | 如实比较并解释 | 删除先验或改变它的候选集 |
| 任务/检查过于简单 | 只在开发侧按预先类别补自然任务 | 看最终效果换题、削弱 Agent 或制造错误 |
| 发现验收器机械错误 | 留原版，按来源修复并对称复验 | 只重验喜欢的臂、针对补丁调整义务 |
| 数据不足或零差异 | 交付失败原因、未完成范围或零增益对照 | 改成“安全平台升级完成”交差 |

若确实必须改变主指标或研究对象，记录为另一项未来研究，不在本 Goal 内悄悄替换。
不为了完成本轮而继续派生新的 Goal、架构层或无限数据收集。

## 5. 三轴结果：功能、文件约束、成本分开

对每份完整原始候选保存：

```text
execution_status
verifier_integrity_status
y_target: 0 | 1 | UNKNOWN
y_regression: 0 | 1 | UNKNOWN
y_functional: 0 | 1 | UNKNOWN
file_policy_status: PASS | FAIL | UNKNOWN
file_policy_reason
qualified_delivery: 0 | 1 | UNKNOWN      # 只作为次表
active_seconds / overhead / input_tokens / output_tokens / cached_tokens
```

主功能结果：

\[
y_F=\mathbf 1[\text{来源支持的目标行为通过，且保护回归没有新增失败}].
\]

前提是检查真实执行、结果可解释且未被候选污染。
目标/回归未运行、收集失败、环境错误、来源不明时为 UNKNOWN，不填写 0 或 1。
执行超时若仍能对截止时完整候选进行可信检查，保留其实际功能结果并单列 TIMEOUT。

**文件策略不是功能标签的一个输入。**
普通的“修改了禁止提交的文档/额外文件”继续记录并拒绝交付，但可信沙箱内仍可独立测量功能。
不得删掉那些额外修改后重验一份“清洗后的补丁”。测的仍是完整候选。

若发生裁判篡改、读参考答案、越权或隔离失效，功能证据可能无效：记录明确的完整性错误/UNKNOWN，不把这种情况当成普通文档合规失败，也不为了收集标签继续危险执行。
现有执行边界照常生效，只是不再承担本轮学习目标。

对照真值表至少覆盖：

| target | regression | 文件策略 | y_functional | qualified_delivery |
|---:|---:|---|---:|---:|
| 1 | 1 | PASS | 1 | 1 |
| 1 | 1 | FAIL（普通非篡改类） | 1 | 0 |
| 0 | 1 | PASS | 0 | 0 |
| 1 | 0 | PASS | 0 | 0 |
| UNKNOWN | 1 | PASS | UNKNOWN | UNKNOWN |

不要再用 `all(checks.values())` 或旧 `quality` 字段直接生成本轮 y。


功能救回严格是同前缀同重复下 `y_F(no-op)=0, y_F(skill)=1`；退化相反。
两个分支仅文件策略不同，必须计作功能持平。
不能因为 v1 最终测试全过，就假定它的全部训练/开发也全过；实际解析后再报告。

用途：解释旧训练信号与为何需要新功能任务，不重跑旧 96 条、不再做旧验收全面审计。
v2 主训练默认使用新的配对采集；确需复用旧训练侧功能标签时，必须在训练前清单中标明来源、机制、分区和权重，计入真实总量，不能静默拼接或冒充新增数据。
旧会话不可恢复时，历史终端记录只能用于离线诊断，不能补造同状态新分支。

## 7. 新任务：按真实业务机制准备，不按“让 Hermes 赢”选题

默认正式目标：**12 个训练机制、4 个开发机制、8 个全新最终测试机制**。
另用最先登记的 4 个训练机制做先导探测，它们计入训练数量，不是额外测试。
默认仍使用 sqlite-utils、csvkit、csv-diff 三个已有适配仓库；不把扩大仓库生态作为主线。

从公开历史缺陷与修复前源码中选择自然功能需求，优先类别包括：

- 多接口/多模块一致性，而非只增加一个入口文件。
- 参数组合、空值/类型边界、异常处理和已有行为兼容。
- 数据导入导出中的内容、结构、顺序和往返一致性。
- schema/事务/约束变更中的数据保留及失败回滚。

类别是拟定的数据来源方向，不是假称具体 issue 已验证。
来源查证时记录 issue、base、修复机制、公开义务、验收层次；不得虚构 issue 或拼接几条独立要求成“真实原题”。

任务池的顺序和类别配额在本轮动作结果出现前确定。
可以在开发阶段通过 N0 先导发现天花板，但不能先比较各技能胜负，再只保留技能救回的题。
任务难度针对所有方法相同；不能换弱执行模型、缩短原生预算、隐藏必要资料、损坏依赖或人为注入失败。

## 8. 新任务的最低功能资格与去重

进入新的功能修复主集合需满足：

1. 固定历史 base，在来源支持的目标检查上真实功能失败，而保护回归可解释。
2. 可信参考或已确认合法实现通过对应目标和保护回归。
3. 有正常输出、关键边界及至少一个有依据的反例，不能只检查 help、文件存在或实现特定命名。
4. 题面与验收对齐；重大标题/正文冲突要在执行前显式澄清，衍生澄清题另标，不能看结果后选解释。

初始 base 失败**不等于**强 Agent 原生继续最终失败，两者分别记录。
已经功能通过的 base 不混入新的修复主分母；可保留在训练侧少量 no-op/退化诊断，单列，不充当成功任务扩大分数。

按真实修复机制分组：同 issue、同 fix、共享关键变更的派生问题、同一状态的多分支与重复均不跨区。
v1 已观察的最终任务及所有反复审阅任务不得再叫 v2 新测试。
预处理、标准化、先验和模型拟合只使用对应训练折，不读取测试数据拟合参数。[R2]

## 9. 天花板探测：确认有机会学习，不要求先看到正收益

先导只用登记的训练任务和与正式一致的执行模型/预算，默认每任务 2 次 N0。
沿自然轨迹保存公开错误和检查点；隐藏终端结果仅在执行结束后交给数据准备方，不能回填到 Agent 状态。

分别报告：

- base-red/reference-green 是否成立。
- N0 在完整预算下有无真实功能失败。
- 公开 E1 是否自然出现，以及最终能否自己解决。
- 检查是否覆盖公开关键行为，而非只是模型轻易通过的表面断言。

若先导 N0 全通过，不能立即称整个任务域无困难。按事先登记的训练候选顺序继续考察剩余自然类别；不访问测试结果，不围绕某个模型胜负选题。全部先导任务仍保留，不只留下最终失败者。
若需要拓展训练候选池，先固定公共机制规则和资源范围，保留筛选日志、已完成任务和类别分布，不无限搜到出现救回为止。

**不要求技能先证明能救回，才允许该任务进入训练。**原生失败但所有技能也失败，或技能只有退化，都是有效结果。
相反，整个已批准开发池若功能结果恒定且无可辨识的动作差异，应停止扩大昂贵分支，报告 `FUNCTIONAL_SIGNAL_NOT_IDENTIFIABLE`；不将文件策略信号重新拿来训练。
轻量零增益对照和诊断可以完成，但不能将其称为已经学会功能救回。

这个检查是防止重复上一轮的全功能持平，不是要求必须出现正面结果的门禁。

## 10. 最小验收：来源与覆盖优先，不新增裁判平台

每个新任务一张短语义表即可：公开义务、对应断言、正反例、保护回归、已知遗漏。
尽量使用该版本已有行为测试并补必要边界；参考 patch 不等于规范，参考内部文件名/函数写法不自动成为义务。

测试与修复 Agent 使用的公开观察分开：Agent 可以运行仓库原测试和自己编写的测试；隐藏目标仅用于离线标签与最终评价。
不把隐藏失败注入 E1、不把正确答案内容变成技能、不以 LLM 自评替代功能结果。

文件修改范围默认继承。确有任务本身要求修改文档时，在执行前为该任务所有方法统一声明；不能在看到某臂多改文档后放宽它。
目标功能和约束合规分别输出，不由测试收集器吞并。

发现机械错误可以版本化修复，对所有受影响已保存候选对称重验，不调用 Agent 重新追分；旧记录保留并披露后验性。
不可在同一轮看过最终新结果后不断扩充主测试义务，直到出现有利的功能差异。

## 11. 复用同前缀适配，不重新建执行系统

继承 ASI v1 的 `Session`、检查点、源码/scratch 快照、固定逻辑路径、官方 fork/resume 和实际输入验证。
官方 fork 复制已存储历史，可指定完成轮次边界；不自动克隆源码或隐藏随机状态。[R1]
启动时核对当前安装版本与冻结执行模型，不未经说明替换为默认模型。

每个比较状态绑定：

```text
机制/任务/前缀ID、完成轮次
可见历史、源码、必要scratch、环境
共同中性续跑模板
冻结候选ID与实际指导正文
相同起始剩余预算、模型与推理配置
```

这是相同可观察前缀的随机执行对照，不宣称精确个体因果效应。
所有分支真正继续工作；NO_INTERVENTION 不是保留原补丁原地停止。
已耗前缀时间不重发，分支复制、编码、预测和后续推理计入相应原任务预算。
仅在完成轮次/工具边界复制，不在有后台写入的状态取快照。

## 12. 状态与候选：消融只能改变声明的一个因素

状态继续使用任务/仓库、阶段与预算、公开错误、实际已读/已改内容、diff、进展计数和缺失标记。
不使用最终结果、其他分支反馈、参考修复、隐藏测试、私有推理或任务ID查表。

每个同状态实验检查点**只生成一次**候选清单 `C(s)`，保存 ID、顺序、载荷和来源。
默认采用 v1 的静态首项＋动态不同首项，最多 2 项；冻结编码器和候选规则，不把换检索模型作为本轮贡献。
动态表示模型、无动态表示模型、先验和立即/等待比较都使用同一个 `C(s)`。

无动态表示版本：保留任务/仓库、阶段、预算；独立训练网络，但去掉公开错误、源码变化和进展特征。
它仍然接收共同检索产生的候选，因此测的是**给定相同检索结果后的动态表示增量**，不是“系统完全没有任何状态信息”的总效应。
不得在该臂内重新检索静态 Top-2。

端到端不同策略走出不同轨迹后，其状态自然不同。共同的是检索函数与信息权限，不伪称所有后来实际候选都相同。
精确的表示归因在后述共同状态面板完成。

## 13. 实际动作载荷与普通提醒对照

训练/开发共同状态动作：

```text
NO_INTERVENTION
INJECT(candidate_1)
INJECT(candidate_2)       # 仅实际存在的候选
GENERIC_REMINDER
```

技能采用相同的冻结正文/片段和消息层级；内容真实进入后续模型输入。
编码对象对应实际提供的指导文本，不能以另一版正文训练，再交付不同载荷。
所有方法保留相同原生技能目录；显式注入与自行读取分开计量。
普通提醒不包含具体任务解法，保持预先固定，记录其真实长度，不塞无意义文字伪造等长。

普通提醒是识别“额外提示本身是否有用”的对照，不并入新的技能目录。
主技能增益拟合默认仅使用技能动作；提醒结果用于控制分析与便宜提醒对照，不偷换成“技能算法突破”。
重复提醒、技能长短和原生读取不能作为额外免费预算，全部记录。

## 14. 功能配对监督：保留救回、伤害与持平

对同状态、同预先登记重复构造：

\[
\delta_F(s,k,r)=y_F(s,\operatorname{INJECT}(k),r)-y_F(s,\operatorname{NO\_INTERVENTION},r).
\]

取值 `{-1,0,+1}`；有多个预定重复时可均值聚合，但保留每次原值。
未知一侧不能填0；配对标签未知，分母与原因仍保留。
不干预相对增益定义为0，不需要另拟一个基线噪声分数去与技能竞争。

训练目标为期望功能增益：

\[
\Delta_F(s,k)=\mathbb E[y_F\mid s,\operatorname{INJECT}(k)]-
\mathbb E[y_F\mid s,\operatorname{NO\_INTERVENTION}].
\]

本轮采用可观察前缀配对采样估计，不将单次观测差宣称为真实因果效应。
同一 no-op 尾程被两技能共享时，保留共享 ID；统计按机制聚类，不按配对数量虚增独立样本。

单列以下转换：

- 真功能救回：no-op 功能0 → 技能功能1。
- 真功能退化：no-op 功能1 → 技能功能0。
- 双过/双败持平。
- 仅文件约束变化。
- 仅成本变化。
- UNKNOWN/基础设施/完整性失败。

只收集原生失败状态会丢失“本来能修好却被干预破坏”的信息，禁止作为唯一采集策略。

## 15. 增益网络：只学习功能，不把旧复合权重改名

复用冻结 MiniLM 与轻量64维交互网络；新增独立 v2 权重，从初始化重新训练。
不把 v1 复合效用权重直接当纯功能模型，也不只修改 `model.json` 的目标名称。

建议：

\[
z_s=f_\theta([E(request,repo),E(error),E(source,diff),x_{stage,budget,progress}]),
\quad z_k=g_\theta(E(payload_k)),
\]
\[
\widehat\Delta_F(s,k)=h_\theta([z_s,z_k,z_s\odot z_k,z_s-z_k]).
\]

为可比性，不默认改变现有编码器版本、字段长度或候选生成。必要截断单列覆盖记录，不改到测试最优。
模型输出必须容许负增益；可以以 tanh 约束到 [-1,1]，但需在开发前固定，full/task-only一致。

损失：任务/状态加权的 Huber 或 MSE 对 `delta_functional`；可加同状态的成对排序项。
排序项仅在**真实功能差不为0**的动作对上计算，不能用耗时差将功能持平标成偏好。
零增益/持平样本保留；按 task → state → action 均衡，不人为过采样正例后忘记还原权重。

默认固定小网格沿用80/160轮、相同种子7170和容量；按开发集**功能增益误差**选型。
选模的平分规则预先固定，优先更小模型/更短训练；不用文件合格率、净成本或最终测试选型。
需要保存真实参数变化、曲线、训练样本来源和独立进程重载。

禁止新增 LoRA 候选、换大编码器或多轮超参搜索来追分；表示不足可以记录为下个研究问题。

## 16. 便宜基线与离线选择诊断

至少保留：

| 方法 | 学什么/用什么 | 目的 |
|---|---|---|
| 零增益 | 对所有技能预测0 | 防止复杂模型只拟合噪声 |
| 技能/阶段先验 | 训练任务的同技能同阶段平均纯功能增益 | 有竞争力的便宜基线 |
| Task-only-fixedC | 任务/仓库/阶段/预算，独立拟合，候选固定 | 隔离动态表示 |
| Full-state-fixedC | 完整公开状态，候选相同 | 主增益模型 |

先验按任务加权，未见组合回退规则在开发前固定，不读取开发/测试标签补均值。
所有缩放、特征选择和拟合只用训练侧；等待模型交叉拟合也要重做这些步骤，不能带入被留出的任务。[R2–R3]

报告功能增益 MSE/MAE、正负与零的混淆、动作选择、不干预比例。
不得因为大多数标签为0就只报“符号准确率很高”。
模型在未观察的动作上没有真实价值标签；不把自身预测作为动作正确性真值。

## 17. 等待价值也改为同一个纯功能参照

定义：

\[
D_F(s)=\max_{k\in C(s)}\widehat\Delta_F(s,k),
\quad W_F(s)=\mathbb E[V_F(s_{next})\mid s,\text{本时点继续}],
\]
\[
V_F(s)=\max\{0,D_F(s),W_F(s)\}.
\]

三者都以“不再追加外部干预的终端功能成功”为参照，不能一个用含合规效用、另一个用功能概率差。
本轮 wait/gain 均不含时间、token、文件合规标签；成本只受共同硬预算限制、在附表评价。

沿真实原生链，由后向前训练。为某任务生成下一状态预测的所有模型都排除该任务及同机制衍生任务。
不能直接把未来已实现的最好动作结果作为当前目标；未观测下一状态或执行中断，不当终端0。
确认结束/最后机会才是等待价值0。相同参照下的近似停止决策仍依赖建模假设，不宣称 Bellman 真值或精确最优。

无动态表示的等待模型也独立训练，候选仍用该检查点共同 C(s)。
Myopic 使用 full 的**同一份**增益模型，唯一变化是等待值置0且不调用 wait head。
不另训练一个 myopic 增益模型，否则不能隔离等待。

## 18. 冻结决策规则：正功能增益才消耗一次机会

默认 margin=0，不在本轮按文件策略或成本优化 margin。

```python
best = stable_argmax(functional_gains, candidates)
gain_now = functional_gains[best]
wait_gain = functional_wait(state) if has_future_opportunity else 0.0

if gain_now > max(0.0, wait_gain):
    inject_one_frozen_skill(best)   # 此后不再外部干预
elif has_future_opportunity:
    continue_with_no_new_guidance() # 等待后续自然状态
else:
    finish_without_external_guidance()
```

打平保留预算；全部预测非正时允许零干预。
不因希望展示 WAIT 或注入而移动阈值；所有模型即使不优于先验，也按冻结方案保留比较。

等待能改变立即正增益动作的区域为：

\[
0 < D_F(s)\leq\max(0,W_F(s)).
\]

分别记录该区域的状态数、机制数、是否实际导致分歧及后续功能结果。
`D_F<=0` 时的等待只证明当前没有正增益，不能认领为 wait head 的独立贡献。
资产不可用是 METHOD_UNAVAILABLE，不是学会了不干预。

## 19. 同状态实验一：表示贡献不再混入检索差异

在最终 N0 的预定第一重复中，按公开事件选一个共同检查点：

- 优先首个自然 E1；没有 E1 则使用实际 E2，保留收尾阶段的源码/差异信息。若两者都不存在，则使用 E0并明确这是无动态观察的退化诊断。
- 选择规则在最终运行前固定，不看隐藏功能结果或动作胜负。
- E0没有实质动态信息时标“表示机制不可识别”，仍保留总体诊断，不换一条看起来更有用的轨迹。

对同一个快照 s 和同一个 C(s)，先锁定 full、task-only、先验的分数和动作。
再执行第13节的共同动作尾程（no-op、两技能、普通提醒），默认每动作2次。
所得动作结果表用于检查各预先选择的动作实际表现，不在结果出现后再选赢家策略。

必须明确：

- 只看分数不同，说明表示影响预测，不说明更正确。
- 同状态同候选动作不同，才说明表示影响了选择。
- 被full选择的动作在真实尾程中功能更好，才形成该状态上支持表示价值的观察。
- 配对重复和多状态不是独立任务，效果归纳按机制聚类。

可在冻结模型上做置换/遮蔽动态字段的诊断，但它只是离线敏感性；不能把不自然拼接的虚假状态送给 Agent 后称自然任务。
不重新训练一次“更会赢”的task-only来覆盖主结果，也不故意削弱该基线。

## 20. 同状态实验二：真正比较“现在用”与“稍后用”

从上述共同面板中按预定任务顺序选最多4个非终端状态，不按新胜负选择；不足4个按实际记录。
只有E2的状态不能比较未来等待；不为了凑数修改E2含义、制造新的干预机会或挪到一次有利执行。可观测等待机会不足本身是结论限制，不转用合规或成本证明等待有用。
对每个状态，以 full 的当前预测锁定 `k_now`，然后比较以下真实续跑：

| 尾程 | 当前动作 | 后续规则 | 用途 |
|---|---|---|---|
| NEVER | 不注入 | 此后也不外部干预 | 已有no-op参照 |
| NOW(k_now) | 立即注入该技能 | 此后不外部干预 | 已有技能动作参照 |
| DEFER_SAME(k_now) | 当前不注入 | 到下一个自然机会注入同一份技能 | 控制技能内容，识别延迟本身 |
| WAIT_THEN_FULL | 当前明确保留机会 | 后续运行冻结full策略，仍最多一次 | 识别等待加后续适应的策略价值 |

NEVER/NOW来自同一协议动作表时可明确复用原采样ID；不能将复用记成新增调用。
两个延迟分支从 s 真正继续到各自后续状态，**不能跳到已保存的未来源码/历史**。
没有下一机会或预算耗尽，就保持无外部干预；不为延迟分支赠送额外回合。
不同分支隐藏随机状态未克隆，故每种延迟方式默认2次重复，仍是有噪声估计。

`DEFER_SAME`将技能内容固定；`WAIT_THEN_FULL`可能改选技能或最终不注入，两者不能混称“纯时机效应”。
强制执行延迟分支只是离线机制实验，不表示在线full当时真的选择了等待。

报告全体预选状态结果，以及第18节“等待阻止当前正增益”子集，前者是总体诊断，后者是机制条件子集。
后者若为空，写 `WAIT_EFFECT_NOT_IDENTIFIABLE_IN_OBSERVED_STATES`；不能以WAIT次数代替。
不通过改预测、重选起点或窥看未来来人为填满该子集。

## 21. 同状态实验三：技能知识与普通提醒分开

共同动作表必须包含 GENERIC_REMINDER。
在相同前缀、文件、预算、消息层级下比较每项技能与提醒的最终功能结果。

以下情况区分：

- 技能优于无干预，但与提醒相当：只能观察到额外指导可能有用，不能证明特定知识贡献。
- 技能比提醒更好：保存具体任务与内容依据，同时报告退化与持平。
- 提醒更好：保留，不把它称作“异常值”。

普通提醒的长度可能较短，记录成本，不伪造相同token。
不让提醒泄露额外任务检查点、未来错误或参考信息。
动作表可支持事先冻结的策略值估计；事后取每状态最好动作只能叫有噪声事后上界，不能作为部署结果或训练标签。

## 22. 主端到端矩阵：保留六臂，替换混杂消融

所有臂用相同任务、执行模型、推理配置、总活动时间、原生技能目录、中性续跑及外部验收。
默认8个新测试机制、每臂2次，共96条整任务轨迹。

| 方法 | 定义 | 对照意义 |
|---|---|---|
| N0-v2 | 原生继续，无控制器外部指导 | 主对手 |
| S1-v2 | E0注入冻结静态检索首项 | 是否需要动态方式 |
| P1-v2 | 用训练技能/阶段功能先验，正增益就注入，否则继续 | 比规则更有竞争力的便宜预测器 |
| H-task-fixedC-v2 | 独立task-only增益/等待模型，共同候选函数 | 动态表示的系统层消融 |
| H-myopic-v2 | 完整功能增益模型，wait=0 | 等待机制消融 |
| H-full-v2 | 完整功能增益与等待模型 | 主方法 |

P1只用训练结果，未知技能/阶段默认0，平分规则固定；它不是读取当前任务失败后查答案。
旧R1可在共同状态动作表上作附带规则诊断，不默认另加第七个整任务臂。
普通提醒由共同状态面板控制，不冒充端到端第七臂。

不同方法最终执行自己选择的一条轨迹，不在线穷举动作后返回最佳补丁。
最终不能仅跑发生有利分歧的任务；全体登记任务和失败/未知全部保留。

## 23. 资源规划与防止实验膨胀

默认规模为设计上限估计，不是要求凑齐自然不存在的状态：

| 部分 | 默认计划 |
|---|---:|
| train/dev原生前缀 | 12+4个任务；先导重复另行计量，可合法复用对应前缀 |
| 每任务最多E0/E1/E2，四动作，各1次 | 最多192条采集尾程 |
| 预先固定约四分之一状态做第二重复 | 最多48条额外采集尾程 |
| 最终端到端8×6×2 | 96条 |
| 每最终任务1个共同状态×4动作×2 | 最多64条机制尾程 |
| 预定最多4状态×2延迟方式×2 | 最多16条时机尾程 |

合计研究尾程/整任务执行上界约416条，另有原生前缀、任务准备和少量接口验证。
这不等于416个独立问题，也不假定所有阶段都出现。
实际总成本可能高于上轮；先据已有额度和同模型实测速率估算，不擅自新增消费资源。

默认完整版本应执行三类真实对照：功能主矩阵、共同状态动作面板、延迟对照。
资源不足时，在正式结果出现前登记更小的任务数/重复方案；优先复用身份完全匹配的既有采样，绝不伪造重复。
不能在看到结果后只砍掉不利基线或延迟分支。
中途资源耗尽保存全部分母、启动记录和实际进度，恢复同一Goal；不称剩余格子已完成。

**研究样本次数固定用于防挑结果；工程安装/修复尝试不设置固定次数。**

## 24. 冻结顺序与最终结果不可回流

顺序：

```text
目标锁/任务类别/候选规则
  → train/dev/test机制分区
  → 任务资格与开发侧天花板探测
  → train/dev采集与功能分轴
  → full/task-only/先验训练与开发选择
  → 等待模型和全部策略、面板顺序冻结
  → 全体最终策略运行 + 共同状态和时机续跑
  → 统一释放最终评价结果
```

同一最终任务可先生成N0第一重复以取得共同状态；所有状态选择只看公开事件。
在该任务全部预定策略和机制续跑结束前，不把隐藏结果反馈给控制器、执行Agent或任务筛选器。
可以由独立验收进程先写密封结果以便恢复，但冻结策略不得读取它决定后续任务/动作。
完成模型前不读取最终预测胜负；某次失败不可触发技能改写、换权重、换候选或换成本公式。

旧最终集已经看过，不能因为换了主指标就称为独立新测试。
公开问题可能存在底座预训练污染，最多说明本项目开发分区未见；不宣称污染为零。

## 25. 主指标、未知分母和结果解释

主表首先给：每任务/每臂的 `target / regression / y_functional`，而不是 `quality` 或 `qualified` 的简称。
主要对比：H-full-v2 与 N0-v2 的任务平均功能通过率差。
关键次对比：full与P1、myopic、task-only、static；每项范围和不确定性分别说明。

按任务/机制聚类，先对同任务重复取均值，再做配对区间；不能把分支或重复当独立机制。
小样本bootstrap只能作为描述性区间，不自动认证泛化；同时报告逐任务差和有效任务数。

UNKNOWN不删：报告计划、启动、可评价、未知各分母。
主表至少包含全计划格子的成功下界/上界；有效配对分析另外给并明确条件化范围，不能只用删未知后的漂亮分数。

主结果允许：`OBSERVED_FUNCTIONAL_GAIN_WITH_LIMITATIONS`、`NO_DEMONSTRATED_FUNCTIONAL_GAIN`、`FUNCTIONAL_SIGNAL_NOT_IDENTIFIABLE`、`INCOMPLETE_EVIDENCE`。
不能因为交付合格率或成本区间为正，把功能结果的状态改成GAIN。

次表另给文件策略违规、可交付比例、时间/token/缓存覆盖、控制器开销和输入长度。
实际功能通过不授权忽略安全/文件约束去发布候选；默认策略保持不变。

## 26. 机制证据分三级，禁止“计算了＝有效”

| 层级 | 表示机制 | 等待机制 |
|---|---|---|
| 计算接入 | 动态特征进入模型 | wait head产生并参与分数比较 |
| 决策影响 | 同状态同候选下动作改变 | 正当前增益因更高等待值而被推迟 |
| 功能价值 | 预选动作的真实尾程功能结果改善 | 同起点的真实等待/立即分支功能结果改善 |

三层单独报告，不能跳级。
“注入次数从5到7”“在E2才注入”“WAIT有22次”都不直接证明机制价值。

若 full与myopic 在共同状态上完全同决策，写没有识别出等待机制的边际贡献；不同自然轨迹上的合格数差不补证这一点。
若去状态同时换候选，标实验无效/混杂，按原共同候选重新做相应**设计内**比较；不保留混杂结果充主消融。
未知/无分歧不当负收益，也不变成“已证伪所有等待/动态技能”。

## 27. 防漂移回归：少量、直接、实际接线

至少测试：

1. 目标/回归全过而policy失败，纯功能仍为1；旧qualified继续为0。
2. policy-only救回不会进入功能rescue计数或排序偏好。
3. 时间/token任意合法变化不能改变delta_functional和功能收益结论。
4. 一个未知分支不生成0增益标签；全计划分母仍保留。
5. task-only和full输入确实不同、权重独立训练，但共同候选/载荷完全相同。
6. myopic和full使用同一增益权重；禁用wait不能顺带禁用动态检索或换预算。
7. 正当前增益低于wait时可推迟，负当前增益等待不计入“wait独有影响”。
8. DEFER_SAME使用原技能正文；WAIT_THEN_FULL只能读本分支新观察，不能跳原未来快照。
9. 所有分支共享相同起始预算，不为等待或无干预额外发600秒。
10. 训练/交叉拟合/选模不能读取最终测试反馈；任务族不能跨分区。
11. 功能全持平时，报告器不能被次要成本或policy差触发 `FUNCTIONAL_GAIN`。
12. 已完成格子恢复时不新采样，缺失/中断显式保留，不采到成功为止。

构造测试只验证代码逻辑，不冒充真实功能救回、真实状态差异或真实等待收益。
只补相关单测与集成测试；不以达到某个测试数作为任务目标。

## 32. 面试与创新边界

可解释的设计贡献是：

- 将功能修复增益与合规/成本解耦，训练目标与研究问题一致。
- 在固定可观察状态与候选下，分离动态表示和候选检索的贡献。
- 区分立即注入、延迟同技能、等待后再选择，避免把换技能效果当纯时机效果。
- 用真实配对结果而非文本弱标签监督干预价值，保留退化、零收益与不干预。

这些是本项目的方法设计，不自动构成学术首创或有效性证明。
“相同可观察前缀”不等于克隆隐状态；“实验完成”不等于显著提升；“合规改善”不等于功能救回。
本轮即便结果为负，也要能回答是哪一个假设未成立，而不是把无效结果重新命名成创新。
