# Hermes vNext：状态感知技能干预与边际效用学习

> **算法优先的完整 Codex Goal。**
> 主线不是继续完善评测平台，而是实现并检验一个新的决策机制：
> **在代码 Agent 的执行过程中，学习“现在注入哪个技能、继续等待，还是始终不干预”。**
> 本文激活后连续实施，内部阶段自动推进，不等待用户提供下一份 Goal。
> 范围内持续授权，不逐阶段确认，不设置固定工程尝试次数；实际账户权限、已有执行隔离和资源边界继续有效。

---

## 0. 本轮必须产出的算法成果

将旧的“任务开始时选两个技能”升级为：

```text
真实维护需求 + 当前仓库
        ↓
Agent 开始执行，保留原生技能发现能力
        ↓
少量可观察的决策时点
        ↓
状态表示：当前报错、已读/已改文件、公开测试、历史进展、剩余预算
        ↓
冻结候选检索器：找出可能有用的技能
        ↓
学习式增益模型：相对“不额外干预”，当前注入的预期净收益是多少？
        ↓
时机控制器：现在注入 / 等待下一时点 / 不干预
        ↓
Agent 在同一总预算内继续
        ↓
实际补丁 + 外部行为检查
```

本轮四项核心交付：

1. **可真实运行的执行中干预**：不是只在开始时换 Top-K，也不是最后生成建议 JSON。
2. **基于真实分支执行的增益监督**：同一可观察执行前缀与源码快照下，比较不干预和不同干预。
3. **实际训练的状态—技能增益模型与等待价值模型**：训练、模型选择和上线决策使用一致的目标。
4. **冻结后的端到端对照与消融**：解释状态、时机、不干预选项分别有没有贡献。

完成不以必须涨分为条件，但不能仅交接口、mock、规则触发器或新的审计报告，便宣布上述四项完成。

研究代号使用 `adaptive-skill-intervention-v1`，简称 ASI。`vNext` 是研发版本名称，不自动变更 PyPI 版本、不自动发布。

## 1. 优先级：把主要精力用在决策机制，而不是再造平台

工作顺序：

- **P0：架构与算法**——执行状态、同前缀分支、增益目标、等待决策、可学习控制器。
- **P1：解释性实验**——真实执行监督、强基线、关键消融、失败机制。
- **P2：必要工程**——薄执行适配、结果可重算、必要回归与 GitHub 交付。

建议投入约 70% / 20% / 10%，这是方向而非必须核算的工时门槛。

不新增通用权限平台、全仓审计体系、复杂证明对象、产品前端、分布式服务、发布管理系统。
不把测试总数、文件哈希数量、状态字段数量作为主要成绩。
沿用已有隔离、文件策略、补丁重建和外部验收；只在其妨碍本轮真实实验或出现明确缺陷时做局部修复。

**保留执行底线，不新增“先证明 90% 文本支持精度才能做算法实验”的门槛。**
低置信建议可以在本研究受限环境中测试；凭据泄漏、参考答案泄漏、原工作区破坏不能被称为普通探索。

## 4. 创新表述：不是“动态路由”四个字本身

已有公开研究已经讨论：检索重排技能、执行反馈驱动的技能选择、动态技能上下文，以及在失败状态干预 Agent。[R1–R4]
因此不得宣称“首次动态注入技能”“首次用执行结果评估技能”或“首次有 no-op”。

本项目本轮要做出、并用消融支撑的设计组合是：

| 设计 | 与旧 Hermes 的实质区别 | 必须回答的问题 |
|---|---|---|
| **同前缀、不干预参照的增益学习** | 不再用模型生成的适用性标签代替修复效用 | 技能改变的是本来就能成功的任务，还是实际增加了成功机会？ |
| **剩余预算下的时机决策** | 不再发现报错就机械注入 | 现在用掉一次干预，是否不如继续观察后再使用？ |
| **状态—技能交互建模** | 同一技能在不同报错/执行阶段具有不同价值 | 模型是否真正依赖执行状态，而非记住技能名或任务先验？ |
| **显式内容干预、同机制静态对照** | 不再把“挂载了但可能没读”当作干预完成 | 观察到的差异来自内容/时机，还是仅仅多给了一次提示？ |

这是本项目的架构贡献与研究假设；是否构成新的学术方法，需要与相关工作进一步比较，不能由本 Goal 自动认证。

## 5. 第一版采用“最多一次显式技能干预”

本轮主协议：每个完整任务最多消耗一次**外部显式干预**预算，最多考察三个决策时点。

这不是限制工程尝试次数，而是简化因果归因与时机学习的算法设定：

- 干预前沿不干预轨迹观察；决定注入后不再追加第二个外部技能。
- 因而可以比较“现在用”与“保留给后面”，不用同时解决多轮技能组合和长程信用分配。
- 原生 Agent 仍可自行阅读可用技能；一次预算只计本控制器显式添加的指导。
- 不尝试从上下文中“撤销”已经读过的技能；删除文件不等于模型忘记内容。

不在本轮默认实现多次替换、多技能撤回、在线 PPO、GRPO、完整 POMDP 求解或多智能体辩论。
先把这一版本的单次干预停止决策做实，而不是用更多自由度掩盖收益来源。

## 6. 核心假设与反证条件

**H1：状态带来额外信息。** 相同任务和技能，在不同公开错误、修改状态或验证阶段，其增益不同。
比较完整状态模型与仅任务/仓库模型、技能先验、简单规则。

**H2：存在需要保留干预预算的时机。** “出现第一处异常马上注入”不必然最优。
比较等待价值控制与只看当前正增益就立即注入的策略。

**H3：不干预是有意义的动作。** 某些技能会浪费预算或破坏本来正确的方案。
保留不干预分支，报告修复、退化、持平和成本；不能只收集基线失败状态。

**H4：状态特定技能优于一般提醒。** 真实分支中加入固定的一般提醒，避免把“再仔细想想”的效果全归给技能。

以下都是允许的结果：没有可识别收益、只有成本变化、时机模型不如规则、状态特征无帮助、全部学习式决策选择不干预。
这些结果不触发自动换模型、换题或无限扩大数据；但也不阻止完成已冻结的对照。

## 7. 执行状态：只使用决策时真实可见的信息

建议状态表示：

```text
request + bounded_repo_facts
current_stage / completed_turn_index
files_read / files_changed / bounded_diff_summary
latest_public_test_command / exit_code / failure_signature
recent_tool_errors / repeated_error_count
public_tests_run / observed_pass_fail_counts
changes_since_last_check / unchanged_error_after_edit
skills_available / observed_skill_reads / previous_explicit_interventions
remaining_task_budget / elapsed_active_time
```

状态以可见工具事件、源码和公开测试输出构造；先用确定性提取，不为每个时点新增大模型总结调用。

约束：

- 不能放入未来工具结果、最终补丁、最终外部验收、参考修复、隐藏测试内容或其他分支结果。
- Agent 自己写的测试或旧仓库公开测试可以作为观察，但不是最终金标准。
- 测试未运行、输出无法解析必须有缺失标记，不填成通过、零错误或零不确定性。
- 不读取私有思维链，不假设能取得模型隐状态或真实不确定度；重复错误等只是可观察代理特征。
- `state_id/task_id/repository_name` 用于分组与追踪，不直接作为模型查表特征。
- 状态应含必要报错正文和真实源码片段，不能只有计数；设置预算时同时记录实际保留/截断内容。

## 8. 三个决策时点：让“何时”可以被明确检验

按单调顺序识别以下时点，不要求每个任务都必须出现三个：

| 时点 | 触发定义 | 注意 |
|---|---|---|
| E0 开始 | 正式执行前，只有需求与仓库事实 | 是静态干预基线使用的时点 |
| E1 执行障碍 | 第一次观察到失败的公开测试，或同签名工具错误重复，随后第一个可暂停边界 | 不靠隐藏裁判判断“卡住” |
| E2 收尾 | 首次准备交付候选，或达到预定预算比例后的可暂停边界 | 尚有统一的剩余预算，不能临时多送一个修复回合 |

默认 E2 的预算比例为总允许工具动作的 75%；若后端不能可靠计数，改用已实测可执行的活动时间比例，并在生成研究结果前固定。
E1 的公开测试失败识别与“相同错误重复”的规则在数据收集前固定。
同一个边界同时满足多个事件时合并，不复制为多个独立样本。

工具仍在运行时不能直接复制正在写入的工作目录。使用完成的轮次/工具边界，确认进程状态后再保存。
若后端只能在轮次结束时干预，准确称为“轮次边界的事件响应”，不宣称在错误发生的瞬间完成干预。
没有 E1 是正常轨迹；不能为制造状态多样性故意让测试失败。

## 9. 干预载荷：让 Agent 真正收到内容

各方法均保持相同的原生技能目录、工具、权限和共同任务提示。
控制器干预是新增一个明确的技能指导消息，而不是只改变挂载目录。

默认每次干预提供**一个**已冻结技能的指导文本：

- 优先完整提供正文；内容过长时，在看本轮任务结果之前按技能章节生成固定片段并记录来源。
- 同一技能在不同策略/时点使用同一内容；不能针对候选失败即时让大模型重写成解题提示。
- 每份载荷默认不超过 1,200 个被测 Agent tokenizer token；这是新增上下文预算，不是技能选择置信阈值。
- 完整技能资产仍只读可用，不把参考补丁、具体答案或新增权限夹带进载荷。
- 所有方法使用相同的消息层级和包装；不让学习方法获得更强的 system 权重。

记录内容真正进入后续请求这一事实，区分 `injected`、`model_input_observed` 与后续是否遵循。
输入可见不等于服从，更不等于有因果收益。

一般提醒对照使用预先固定、不含具体技能知识的提示。它的长度和技能正文可能不同，必须计入成本并披露；不靠重复无意义文字伪造等长对照。

## 10. 候选检索：复用底座，不把本轮做成 Router V4

候选生成不是本轮主创新。使用现有冻结的文本模型/检索器和技能目录。

默认每个时点取两个候选：

1. 根据请求与仓库信息的冻结静态排序第一项。
2. 根据请求加当前公开错误/状态摘要的冻结检索第一项；与前者重复则取下一项。

来源损坏或实际权限不允许的技能剔除；不按隐藏标签、参考答案或本轮最终胜负剔除。
两个候选不足时如实保留，不能手选“正确技能”补齐。

完整十技能目录的来源和正文保持既有版本。可以修复明确的输入拼接缺陷，但不得在看过测试收益后改变候选生成方式。
在训练分支中，动作集合为 `NO_INTERVENTION + candidate_1 + candidate_2 + GENERIC_REMINDER`。
一般提醒是控制动作，不自动并入最终技能目录。

## 11. 先做一个真正可用的暂停、分叉和续跑适配

已有同步执行器需要新增薄适配，不是已有能力。[S3]

优先级：

**路线 A：官方会话分叉。** 若实际安装版本支持，使用完成轮次的历史分叉及显式续跑，配合独立源码快照。
官方文档列出了 `thread/fork`、`thread/resume`、`turn/start`；分叉复制历史，不自动证明文件系统或隐藏随机状态已克隆。[R5]
启动时用本地版本 schema/help 核对字段；文档版本不能替代实际能力测试。

**路线 B：受控轮次和可观察前缀重放。** 如路线 A 不可用，所有实验臂统一使用同一冻结的分段执行协议与前缀重放。
复用相同可见消息、工具输出、工作目录和预算；必要时在新会话重建。
只能称为“相同可观察状态下的对照”，不能冒充同一隐藏状态的精确反事实。

不把“重新跑一遍同一 issue”当成同状态分支；不在原进程里只改一个prompt就声称已经冻结原前缀。
不为获得分叉绕过已有隔离，也不直接编辑未公开、未经核对的内部会话格式。

最先完成的能力测试必须有：

- 一条真实前缀被续跑两次，工作目录互不影响。
- 其中一个分支收到技能内容，另一个没有；基线继续工作而不是原地停止。
- 两分支从同一前缀文件与可见历史开始，剩余预算相同。
- 一条分支先执行不会把文件、工具结果或新对话泄漏到另一条分支。

这是一项最小实验接口验证，不要求重造 Agent 框架。做不出真实中间状态对照时，不以静态 Top-K 换名替代；明确报告技术边界。

## 12. 前缀、文件系统和预算必须一起保存

每个可分叉状态至少保存：

```text
visible_history_prefix / boundary_id
source_snapshot / required_scratch_snapshot
cwd_mapping / environment_profile
completed_tool_events / no_running_tool_confirmation
remaining_budget / elapsed_prefix_cost
state_features / candidate_list
```

文件复制与会话分叉是两个独立动作。特别注意历史消息中的绝对路径：
优先让各容器内部统一使用相同逻辑路径，例如 `/workspace/repo`，宿主路径各自独立。
不得让分叉后的工具继续写回原前缀目录。

前缀共同耗时在分支比较中是相同常数；尾程也必须受原任务剩余预算限制。
不能给每个分支重新发一份完整 600 秒预算后，把收益叫“更好的干预”。
不干预分支同样拥有继续推理、修改和测试的机会，不是“保持原补丁不动”的弱对照。

所有主比较采用同样的暂停/续跑机制与中性续跑消息；no-op也继续获得原剩余预算，但不收到额外技能指导。不能只给干预臂一个新的推理回合。
可在开发任务上额外比较连续原生与分段原生，估计适配本身的影响；不能混入主表。

## 13. 数据分组与任务选择

建议本轮目标规模：**24个独立维护机制：12个训练、4个开发、8个最终测试**。
任务数是默认研究方案，不是承诺足以产生统计显著性，也不是工程排障次数限制。

沿用已具备适配的 Python CLI/数据仓库；优先从既有三个仓库中选择新机制，不先增加第四个仓库。
当前已反复观察的四道题只适合能力测试与开发，不进入新的最终测试集。

按任务/修复机制分组：一个任务的所有时点、分支、重复、衍生需求都在同一分区。
最终测试机制不得参与技能改写、模型选择、成本权重选择或触发规则调整。

任务应包含多种自然工作类型：接口/命令行一致性、数据处理、参数边界、跨模块修改等。
按公开需求特征和可执行性确定，不先运行各种策略再保留差距最大的题。
不通过隐藏必要文档、换弱执行模型或注入人为错误来让技能显得有用。

每个任务在正式策略比较前具备：

- 明确的公开需求与固定base。
- 来源支持的目标检查与合理回归，至少有一个错误输出反例和一个不同合理实现的接受例。
- 能实际运行；题目本身无法消除的重大歧义不进入新的单一成功率主表。

这里直接复用上轮验收经验，不重新开发通用“验收语义平台”。
数量确实不够时，在看本轮策略胜负前登记较小规模并限定结论；不得使用改写同一题来冒充更多独立机制。

## 14. 真实分支监督：终端效用相对不干预的增量

对训练/开发任务，先产生未受外部显式干预的轨迹，保存自然出现的 E0/E1/E2 状态。
从每个状态比较同一动作集合的尾程；每条干预尾程不再允许后续外部干预。

```text
                         ┌→ 不干预，继续完成任务
相同前缀 + 源码 + 预算 ──┼→ 注入候选技能1，继续完成任务
                         ├→ 注入候选技能2，继续完成任务
                         └→ 注入一般提醒，继续完成任务
```

使用外部行为检查评价最终补丁，不让新弱标签或 Agent 自评代替执行结果。

必须保留：

- 不干预成功、干预失败的退化例。
- 两者都成功/都失败的持平例。
- 正在顺利推进的状态，以及公开测试失败状态。
- 未执行、基础设施错误、无效检查：没有可用标签，不能填作技能负例。

所有尾程完成后才把隐藏验收结果交给训练数据构建器；状态抽取和决策器不能提前访问。
一次尾程差异是带执行随机性的观测，不是精确个体因果效应。
若分叉不保存模型内部随机状态，按“可观察前缀配对”描述；不承诺两个分支只差一个随机变量。

## 15. 效用定义：质量为主，成本为次，不混合未知账单

主质量标签：

\[
y(s,a)=\mathbf 1[\text{预定目标通过且保护回归无新增失败}] .
\]

推荐的主效用：

\[
U(s,a)=y(s,a)-0.05\,c_{time}(s,a)-0.02\,c_{context}(s,a).
\]

其中：

- `c_time` 为原任务固定总活动时间预算下的归一化执行开销，截断到 `[0,1]`。
- `c_context` 为此次显式指导token数除以固定指导预算，截断到 `[0,1]`；不干预为0。
- 每个分支的资源分母沿用任务全局预算，不随剩余时间变化而重新定义收益尺度。
- 分支生成、模型评分和控制器在线开销计入相应成本；离线训练、反事实数据收集和外部评分成本另列。
- API总token、缓存输入和美元账单可以附报，有缺失就保持未知，不拿代理量冒充实际账单。

成功的最低效用高于失败的最高效用；不能靠少运行测试让一个失败补丁战胜成功补丁。
主要结果始终另报原始成功率、回归、时间、注入次数和token，避免一个加权分数掩盖退化。

标签：

\[
\Delta(s,k)=\mathbb E[U(s,\operatorname{INJECT}(k))]-\mathbb E[U(s,\operatorname{NO\_INTERVENTION})].
\]

本轮用真实配对尾程估计它。未采集动作的值未知；不从“文本相关”补成正收益。
成本权重可以在冻结前做固定小网格的开发选择，但最终测试不重新挑权重。

## 16. 第一版增益模型：轻量状态—技能交互，不再靠堆大模型

主模型优先采用**冻结真实文本编码器 + 可训练低维交互网络**。
可复用现有真实 embedding 编码器；缺资产时取得固定公开版本，不能用hash/random向量冒充。
旧 A/J 可作为静态相关性特征或候选来源，不把原适用性概率直接叫修复收益。

示例结构：

\[
z_s=f_\theta([E(request),E(state\_text),x_{state},budget]),\qquad
z_k=g_\theta(E(skill)).
\]

\[
\widehat\Delta_\theta(s,k)=h_\theta([z_s,z_k,z_s\odot z_k,z_s-z_k,x_{state}]).
\]

推荐64或128维投影，两个小隐藏层；分别预测质量差与成本差，再按固定效用组合。
也可以直接预测净增益，但必须额外保留原质量/成本标签和分层结果。
不干预的相对增益固定为0，不通过sigmoid把所有技能压成正增益。

训练至少包括：

- Huber/MSE形式的配对差值监督。
- 对同状态内有真实非零效用差的动作，加入少量成对排序损失；持平例不能强造胜者。
- 按任务与状态加权，避免一个任务三个状态、多个分支被重复当作大量独立机制。
- 相同不干预尾程被多个技能共享时记录相关性，不虚增样本数。

至少比较：零增益预测器、按技能/阶段先验、仅任务输入的轻模型、完整状态模型。
主学习目标是“相对继续的收益”，不是适用性分类准确率。

必须完成真实参数更新、训练曲线、保存与独立进程重载验证。
当前核心不是再做一轮0.6B LoRA。仅在训练数据和开发诊断明确显示冻结表示不足时，允许在本Goal内增加一个预声明的LoRA值模型候选；不得在看最终测试后追加并择优。

## 17. 等待价值：不要把“此刻不干预”等同于“以后永远不干预”

这是本轮时机架构的核心。

`NO_INTERVENTION` 尾程提供“以后也不追加外部指导”的基线，适合构造增益标签。
在线的 `WAIT` 则是“这一时点不使用预算，未来仍有机会”。两者不能使用同一个未经解释的数值。

令：

\[
D(s)=\max_{k\in C(s)}\widehat\Delta(s,k),
\]

\[
W(s)=\mathbb E[V(s_{next})\mid s,\text{当前继续不干预}],
\]

\[
V(s)=\max\{0,D(s),W(s)\}.
\]

终端或最后一个机会之后 `W=0`。候选得分和等待得分都以相同的“不再外部干预”的终端效用为参照。原生执行仍可能自行读技能，这里的“无干预”仅指没有本控制器追加指导。
在预算和过程假设下，这是**单次干预的近似有限时域停止决策**，不是宣称求得真实最优策略。

训练办法：使用真实不干预链上的下一可观察状态，分阶段从后往前拟合等待价值。

- 最后阶段只有当前干预与0基线。
- 前一阶段的等待目标来自下一状态的冻结/折外价值预测，再回归到当前状态。
- 以任务为单位交叉拟合：为某任务生成等待监督的增益/后续价值模型不能训练过该任务。
- 不把整条未来轨迹上“实际最好的分支”直接当成当前可预测的值；那是带未来信息的上界。
- `state_next` 只用于离线构造监督，部署时只能输入当前状态。

不要把估计的等待价值报告为已校准概率，也不强加旧支持精度/覆盖认证。
增益模型与等待模型必须在部署时真正参与选择；不能训练完后又只用手写触发规则。

## 18. 在线控制器与不干预规则

伪代码：

```python
budget = 1
for state in observed_opportunities():
    if budget == 0:
        continue_native()
        continue

    candidates = frozen_retrieve(state)
    gains = value_model(state, candidates)
    best_skill, gain_now = stable_argmax(gains)
    gain_wait = wait_model(state) if state.has_future_opportunity else 0.0

    if gain_now > max(0.0, gain_wait) + margin:
        inject_frozen_payload(best_skill)
        budget -= 1
    else:
        continue_native()
```

`has_future_opportunity`只表示根据当前阶段、剩余预算与预定调度仍可能有后续机会，不读取原轨迹未来是否真的失败、何时结束。
默认 `margin=0`，也可仅依据开发任务的真实效用选择一个小的固定margin；不设置0.8/0.9这种支持概率门槛。
打平时优先保留预算、不干预。
无未来机会且全部增益非正时允许任务不发生任何外部干预。

需要注意：

- 原生继续不等于停止执行；不能让no-op臂失去继续修复机会。
- 只在少量机会打分，不在每个token或每次工具调用启动大模型控制器。
- 最终测试时每个完整任务只执行控制器选中的一条真实轨迹，**不能在线分叉所有候选后选最好补丁**。
- 反事实分支属于离线数据采集，不是免费部署能力；单独报告训练开销。

## 19. 泛化边界：同一前缀的分支不能拆进训练和测试

按机制建立外层 train/dev/test，按训练任务建立内层交叉拟合。
状态—动作记录继承任务分区，不能随机按pair分割。

训练/开发的外部目标反馈可以监督增益模型。最终测试的外部反馈只能在策略冻结并完成执行后用于评价。
模型选项、状态字段、干预载荷、候选检索、效用权重和margin在最终测试前一次固定。

已有历史32次/16次后验数据可以帮助实现和检查，但不混称新版本盲测数据。
公开issue可能出现在基座预训练中，必须说明未排除这种污染；本轮独立性仅是本项目开发分区与可见性意义。

## 20. 数据量、重复与实际计算计划

默认上界规划：

| 项目 | 数量估算 |
|---|---:|
| 训练/开发任务 | 12 + 4 = 16 |
| 每任务最多三个自然时点 | 最多48个状态 |
| 每状态：不干预、两候选、一般提醒 | 最多192条尾程 |
| 预先按任务/阶段均衡选取约四分之一状态做第二次重复 | 最多约48条额外尾程 |
| 最终8任务 × 6种方式 × 2次 | 96条完整策略运行 |

另有前缀生成与少量非研究能力测试。不干预主链/尾程有真正可复用部分时可去重计算，但须保留明确身份，不伪造新采样。

实际时点可能少于上界，不能为凑数强造状态。
一次重复噪声较大，补重复的名单在读取这些分支胜负前确定；不能只为喜欢的正例加采样。

这轮可能需要数百条尾程/任务执行，按每条数分钟估算可达十几个小时甚至更长；不是过去二三十分钟的文档修补。
先用已有合法额度和实测速度估算规模。资源不足时在正式比较结果出现前选择较小的对称方案并登记，不要求新增购买。
缩小后若独立机制过少，交付研究原型与有限结论，不冒称强泛化。

暂停可以恢复同一Goal，不能靠重复请求用户新Goal掩盖已规划工作的未完成。

## 21. 端到端主比较：六种方式，解释架构而不是只展示最好分数

所有方式用同一执行模型、信息来源、总预算、工具、原生技能目录和干预载荷规范。

| 名称 | 决策方式 | 用来解释什么 |
|---|---|---|
| N0 | 同样的检查点与续跑，没有控制器额外技能指导 | 控制器是否比原生继续更好 |
| S1 | E0按冻结J/现有静态相关性选一个技能并显式注入 | 相同显式载荷下，动态方式是否超过静态方式 |
| R1 | 首次E1注入当前冻结检索首项；无E1则在E2使用 | 学习控制是否超过简单错误触发规则 |
| H-myopic | 使用相同增益模型；首次当前增益大于0就注入，不建模等待 | 等待价值是否有必要 |
| H-no-state | 同一训练流程但仅任务/仓库、阶段和预算，无动态错误/进展信息 | 状态信息是否贡献额外价值 |
| H-full | 完整状态增益 + 等待价值 + 不干预选项 | 本轮主策略 |

所有非N方法最多一次显式干预。S1不是旧“挂载两包”的数字，必须在同一新执行协议下重新运行，不能混表。

H-no-state必须实际重新拟合对应小模型及等待模型，不只是部署时把已训练网络的某些输入粗暴置零。

另在离线开发分支上报告两项预定诊断：

- **不允许完全不干预**：最后机会强制选择技能的受限策略，与允许no-op比较。若要把它升级为端到端消融，应在最终执行前明确加入所有最终任务，不能看结果后挑题。
- **一般提醒对照**：技能尾程是否超过同状态的一般提醒；不能把任何额外消息效果都算技能知识收益。

默认不要再增加第七、第八个新模型。若资源必须缩减，优先减少重复或任务，但保留N0、静态、规则、完整方法和至少一个关键消融，且在胜负出现前固定。

## 22. 不干预选项的实质检验

no-op不是一个仅为安全审核存在的按钮，而是要通过结果解释的算法动作。

报告：

- 控制器不干预的比例及对应状态/阶段分布。
- 在离线有动作对照的状态中，不干预成功而注入退化的数量。
- 强制注入的事后策略值与允许不干预的策略值；仅在已观察动作支持范围内计算。
- 全部增益接近零时模型是否诚实保留原生。

不把因资产缺失、环境不可用导致的fallback算成“学会不干预”。
`NOOP_MODEL_DECISION`、`WAIT_MODEL_DECISION` 与 `METHOD_UNAVAILABLE` 分开。
模型确实全部选择no-op时仍运行已冻结的N/S/R对照并报告原因，不能回到“没有操作点所以不做实验”的循环。

## 23. 评价目标与小样本解释

主指标：**真实补丁在预定语义检查与保护回归下的任务成功率**。

辅指标：净效用、回归退化率、显式干预频率、阶段分布、状态识别/评分开销、活动时间、实际token。

算法诊断：

- 增益预测相对零预测/技能先验的误差与符号识别。
- 同状态候选相对不干预的修复/退化/持平分布。
- 等待与立即干预的选择分布，以及已观察范围内的后验机会损失。
- State-only、task-only与完整交互是否真正不同。
- 相同技能跨阶段的效果变化；不要只展示一例成功轨迹。

统计以任务为聚类单元；同一任务三个状态、四条分支、两次重复都不是独立任务。
可以给任务配对bootstrap区间，数量少时明确不稳定；不能把“未显著”当作“已经等价”。
所有未运行、执行故障、无效验收与真实失败分别报告。
不把未知删掉后生成更高成功率。

最终结果采用“训练任务→开发选择→冻结测试”的完整顺序，不能只展示开发最优的例子。

## 24. 最低验收质量：只做能支持算法结论的必要检查

复用现有行为验收，不回到繁琐平台建设。
在新任务正式分支前用一次简短语义表确认：公开要求、目标断言、回归、合理替代实现、明确错误实现。

重点避免旧问题重演：

- 不把无依据的文件名前缀当成功条件。
- 不只检查文件存在或help文字，缺失内容/功能却算成功。
- 包入口、子模块入口和命令入口不能互相替代。
- 重大需求歧义先在任务设计阶段澄清并固定；由控制器澄清的衍生任务应标明来源与范围。

最终隐藏验收与控制器可见的公开测试分离。新增训练反馈只在分支完成后产生。
已有外部检查过程出现具体错判可以修复，但须版本化并对相关各方法对称复验，不偷偷修改本次主定义追求收益。

## 25. 工程范围：最多围绕六类职责做薄扩展

推荐结构，仅作职责建议，可复用现有模块：

```text
intervention/state.py          # 可见状态与少量事件时点
intervention/session.py        # 暂停/前缀/分叉/续跑适配
```

不是要求恰好六个文件，更不是新增六个服务。没有必要修改既有数据库、产品API、GUI或生产权限模型。

## 27. 允许的开发修复与禁止的追分行为

允许修复：接口不匹配、暂停失效、路径映射错误、事件提取缺陷、数据读取错误、训练数值不稳定及检查器明确机械错误。
修复后重跑受影响工程验证，保留变更原因。

不允许：

- 看最终测试后改触发时点、目标、成本权重、技能正文或模型，然后覆盖旧结果。
- 只重跑失败的研究样本直到通过，或保留多个候选中最好的一条。
- 为制造收益临时降低原生预算、禁止它读取必要源码，或只给学习策略额外工具。
- 用最终验收提示当前控制器“现在应该注入验证技能”。
- 将新会话重新解题伪装成同前缀反事实。
- 把静态J分数、weak label或模型自评直接转成增益标签。

工程排障次数不设硬上限；研究重复与资源预算必须在结果前确定。
无收益可以完成；修改方案后的新探索必须另行标注，不能无限扩张本Goal。

这部分复用已有能力，不要求新的全仓审计或独立“安全阶段”。
普通允许范围内的失败自动排查，不反复请求用户授权；平台本身的权限要求不能被文本合同取消。

## 31. 面试产出：把“为什么这样设计”讲清楚

最终一页中文总结应能回答：

- 为什么从静态Top-K改为状态干预？旧结果提供的是动机还是证明？
- 为什么用相对不干预的增益，而不直接预测适用性？
- 为什么第一版只允许一次显式干预？它怎样帮助识别时机价值？
- WAIT与永不干预有什么不同？等待价值怎样训练，部署时怎样避免读取未来？
- 轻量交互模型比规则或只看任务的模型增加了什么？
- 当前收益究竟由状态、时机、额外提示还是执行预算带来？

推荐在有实测后使用的介绍框架：

> 我把技能选择从静态检索改为一次预算下的状态干预问题。先在同一可观察执行前缀上比较注入与不注入的尾程，学习相对继续的净增益；再利用不干预轨迹训练等待价值，决定现在使用技能、保留机会，或不介入。最后在相同预算下与静态注入、错误触发和不使用状态的策略做对照。

后面接实际结果及限制，不预填成功率、成本下降或“领先所有基线”。
