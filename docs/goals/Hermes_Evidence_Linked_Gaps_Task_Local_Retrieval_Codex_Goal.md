# Hermes：公开证据关联的功能缺口与任务局部知识检索

> **完整 Codex Goal｜算法与可归因实验优先。**
> 主线：让“当前未解决的功能要求”与“实际能提供支持的仓库知识”对应起来，再检验这种选择是否改善真实修复。
> 不继续扩建 gain/wait，不重写实验平台，不以检查数量、引用完整或更短的知识包代替功能收益。
> 范围内持续授权、连续实施、不逐阶段确认、不设置固定工程排障次数。
> 第 3 节起是本轮待实现设计，不是对已有实现或未来效果的声明。

---

## 0. 一页目标与完成边界

本轮只集中解决上一版三个相互关联的问题：

1. **缺口是什么？** 不能把历史环境报错直接当作当前功能矛盾，也不能让它挤掉列表、字典、异常分支等公开要求。
2. **相关知识是否还在？** 不再在查询之前把整个仓库压成 40 条片段；先建立完整的合法源码索引，再按当前任务局部召回。
3. **为什么这段知识有用？** 词语/向量相似只是检索信号；组合时还要区分规范支持、实现上下文、前置条件、验证方法和仅仅词语接近。

执行主链：

```text
复现旧四状态的具体表示/召回问题（只作开发诊断）
  → 全量范围元数据索引与任务局部召回
  → 公开要求—时序观察关联的功能缺口
  → 同候选的 MMR / 相似度覆盖 / 有证据关系覆盖
  → 先做独立于组合器分数的来源语义核对
  → 冻结方法，在预登记新状态上做有限真实续跑
  → 分开报告表示、召回、选择和功能结果
```

**终端主要指标仍为目标功能通过且无新增保护回归。**
本轮增加的来源关系评测是必要的机制诊断，不替换这一指标。

必须交付实际算法、真实源码与状态的选择结果，以及可执行范围内的真实补丁对照。
无功能收益允许结束研究；只有新 schema、几张说明表、自己的覆盖分变高或 CI 通过，不算算法实证完成。

## 3. 防漂移：四个对象分开，不许混成一个分数

```yaml

primary_comparison: H_link_minus_M_local
mechanism_comparison: H_link_minus_H_sim

new_neural_training: false

guidance_token_cap: 1200
max_pack_units: 4
legacy_results_overwrite: false
```

四种报告不可替换：

| 对象 | 可以回答 | 不可以冒充 |
|---|---|---|
| 公开缺口准确性 | 当前摘要是否对应真实公开要求与观察 | 最终功能正确 |
| 知识召回与关系质量 | 原文是否对题、关键合法资料能否进入候选 | Agent 必然受益 |
| 组合决策 | 规则是否改变选择、引用与预算是否一致 | 更优修复策略已成立 |
| 功能结果 | 同状态下补丁是否真正改善 | 总体泛化/学术首创 |

不要把“修正状态后不再看到环境错误”当目标：历史事实必须保留，只是分类、时效与功能权重不同。
也不要为了显得算法更强，把无关系的相似片段包装成“必要前提”。

## 5. 完整功能要求账本：不是前六行摘要

从**修复 Agent 当时收到的完整公开题面**提取功能义务，不读 reference、test_patch 或未来轨迹。
每项保留原始跨度和条件分支：对象、输入条件、期望行为、异常要求、与其他要求的关系。

```yaml
requirement_id: stable_within_request
parent_requirement: optional
verbatim_span: {field: request, start: ..., end: ...}
subject: public_API_or_behavior
condition_text: source_supported_condition
expected_text: source_supported_behavior
case_family: scalar | list | mapping | exception | compatibility | other
status: unverified | contradicted | locally_supported
observation_refs: []
conflict: false
```

要求：

- 完整账本不设“先到先得六项”上限。长题按父要求分批处理，组合函数可在所有已解析要求上计算。
- `unless`、否定、互斥、默认值、空值和非空值规则不能拆丢；把一条要求分成更多子句不能增加它的总权重。
- 所有原题要求跨度有归属；无法解析的跨度进入 unresolved，不静默丢掉。
- 主要求账本与紧凑显示摘要分开；界面只显示几项不能改变算法的完整输入。
- 源码现有行为不是题面规范；题面本身矛盾时标冲突，不自动选择更像参考实现的一种解释。

默认按完整 bullet/段落切分并保存条件；必要时使用冻结的结构化抽取提示，输出必须回指原文。
提取器不生成修复计划、不定位本题答案。来源位置可验证不等于语义自动正确，仍需第 17 节核对。

## 6. 时序观察：区分功能、环境、读代码与候选修改

从检查点之前的真实事件构造 Observation，不仅消费 `failure_text` 拼接字符串。
每项包括 event/turn 序号、完整命令、退出状态、源码版本标记、可见输出位置、涉及测试/符号、信息完整性。

```text
kind: FUNCTIONAL_ASSERTION | ENV_TOOL_FAILURE | SOURCE_READ |
      PUBLIC_CHECK_PASS | CANDIDATE_CHANGE | UNKNOWN
lifecycle: current | superseded | historical_unresolved | unknown
requirement_links: list of grounded associations
```

重要规则：

1. 缺少共享库、git 或 `.git/HEAD` 默认是执行条件问题，不自动新建一条功能要求。
2. 如果公开任务本身要求处理某环境失败，必须关联到这条真实要求；不能按错误关键词一刀切删除。
3. 同一次失败命令的后续可比重跑成功，才能对对应失败建立 superseded 关系；不同测试通过不能清空全部历史错误。
4. 测试成功只能为其实际可识别的覆盖范围提供**局部**支持。只有退出码、没有覆盖映射时，不把整项复杂需求标完成。
5. 支持证据之后相关源码又改变，应标证据陈旧/要求待验证；不能沿用老 PASS 证明新候选。
6. 存在互不覆盖的成功和失败证据时保留冲突，不能简单按最后一条日志覆盖。
7. 没有完整命令/顺序/源码关联时写 unknown，不从最终成功倒推早期状态。

环境观察保留独立列表，供解释运行条件；未关联到功能要求的环境项在**功能覆盖权重中为 0**。
本轮不新建环境恢复 Agent；真实执行环境失效仍由既有运行器正常处理。

## 7. 功能要求—观察关联：既不是关键词匹配，也不是全知裁判

关联最小依据：实际测试 node/调用对象、同一公开输入/输出、可解析断言、源码符号或有来源的语义对应。
优先确定性解析已结构化的信息；语义不明确时用固定模型做受限关系提议，并记录判断依据。

提议输入仅包含该条要求、检查点前相关事件及允许源码片段；不得含隐藏测试、原生终端隐藏结果或其他分支。
输出只允许 requirement_id、observation_id、关系类别、两侧原文跨度与简短依据，不允许修复步骤。

`contradicted` 必须是有对应公开证据的功能矛盾；“曾经运行失败”不能直接赋值。
`locally_supported` 表示有限观察支持，不叫全局已验证；`unverified` 表示当前证据不足，不表示模型不懂。
默认权重沿用 2 / 1 / 0.25；先按父要求归一，再在其子条件中分摊，禁止通过拆句放大权重。

同一个状态只构建一次关联账本，MMR、H-sim、H-link 接收相同事实、状态与候选，不给 H 专属的人工根因提示。
模型给出的引用与关系是待核对提议，不能自动称为形式逻辑证明。

## 9. 索引在前、任务筛选在后：取消查询前的 40 项库上限

建立仓库/精确 base 的轻量索引；默认覆盖该 base 合法的一方源码、文档与已存在公开测试。
一次固定范围与排除理由，不依靠 hidden test、fix diff、事后候选路径决定要索引哪些文件。
不抓取新版本 release notes 或远端答案。vendored、生成物、二进制、私密/未来材料分别排除并计数。

索引保存：路径、qualified symbol、类/函数/赋值边界、docstring/段落、import绑定、可静态解析的调用关系、内容身份。
可用本地文件/SQLite/倒排表，不建图数据库或向量服务。

重点覆盖上一版容易遗漏的内容：

- 类的 `DOCUMENTATION` 等字符串赋值及文档片段，而不只 `ast.get_docstring()`。
- 与正常返回、状态更新、数据保持有关的函数逻辑，而不只包含 `raise` 的 guard。
- 同一符号的定义、直接调用者/被调用者、真实 import 目标和引用它的已有公开测试。
- 超长定义先保留元数据，查询到时按完整语法分支与必要外围条件形成局部视图；不要在入库时全部丢弃。

**不要求把全部正文立即送入编码器。**完整元数据/词法索引可先做，向量按文件/单元缓存或延迟计算。
资源不足时公开索引覆盖范围及尚未建立的分片；不能悄悄恢复“排序最前40条”。

## 10. 知识视图：保留条件、区分规范和实现

沿用 RepairKnowledgeUnit/SourceSpan，做必要扩展而非换一套无调用方的schema。
每项实际包含来源跨度、适用符号、明确可抽取的前置条件、内容角色和可用的公开验证示例。
无法提取某字段就 unknown/None，不能再用统一的“详见原文”假装已经建模了前提。

三种内容角色至少分开：

- `documented_contract`：公开规范/文档所说的预期。
- `existing_behavior`：base 当前实现所展示的行为，可能恰是有 bug 的行为。
- `public_test_example`：修复前已经存在的公开示例/测试，支持范围有限。

普通源码不能通过改字段名升级为正确不变量。候选已修改的源码只作为当前观察，不混入静态 base 库冒称旧知识。
跨函数视图可以包含直接调用关系与必要条件，但每段都有原位置；无法静态解析的动态调用不得伪造边。
不总结“把第X行改成Y”，不把参考修复蒸馏成维护知识。

控制实际指导仍使用同一 tokenizer、1200 tokens、最多4项完整单元。超长单元需带必要上下文的有界视图或标不可装包，不能从结论中砍掉前置条件。

## 11. 任务局部召回：全局搜索、局部扩展、再统一截到 24 项

输入：完整公开要求、当前相关功能观察、真实读过/改过的符号，全部截止检查点。

建议固定流程：

```text
逐要求 BM25 / 精确符号 / 路径召回
  → 全局种子定义与公开已读符号
  → 一跳可解析调用/import/测试引用扩展
  → 完整来源视图物化与冻结 MiniLM 编码
  → 多通道合并、去重、逐要求分配
  → 共同候选 C(s)，至多24项
```

初始具体默认：每条要求最多8个词法/符号种子；合并后最多128个完整视图进入精排；每个种子一跳扩展最多4条真实边；不递归漫游仓库。
这些是查询后的工作量预算，不是整个仓库只有128项；去重、溢出和未覆盖要求单列。
先按要求轮转保证多种输入/行为分支有候选，再用归一化混合相关性填剩余名额，固定平分规则。
索引中的文本可以 task-independent，查询与局部视图选择可以 task-dependent；两者都不能依赖答案。

保留冻结 MiniLM，采用已有完整分块编码；BM25/向量/符号权重可沿用 0.3/0.6/0.1，首个开发核对前固定，不根据最终胜负搜索。
环境日志不与全部功能query无差别拼接。与公开功能义务相关的环境观察才可进入对应子query。

输出每个候选的检索入口、符号路径、扩展依据与针对的要求；“同一个文件import过”不能冒称存在直接调用关系。

## 12. 关系化覆盖：相似度负责找候选，来源关系负责解释用途

对同一 C(s) 与同一要求账本建立关系表，不让 H 的目标函数为自己输出真值。

| 关系 | 含义 | 预定覆盖权重 |
|---|---|---:|
| CONTRACT_SUPPORT | 来源直接说明该条件下的期望行为 | 1.0 |
| VERIFICATION_PATTERN | 提供该要求相关的具体公开验证办法/示例 | 0.7 |
| PRECONDITION | 提供明确关联且适用的前置条件 | 0.6 |
| CONTRADICTION_CONTEXT | 展示当前实现与公开预期的有依据差异，只作排查上下文 | 0.6 |
| IMPLEMENTATION_CONTEXT | 有真实符号/行为关联，但不证明正确预期 | 0.3 |
| TOPICAL_ONLY / UNRESOLVED | 仅词语相关，或无法建立有据关系 | 0 |

这些值是本轮预先声明的启发式，不是成功概率、置信度或已学到的效用。
每对至少有 requirement_span、unit_span、条件是否适用、关系类别、简短依据。
类型冲突或引用不合法不能得到正覆盖；实现本身可能错误不意味着它毫无排查价值，须按角色保留。

默认用已有合法可用模型做一次冻结的批量关系提议：同一状态的24候选与要求分批处理，只分析源材料，不生成代码、不调用工具修任务。
模型名、提示、推理设置、批次顺序和输出格式在新状态检验前冻结；在运行前核对实际可用版本，不隐式使用最新默认。
没有可用语义模型时可以完成结构索引与符号关联，但不得把纯词法结果标为语义关系覆盖已实现。

模型关系判断与独立核对均另计量；不购买服务，不重复采样直到得到喜欢的关联。
输出格式/服务错误允许范围内修复，保留旧调用；已知语义结果不得重抽只保留最好一次。

## 13. 三种同池选择器：主对手不能被故意弱化

共同条件：同一完整合法索引、公开状态、关联账本、候选ID/顺序/正文、tokenizer、载荷模板与预算。

| 方法 | 选择规则 | 用途 |
|---|---|---|
| M-local | 0.7相关性 − 0.3最大已选冗余的MMR | 主要低成本基线 |
| H-sim | 正确功能缺口＋原相似度覆盖组合 | 隔离关系化覆盖的对手 |
| H-link | 正确功能缺口＋来源关系覆盖组合 | 本轮主方法 |

M-local 的query也包含相同公开要求与已关联观察；不能只给它标题。
关系表可提供给各选择器作为共同元数据，M-local仍按预定MMR选择，不能给H额外人工解法。
最终注入正文一律采用同一原文/条件/引用模板，不给H额外解释型修复计划。

H-link沿用上一版集合目标，只替换覆盖项：

\[
F_{link}(A;s)=\sum_j w_j\max_{i\in A}a_{ij}
+0.10\sum_{i\in A}r_i
-0.10\sum_{i<l}d_{il}
-0.05\sum_{i\in A}e_i.
\]

其中 a 是有原文依据的关系类别权重；H-sim使用旧的向量/词法c，其他项相同。
可见重复率只代表出现过，不代表Agent理解，未知不作为“没见过”的测量事实。
采用同一正边际/token贪心和最佳可行单项比较；不宣称全局最优或1−1/e保证。
没有可用功能要求则显式退回M-local；空包或fallback不得被记成发生过新方法干预。

## 14. 离线消融：区分缺口、库覆盖和组合

先用旧四开发状态运行，不调用修复Agent：

1. **状态表示表**：旧摘要与新账本读同一事件前缀；比较功能要求遗漏、环境项混入、失效证据与错误支持。
2. **查询前截库对照**：固定新query和同一检索器，比较旧40项子集与完整索引；旧单元保留在新索引中以便来源对应。
3. **符号局部扩展对照**：完整索引与新query不变，关闭一跳扩展；仅用于判断可解析代码关系的召回作用。
4. **同池选择表**：固定新C(s)，比较M-local、H-sim、H-link。

每项只改变声明的因素。不同索引上的H对旧M胜负不能作为组合算法独立收益。

## 15. 先核对知识是否对题：参考证据不能由H自己挑

在运行器生成方法包之前，由分开的只读核对上下文依据公开题面、检查点前观察、base源码建立小型参考锚点集。

## 16. 离线指标：不通过自己的函数制造正结果

至少报告以下可核对事实，按要求/状态分别列出：

- 公开要求保留情况：独立核对的条件分支是否进入账本，含否定与互斥。
- 功能缺口污染：无功能关联的环境观察是否得到正功能权重。
- 关系精度：被判为正关系的候选中，核对支持/反对/未知各多少；未知不删除。
- 参考锚点命中：有已找到参考锚点的要求，候选是否命中相应来源或有依据的等价来源。
- 最终包支持：有针对性的条件覆盖、仅主题相关内容占比、丢失前提和相互冲突。
- H/M实际选择和长度差异，以及每个有用/无关来源的解释。

参考锚点集并非完备gold，不将命中率称为完整仓库召回率，也不宣称“功能覆盖率”。
自己的F、余弦、关系提议分数只能作诊断附列。
语义核对尚不支持差异时写清，不换成更好的相似度指标报提升。

## 17. 修复性准备检查与效果判断分开

进入新状态/真实续跑前要满足的是普通实验可执行性，不是“H必须赢”：

- 实际输入只含正确的公开前缀，来源和条件没有缺失或越界。
- 旧环境错误污染与原题分支丢失的具体实现问题已经通过通用反例及真实旧状态核对。
- 能从合法源码生成真实候选，选择器在同池工作，载荷可装入预算。
- 隐藏验收可执行，公开义务与关键保护检查没有已知未处置冲突。

不要求H离线分数高于MMR，不要求N已功能失败，也不要求先出现技能救回。
若该任务全部候选都无法建立任何有据关联，应明确 `NO_SUPPORTED_LOCAL_CONTEXT`，不硬塞不相关资料凑干预；保留任务分母，不按功能结果替换它。
若只是效果持平而非输入/实现错误，按冻结方案完成有限真实比较，不能又停在推荐JSON。

## 22. 功能判定：明确失败、未知和完整性边界

复用已修正的可信测试安装规则；在新采样前核对目标测试和保护集合确实执行，不能到尾程结束才发现test.patch冲突。

本轮新的报告协议使用独立有效判据：

```text
完整性无效 / 未确认真实候选 → UNKNOWN
有可信且在公开范围内的目标或保护失败 → FAIL
全部必要目标与保护有效通过 → PASS
否则 → UNKNOWN
```

即：一项合同分类未知，不会抹掉另一项已独立确认的保护失败；但无依据的精确消息差异也不能被当作可信功能失败。
重大公开合同歧义在采样前排除或明确标不可完整判定；不为涨分事后增加义务。
该协议是本轮新版本，不能修改旧functional_outcomes导致#48–#52历史表自动变值；保留旧入口，必要时以新薄报告适配实现。

旧第四机制的16条UNKNOWN及15条保护失败在本轮只作边界说明，不重新重算成新的正负效果。
不再开展旧56候选审计或六补丁复验；旧收尾已经完成，不能自动继承为新主线。

## 23. 结果与归因

先报告每状态N/M/H-sim/H-link的目标、保护、功能通过/失败/未知/计划数，再给H-link−M、H-link−H-sim与M−N。

UNKNOWN保留全计划上下界，不能只删掉未知后取已知均值冒称完整对比。

归因边界：

- 旧40库与全索引的离线差支持检索入口诊断，不自动证明召回导致功能改善。

- 表示/关系质量提高但功能持平：表示问题改善，功能收益未建立；不能改主指标。
- 全部通过：当前有限比较没有功能区分力，不证明方法总体等价。
- H没有超过M或不如M：保留MMR结果和默认，不删除便宜基线。

没有新训练，不称“学会了修复”；没有等待对照，不认领时机学习。更多源码片段也不等于知识自动推理成功。
