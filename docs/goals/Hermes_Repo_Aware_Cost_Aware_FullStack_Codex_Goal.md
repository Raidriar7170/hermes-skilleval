## 4. 正确的最终架构：先判断值不值得，再运行昂贵模型

```text
公开请求 + 修复前/当前源码快照 + 实际环境事实
                         |
             便宜、确定性 Repo Context
                         |
                前置 Cost-aware Gate
           +-------------+--------------+
           |             |              |
        N: Native     F: Fixed       R: Learned Route
           |             |              |
           |             |     强 encoder 召回候选
           |             |              |
           |             |     训练后的 repo-aware reranker
           |             |              |
           |             |     有预算的技能集合选择
           +-------------+--------------+
                         |
                共同 Agent 执行器
                         |
              实际 patch + 外部有限验证
                         |
               结果、暴露、用量、失败分析
```

S 表示原公开强检索基线；R 表示新训练排序＋集合选择。主门控在 N/F/R 中决策，不用“是否调用 S”指代不同版本的流水线。

### 必须遵守的五项修正

1. **不能先跑完 encoder/reranker 再决定“不调用检索”。**那只能叫后置选择，已经花掉的成本不能计作节省。
2. gate 的输入只能是决策当时可得的便宜特征。reranker分数、目标测试、候选patch、最终token数均不能成为前置特征。
3. 获得相同仓库信息的原生/固定基线必须存在；不能只给新方法额外信息后，把全部收益叫选择算法收益。
4. 一次运行的成功/失败，不是每个被挂载技能的独立因果标签。未观察动作不能填失败。
5. “覆盖－冗余－成本”写成公式，不自动具有单调次模保证；本轮明确选择可验证的优化实现，不套用不成立的理论结论。

## 5. 端到端产品行为与非目标

新增或扩展一条统一策略参数，推荐语义如下；实际命令名由实现决定，文档必须以真实 help 与实跑命令更新：

```text
native      = 同一合格技能库，原生渐进发现
fixed       = 仓库级冻结组合，与当前请求无关
strong      = 旧真实强检索＋固定 Top-2，作为对照
repo-aware  = 新训练排序＋预算集合选择，总是运行 R
auto        = 便宜 gate 选择 N/F/R，仅执行选定路径
```

旧 `--arm N/F/S/T` 接口保留兼容，不静默改变旧 S/T 的算法或模型。新增模式应有新的策略身份。

auto 要接入真实 replay 和 assist，而不只是离线 `recommend.json`。旧 N/F 仍无检索模型依赖；auto 的便宜分支不应加载 Torch/Transformers或访问重模型权重。

模型包缺失：显式 `repo-aware` 应清楚报错；auto 可以按已声明的 fallback 返回 N/F，并记录 fallback_reason。不能冒充运行了 R，也不能因找不到新模型回退 hashing 仍保留原名称。

本轮不做在线RL、PPO/DPO训练执行Agent、动态循环补检、多模型执行器自动切换、GUI前端、多租户SaaS、自动修改用户原仓库或自动提交上游。后续训练内容仅是小型排序/覆盖评分器和路由门控。

## 6. 数据设计：先有真实任务，再有有效学习信号

### 6.1 任务来源与资格

核心使用可追溯的公开 Python 仓库维护需求、历史 issue/bugfix 回放。已有 sqlite-utils/csvkit 适配继续复用；本轮允许接入少量相近仓库以支持新的、未见仓库测试。

先按安装/许可/目标行为/接口范围选定候选，不按原生是否失败、R是否可能赢来筛题。不把明确给出的修法藏起来制造难度，也不额外加入题面/文档无法推导的秘密要求。

可信控制器先核验：base 目标红、可信修复绿、base与修复的受保护回归成立；集合/加载错误与功能失败分开。参考patch与隐藏测试不进入路由或任务Agent。

扩展仓库按实际差异提取最小 profile；不要复制 runner。候选获取失败可以调查下一个预定义候选，记录资格失败原因，不用合成JSON题填满主要分母。

无参考的新 assist 只用于产品验证/真实使用观察，不自动生成完整 `success=1` 学习标签。仅当独立判据明确覆盖所定义质量目标，才按该限定目标进入数据。

### 6.2 推荐规模与完整性

建议完整研究优先准备 3–5 个仓库、约 60–100 个独立修复族，以下为首次资源规划参考：

| 分区 | 建议修复族数 | 用途 |
|---|---:|---|
| rank-train | 24–40 | 相关性/能力训练及开发执行标签 |
| rank-dev | 6–12 | 选择排序训练参数和集合策略 |
| gate-fit | 12–24 | 固定 R 后，训练 N/F/R 动作收益与成本模型 |
| gate-calibration | 6–12 | 阈值、成本权重、校准和默认决策 |
| final-test | 12–24 | 策略冻结后确认；同时含未见修复族与未见仓库子集 |

数量是研究起点，不是“凑到数字就有效”的验收线，也不是允许尝试次数。用户未授权额外费用时不为了凑数购买资源。规模变动必须在观察相应结果前说明。

完整实现可以在较小样本上跑完，但若校准/泛化依据不足，必须将 evidence_level 写为 PILOT，不得用参数对数或运行次数替代独立任务数。

若只有旧两库、几条旧题或全部合成任务，只能报告局部原型/数据不足，不能声称完整跨仓库验证。

### 6.3 严格但不过度承诺的数据划分

- 按修复机制/同一 issue-PR 家族分组。多个别名、同一回滚、同一补丁的变体进入同一区。
- rank-train、rank-dev、gate-fit、gate-calibration、final-test按修复族分开。
- 至少一个 final-test 仓库不参与排序训练、门控拟合或校准。适配工程可以在无关smoke上完成，但不得查看该测试库的目标结果后调整算法/技能。
- 不能把同一任务的100个技能对称为100个独立任务。重复执行、改写请求、多个目标测试也不是独立任务。
- 历史公开修复可能在基础模型预训练中出现；只能承诺本轮受控输入不泄漏，不能声称无预训练污染。
- SkillRouter公开评估与SkillsBench有来源重叠，不能同时当两份独立确认，也不要把公开评估标签用于训练再原样评测。[P1]
- final-test 的请求和base可由评测控制器交给冻结推理路径；目标标签/参考patch不能被训练器、需求抽取器或选择器读取。

### 6.4 保留“可做”与“做对”的分母

每个资格候选、每次Agent尝试和所有启动前失败都记录。修复族结果之外单列：准备失败、政策拒绝、模型未启动、超时、验收未知。

统一政策错误应保留原结果，必要时在冻结后的事后敏感性分析中重验所有受影响原patch；不择优覆盖主表，不只重验新方法。

## 7. 技能库：自然匹配、完整资源、避免人为制造路由必要性

建立两个明确不同的池：

1. **执行技能池**：确有当前工作流用途、许可可用、资源齐全、依赖已核查的完整技能包。建议先几十项自然相关能力，不要求凑数。
2. **索引规模池**：可扩到数百/千级真实去重技能，用于检索/延迟实验；只有通过执行资格的包才能在真实Agent上运行。

所有真实对照条件使用同一执行池和同一技能内容。原生选择不是全量正文灌入，而是客户端真实渐进发现。[P5]

禁止：同一技能改名复制凑规模；为确认题定制答案技能；给 baseline 删除重要说明；给新方法秘密注入参考实现。

技能清单保留 source_repo、revision、package文件、许可、说明/正文、工具要求、输入输出、版本适用条件及证据片段。自行整理的项目技能标明作者与来源，和外部独立技能分开。

去重保留三类：字节相同、明确可替代、未知。不要把同名或embedding相近直接当可替代；不同版本支持不同API时必须保留差异。

必要的仓库贡献说明对所有臂共同提供，不应只放在Hermes专用技能里。

## 8. Repo Context Extractor：便宜、只读、有来源

### 8.1 允许的输入

仅公开请求、base/current snapshot和已核对环境事实：

- 文件目录的有限摘要、包与CLI入口；
- `pyproject.toml`、setup配置的静态字段；不执行setup.py；
- 请求明确提及的函数/类/命令/异常及静态匹配；
- 候选相关源码片段、原有公开测试位置、import关系；
- 实际解释器/依赖/网络限制，来自控制器探测，不来自技能自述。

先使用AST、TOML/JSON读取、词法检索等确定性方法。不要用完整仓库LLM总结器作为廉价gate的前置，也不要构建全仓库知识图谱。

### 8.2 输出建议

```json
{
  "schema": "repo-context-v1",
  "snapshot_id": "...",
  "public_request_hash": "...",
  "entrypoints": [{"kind": "cli", "symbol": "pkg.cli:main", "evidence": "pyproject.toml:10-14"}],
  "matched_symbols": [{"symbol": "query", "path": "pkg/db.py", "lines": [40, 65]}],
  "related_public_tests": ["tests/test_cli.py"],
  "environment": {"network": "disabled", "python": "observed version"},
  "capability_facts": [{"fact": "repository exposes CLI and Python package", "evidence_refs": ["..."]}],
  "truncated": false,
  "cost": {"wall_seconds": 0.0, "bytes_read": 0}
}
```

上例是接口形状，不是当前实测结果。每项事实可回指文件/行；推断用 `inferred=true`，未知不编造。

### 8.3 预算与稳定性

设定有限文件数、源码片段长度和总token预算；具体值在dev冻结。超长请求保留关键字段并明确截断，不静默吞掉否定条件。路径选择稳定、排序可复现；缓存键包含源快照、请求、抽取版本与有效配置。

同名项目但内容变化必须失效。测试修改 CLI entrypoint、相关符号、配置后确实重新提取；不变输入可命中缓存。

检测到不支持布局/无法解析时返回缺失项并触发保守回退，不把“解析失败”当成“没有CLI”。

### 8.4 在线特征禁止项

不得使用 target/reference文件、候选patch、修复后符号、最终验收/用量、其他臂轨迹、issue ID→正确技能表、人工确认阶段的标签。

仓库名/任务ID仅作日志键。门控不靠 `repo_id` 或 `task_id` 记忆答案；可使用真实工具栈/布局等可转移事实。

## 9. 需求与能力证据：不要重复词面误匹配

从请求提取少量要求，保留操作、对象、约束、否定、产物与验证范围。例如：

```text
操作：修复读取行为
对象：CLI/API的相关入口
约束：保留重复记录；无外网；不修改依赖
验证：原有行为保持；新增情况正确
```

规则/小模型皆可，但不能只因 `report/source/sorted` 等通用词重合就认证覆盖；不能逐题加 `if task_id...`。

用同一预训练/训练评分器评估“要求＋仓库事实—技能证据片段”的相关性，输出支持分与证据。对否定、输入格式、版本与依赖不匹配加入明确反例。

需要区分：

```text
SUPPORTED_BY_TEXT       原文确有相关能力描述
CONTRADICTED            明确方向或条件冲突
UNKNOWN                 原文不足、未标注、模型低置信
```

`SUPPORTED_BY_TEXT` 不等于技能必要、不等于成功概率，也不证明Agent实际采用。技能支持分只作选择特征，不能作为最终任务裁判。

没有明确信息时采用回退，不强行补出每个任务至少一个互补技能。

## 10. 复用强检索并建立真实可训练的 Repo-aware Reranker

### 10.1 冻结检索底座

优先复用已接入的真实公开模型：[P1]

```text
pipizhao/SkillRouter-Embedding-0.6B
pipizhao/SkillRouter-Reranker-0.6B
```

先锁模型 revision、tokenizer、query指令、字符裁剪、token上限、pooling、dtype、device与索引；校验本项目适配实际符合所用版本的上游输入/打分路径。

不强制重跑上游80K全量评估，不重新下载本地已核验模型。现有同名类可能有hashing默认项，必须通过实际实例与权重身份确认。

主算法消融尽量固定第一阶段召回集合：同一q使用同一encoder得到Top-M，新旧reranker在同候选上比较。query expansion/多路召回只能作为另列dev诊断，不能混入主贡献。

检索召回漏掉相关技能时记录上限，不能在测试时偷偷将gold补进候选。训练时补充正例可以，但标明它原来是否被召回。

### 10.2 输入表示

实现受预算控制的四段模板：

```text
[TASK] 原公开请求
[REPO_CONTEXT] 有来源的仓库事实和相关片段
[SKILL_METADATA] 名称、用途、适用范围
[SKILL_EVIDENCE] 原文中相关章节/步骤/约束
```

保留 request-only 对照。相同backbone下比较：无上下文、加入上下文但不训练、加入上下文并训练。必须记录实际token长度与被截断部分，不能把 `full` 文件名等同完整输入。

技能分段使用固定规则；聚合避免片段越多越容易虚高，可比较最大值、限定top-m平均等，dev选择后冻结。完整技能包交给执行器，检索片段不能代替完整可执行资源。

### 10.3 真实训练选择

首选对同一0.6B reranker进行LoRA或小范围参数微调，以减少“模型容量变化”的混杂。若它是causal yes/no打分模型，使用经核对的yes/no位置与logit差，不因名称叫reranker就直接套不兼容的CrossEncoder类。

训练、推理必须共享tokenization、模板与打分函数。替换为另一个公开Cross-Encoder仅作为有说明的资源兼容方案，重建相同backbone基线，不能冒充原SkillRouter微调。

实际任务Agent模型不在本轮训练。

## 11. 训练标签：相关性与执行效用分开

### 11.1 两层标签

**相关性/能力层**：来自公开请求、技能原文、明确环境条件，允许多正例、部分覆盖、冲突与未知。可以使用已授权LLM辅助提出标签，但标记 `model_judged`，保留原文依据和冲突；不能声称人工标注或独立真值。

**执行效用层**：来自同任务、同环境、同预算下的真实技能集合对照与外部验收。它约束的是集合/动作的效果，除非实验只改变一个技能且其他条件一致，不自动分摊成每个技能的因果标签。

未知候选不当负例；失败原因来自环境/政策/技能未读时，不把整包标成“没用”。

### 11.2 Execution-grounded hard negatives 的合格来源

允许从rank-train中预先选定一部分任务，固定一个anchor技能，比较替换第二技能的集合；同时保留相关性足够但约束冲突、输入类型不同、操作方向不同等困难对。

每个替换比较记录：相同/不同的实际包、前置模型/环境/提示、运行顺序、外部结果、读取证据及次数。出现一次成败差异，只能先记 `observed_preference`；按重复与不确定性加权，不能直接写“该技能造成失败”。

若两个完整集合同时变化，偏好用于集合效用/gate数据，不直接拆成skill正负对。

没有足够执行偏好差异时仍训练文本相关性模型，但必须报告 `execution_preference_signal_insufficient`。不得捏造偏好、靠LLM想象Agent修复结果，或换题直到出现想要的负例。

### 11.3 最小样本字段

```text
task_key / repair_family / repository / split
base_snapshot / public_request_hash / context_hash
candidate_pool_version / skill_package_ids
positive_or_preferred / negative_or_less_preferred
label_source / evidence_refs / confidence_or_weight
execution_comparison_ids / uncontrolled_factors / annotation_seen
```

标签范围写在dataset card。日志键不作为模型输入。prompt改写、片段展开、候选对派生都继承原修复族分区。

### 11.4 一个可实施的排序目标

对有可信偏好的候选对：

\[
\mathcal L_{pair}=-\sum_i w_i\log\sigma(f_\theta(q_i,c_i,s_i^+)-f_\theta(q_i,c_i,s_i^-)).
\]

`w_i`来自预定义标签可信度/重复证据，不根据确认结果修改。语义相关性偏好与执行派生偏好分开统计、分开消融。

可使用分级BCE/排序损失补充，但不叠加多种loss只为显得复杂；所有loss mask应有独立小算例。[P3]

句段支持评分可复用同backbone并以requirement为query；必须验证否定与冲突案例。未经单独校准，sigmoid后的分数也不称为任务成功概率。

## 12. 排序训练的实际验收

资源允许时推荐起点：LoRA r=8或16、dropout约0.05、学习率在1e-5至1e-4的小范围dev对照、1–3个epoch、梯度累积适配显存。这些是起始配置，目标模块从真实模型结构读取，不写死错误层名。

必须实际完成：

- 数据清单与划分检查；训练batch抽样检查；
- 正确mask、有限loss、非零梯度及真实可训练参数变化；
- 保存adapter/模型，干净进程重载；
- 重载前后固定评分probe一致；与训练前的差异可定位；
- 同backbone、同模板的request-only/ctx-untrained/ctx-trained对照；
- 至少一个完整训练轨迹，资源允许再做第二seed稳定性诊断；不能只保存最好seed并隐藏另一个。

训练loss下降、checkpoint存在或参数变化都不等于泛化提升。训练输出通过rank-dev选择；final-test不可参与学习率、checkpoint或种子选择。

MPS不支持某算子时优先调整合法精度/批量/CPU小规模路径；不要假装使用过CUDA。量化加载或替代backbone改变数值协议时单列。

## 13. 预算化技能集合选择：先定义正确优化对象

### 13.1 候选、覆盖与成本

reranker产生的候选池为C；要求集合为j=1…J。每个技能提供：相关性r_s、原文支持e_js、兼容状态、可替代族、包token统计。

建议目标：

\[
F(S)=\sum_j w_j\max_{s\in S} e_{js}+\alpha\sum_{s\in S}r_s
-\beta\sum_{s<t,\,s,t\in S}d_{st}-\gamma\sum_{s\in S}c_s.
\]

约束：

\[
|S|\le K_{max},\quad \sum_{s\in S}c_s\le B,\quad S\subseteq C_{compatible}.
\]

在实现中规定空集的覆盖为0；w_j非负，e_js和r_s使用在dev中固定的有界分数变换，原始负logit不能直接与token数相加。把这些分数变换到0–1不等于获得了校准成功概率。成本c_s、权重和预算单位要在配置中明确。

原文不足的UNKNOWN不被当作已覆盖；明确冲突可排除，未知则按声明策略惩罚/回退。d_st需要可解释，cosine相似仅为重复风险，不自动证明可替代。

`c_s`若为完整正文token，是**潜在加载预算/代理值**，不是已经支付的token。实际read/输入usage另测，不能直接据此声称节约费用。

### 13.2 不套用错误的次模保证

覆盖项在非负支持下有边际递减性质，但加入冗余/成本惩罚后目标可能非单调。简单贪心不自动具有单调次模cardinality的近似保证。[P4]

本轮首选：对截断后的较小候选池做确定性精确枚举。例如M=12、Kmax=4时仅794个含空集的子集，先预计算模型分数，再进行便宜集合优化。

这只是在已截断候选池内对所定义代理目标精确，不是全技能库或真实任务效用的全局最优。

若更大候选需要贪心/beam，保留小池穷举参照，报告代理目标差和时延；不编造理论最优性。禁止对子集逐个调用昂贵模型而不计成本。

### 13.3 必须保留的对照

- 固定Top-2；
- 等K的简单去冗余；
- 等K互补选择；
- 预算约束下可变K的完整策略。

先用等K检查集合决策，再允许完整策略可变K。更多技能带来的效果不能直接归因于“更聪明”。

预算下允许0项，但必须区分“无需额外技能”和“无法确定/预算不足”。后一种回退N/F，不把空集冒称最优。

不要固定保留一个已明确不兼容的第一名。anchor只允许在适用性证据成立时使用。

### 13.4 集合训练的归因边界

此版本集合优化器可不另训一个神经网络：排序/支持分来自真实训练模型，优化器是明确算法。如果只是启发式规则，不称成已训练的planner。

选择结果包含每项增量支持、重复惩罚、预算、拒绝/回退原因。所有选定包通过原有完整包物化路径进入Agent。

## 14. 先冻结 R，再采集门控训练数据

冻结R包括：模型checkpoint、context extractor、技能池、候选深度、评分模板、集合参数与版本。门控目标必须对应这一个完整R策略。

**不能用旧S的成功记录训练gate，再把动作S静默替换成新R。**也不能把rank-train上过拟合的R成绩当独立gate-fit验证。

在与排序训练修复族不重叠的gate-fit数据中，运行N/F/R，环境、模型、effort、公开信息、预算一致，随机化或平衡运行顺序。

优先小规模完整动作反馈：每个任务都观察N/F/R，计划重复以估计波动。默认完整动作采样不等于用户线上请求要执行三遍；它是训练数据采集开销。

若资源只能部分动作采样，预先随机设计并记录真实selection propensity，保留支持域。没有动作概率、没有探索覆盖的旧日志，不使用IPS/DR去“恢复无偏真实效果”。本轮不要求引入复杂离线强化学习；完整动作反馈优先。[P7]

另设gate-calibration用于概率/阈值与预算权重，不与gate-fit混为同一验证集。R一旦重新训练/改策略，旧gate标签不能无条件继续使用，必须更新版本关联与必要数据。

## 15. Cost-aware Gate：便宜的学习模型，不是任务难度口号

### 15.1 决策特征

允许：请求长度与结构、明确工具/入口要求、静态上下文统计、工具栈、候选目录规模、便宜词法匹配的不确定性、资源是否齐备。

禁止：为了决策先加载0.6B模型、读取强reranker分数、执行Agent后看补丁/测试、从最终使用量反推本次特征。

若使用已有轻量hash/词袋/稀疏特征，它仅服务便宜gate，必须明确它不是强检索模型的替代。统计归一化与词表仅在gate-fit拟合。

### 15.2 首选可训练实现

从正则化的动作条件logistic质量模型与简单成本回归开始；小MLP或梯度提升树作为开发对照，不默认“大模型比小模型好”。

对真实完整反馈，质量标签来自可信限定验收；未知/政策拒绝不填0。可以训练动作条件的 \(\hat p_a(x)\)，或直接训练动作间收益差；最终须比多数动作/常量策略基线。

动作比较的数据按修复族加权；重复运行可用成功次数/有效次数形成二项观测，不把同一任务的重复当独立问题。对缺失质量的样本保留成本记录但不生成虚假质量标签。

质量probability需在独立数据上检查Brier/log-loss和可靠性；小数据不盲目使用高方差校准。必要时用正则化sigmoid/温度方案；校准不足就输出估计分或宽不确定性，而不是“0.93成功保证”。[P2][P6]

只有一类标签或动作差异几乎不存在时，不伪造训练样本。可使用平滑的常量模型完成退化情形处理，但报告 gate_data_signal=INSUFFICIENT，不称已学会识别何时需要R。

### 15.3 效用与约束

定义：

\[
\hat U_a(x)=\hat p_a(x)-\lambda_t\tilde T_a(x)-\lambda_u\tilde U_a^{tokens}(x).
\]

其中时间/用量按**gate-fit中冻结的正尺度**归一化；权重在校准集或事先工作模式中选择，不能混用秒、美元、tokens而不说明单位。

若实际计价不可得，默认做时间/资源向量与Pareto分析，美元保持null。代理效用可训练，但不能把代理效用胜出写成已测美元降本。

先确定一个便宜fallback（N或F）：根据开发数据、可用配置和风险边界冻结，不按final-test挑选。只有预估质量/成本条件允许、且数据支持范围适合时才选择R。

不确定/新工具栈/缺模型时回退。所有样本回退是允许的真实结果，不能为了展示三条分支而强迫路由；此时应明确没有证明adaptive收益。

### 15.4 质量保持不是“差异不显著”

目标是质量—成本权衡。质量可接受的下降幅度delta必须事先说明，不能看完结果后扩大delta。小样本置信范围太宽时不能宣称非劣或等价。

可优先提供 quality-first 和 budget-aware 两个明确模式；每个模式用固定校准阈值，不在同一主表中替每题选择最好模式。

## 16. 如何证明 gate 真正省掉了昂贵工作

必须有下列实际测试与计数：

1. gate选择N/F时，重模型构造、encoder查询、reranker forward调用数均为0。
2. 在没有Torch/Transformers和重模型文件的干净环境中，具备gate轻量依赖与fallback配置即可走N/F。
3. gate选择R时，实际加载绑定的训练模型和集合策略，不能只改变返回字符串。
4. 计时从真实请求开始到报告/补丁就绪；context、gate、模型初始化、索引、重排、选择、Agent与验证分别记录。
5. 已有持久进程里重模型驻留的内存仍需说明；“本次未forward”不等于整个服务没有重模型占用。
6. 冷启动与warm cache分开；训练/数据采集费用、运行时开销分别报告，不能把离线预计算的查询结果算成在线免费。

在最终测试，H必须先决策并持久化选定动作，再启动对应Agent，不得从已经运行的N/F/R结果中挑最好答案。

离线重放完整动作表可用于开发估计，但不能代替至少一次冻结H的真实在线执行，也不能称独立因果验证。

## 17. 与现有 runtime 的完整接入

### 17.1 可复用核心与新增最小接口

建议按职责分模块，不强制文件名；不要把所有逻辑写进新的千行实验脚本：

```text
repo_context/          静态抽取、事实来源、预算与缓存
routing_data/          标签、分组划分、执行偏好关联
repo_reranker/         模板、训练、打分、checkpoint加载
budget_selector/      候选支持、集合优化、回退
routing_gate/          决策特征、质量/成本拟合、校准、策略
routing_policy/        native/fixed/strong/repo-aware/auto统一调用
```

输入可统一为 `RoutingRequest(public_request, snapshot, environment, registry, budget)`；输出含策略版本、动作、技能集合、原因、预计成本/置信边界和已发生开销。日志标识与模型输入分开。

控制器内部共享ContextEvidence，不在多条臂中复制不同prompt。现有 `assist` 仅支持两种布局的检查必须明确扩展为新的受支持profile，不能绕过检查/伪造库名来承接第三仓库。

### 17.2 模型与策略包

模型包包含：真实base/revision/tokenizer、adapter、feature schema、context版本、policy参数、训练数据身份、适用动作与fallback。加载时校验版本兼容。

本地JSON/安全张量等可用；不从不可信网络加载任意pickle或未经检查的远程代码。门控工件优先可解释参数格式。模型身份检查优先启动时一次，不在每次请求重复全库/全权重哈希。

原有N/F安装仍轻量，训练依赖放extra。auto可以加载轻量门控而不导入重模型，只有R分支才加载强模型。首次R延迟应计入，缓存应区分模型/索引/输入。

### 17.3 有参考与无参考路径分开

历史replay：仍必须有真实qualification、可信目标/回归，不允许新路由参数绕过。

当前assist：仍基于当前字节快照，不修改原仓库；支持dirty-worktree且仅输出Agent新增delta；没有完整目标判据时总体resolved保持未知。路由gate的预计成功率不能替代最终有限验证。

用户明确要求只用N/F时不偷偷启用模型训练或自动探索。`auto`为显式新实验模式，在未满足晋升条件前不改变现有默认。

### 17.4 可重复运行入口

提供实际的：数据准备、采集、训练排序器、拟合门控、冻结协议、评估、离线报告重算和在线使用命令。可以采用几个小脚本/现有CLI子命令，不需要发明通用pipeline引擎。

示意接口（开发后必须替换为真正能跑的语法）：

```text
hermes-maintain route --repo ... --request ... --policy auto --routing-config ...
hermes-maintain assist ... --policy auto --routing-config ...
hermes-maintain run ... --policy repo-aware --routing-config ...
python scripts/repo_aware/train_reranker.py --config ...
python scripts/repo_aware/train_gate.py --config ...
python scripts/repo_aware/evaluate.py --protocol ... --resume
python scripts/repo_aware/recompute.py --index ... --output ...
```

文档不应声称这些拟议命令已经存在。交付时 `--help`、参数、依赖、相对路径、失败码均与实测一致。

## 18. 开发对照与消融：每次解释一项贡献

不要把上下文、backbone、训练数据、候选数和预算同时改变后，只报告一行“ours”。

### 18.1 便宜离线层

在rank-dev上至少比较：

| 条件 | 保持什么相同 | 检验什么 |
|---|---|---|
| 原强模型 request-only | 同一召回池与backbone | 对照 |
| 原强模型＋repo context | 相同模型权重 | 上下文信息的作用 |
| 训练后模型 request-only | 相同训练来源、控制输入预算 | 训练作用是否依赖context |
| 训练后模型＋repo context | 相同候选与标签范围 | 完整排序方案 |
| Top-2 / 去重Top-2 / 互补Top-2 | 同一分数与K | 选择层的增量 |
| 预算选择 | 同一候选、另列实际K/预算 | 变量K的权衡 |

训练对照模型不得借用final-test确定配置。资源不足时至少保留主模型、同backbone未训练对照与关键context对照；缺少的消融明确列为未运行，不用mock曲线补齐。

离线度量：多正例Recall@K、MRR/nDCG（仅对已标注范围）、已证实冲突率、候选冗余、需求覆盖与未知比例、模型延迟。标签不完整时，不把未标注候选一律计错。

### 18.2 执行层消融

在预先选定的开发子集比较：

- 有相同上下文的原生Agent vs 没有新增摘要的原生Agent；
- 同K强检索 vs 同K学习排序/集合选择；
- 总是R vs gate路由；
- 文本标签训练 vs 加入合格执行偏好训练（有足够真实偏好才称该消融成立）。

不是每个任务跑所有组合；事先按机制选择子集并记录依据，不按是否获胜补选。消融任务与final-test分开。

### 18.3 实际干预检查

每个任务记录选定集合、完整包内容/顺序、元数据可见范围、可观测读取和最终补丁。集合没有变化可以是正确决策；不能强迫换包或只保留换包任务。

只有排名变化但暴露不变时，后续差异不能归因于排序干预。读取日志证明的是某次读取被观察到，不证明理解或因果作用。

## 19. 冻结后的主评估

### 19.1 主表保留五项，而不是四项混在一起

| 方法 | 含义 | 主要目的 |
|---|---|---|
| N+ | 原生渐进选择＋共同仓库事实 | 强、合理的产品默认对照 |
| F+ | 冻结固定技能＋共同仓库事实 | 简单低成本对照 |
| S+ | 原公开强检索＋固定Top-2＋共同仓库事实 | 既有强方法对照 |
| R+ | 训练后repo-aware排序＋集合选择，始终调用 | 隔离新路由内容的作用 |
| H+ | 前置gate选择N+/F+/R+，真实在线执行 | 检验条件调用是否值得 |

“+”表示所有Agent均获得**同一份有来源的静态事实摘要**。S+的检索保持request-only，Agent拥有相同事实；另在消融中比较context-untrained检索。R的优势不能仅靠不给基线提供相同信息。

产品原生N-不加摘要的成本与结果可以单独报告，用于判断整个新增组件的净收益，不能用N-替代主算法归因对照N+。

H的gate使用同一事实摘要的便宜统计，不能看到其他臂运行结果。

### 19.2 固定执行协议

- 相同任务起点、许可工具、网络与文件策略、执行器模型/effort、超时、目标/回归范围；
- 相同技能目录、正文与资源，仅选择方式不同；
- 明确并发数、运行顺序随机化/平衡与重复数；确认预算尽量按最贵臂预留完整运行能力；
- 当前客户端内置技能/服务端模型alias无法完全固定时明示，所有臂使用相同请求参数；
- 不能强迫F读全文却让R自选，或反过来；
- 测试侧不读Agent自述作为答案，不允许候选更改可信判据；
- 所有尝试都入账，超时后的有效产物按预先声明规则检查，同时保留不正常结束状态；
- 只有明确启动前失败才可以按同配置补执行；实际模型启动后的重复是追加观察，不覆盖原结果。

单次smoke可以验证线路；主要确认建议每臂每任务至少计划两次独立运行。若只能一次，报告pilot与宽不确定性，不捏造seed或稳定性。

### 19.3 冻结与防止边看边改

冻结文件包括：模型、gate、context、技能库、policy、任务资格/分区、verifier、F组合、计费/归一化、指标、预算和重复计划。

冻结后不能读取确认结果修特定关键词/阈值，或换题来获得提升。发现真实bug时保留原协议结果；在新的修复版上统一处理受影响范围。重大训练/策略修改后原测试集视为已观察，不继续宣传为未见。

确认完成后不自动搜索更多难题。要扩展研究须先交付当前结论，不能用不断累加数据直到显著的方法。

## 20. 指标、统计与未观察结果

### 20.1 主质量指标

历史任务的完整解决：预先定义的目标测试＋相关受保护回归通过，加载/收集有效。不是全仓库全部行为保证，更不是上游合并。

按仓库和修复族报告pass/fail/unknown/timeout/policy-rejected/未启动。重复先聚合到任务再比较，不把一条任务的20个测试或三个重复当作20/3份独立问题。

H vs N+、F+、S+、R+提供任务级配对胜/负/平与unknown。未知配对不当输赢；同时报告计划总分母、可判定子集和未知的最坏/最好边界，避免只删除困难任务。

### 20.2 辅助质量与机制

- 原始召回能否包含相关技能；reranker是否改善排序；
- 明确约束冲突、错误覆盖、同功能重复；
- 选定/物化/被观察读取的变化；
- 选对仍修错、没用技能仍修对、固定成功R失败、R成功固定失败；
- 由文件政策或验收错误造成的unknown；
- 已验证子用例改善只作诊断，不能改称整题成功。

### 20.3 成本

记录实际：上下文提取、gate、模型初始化、索引、encoder、reranker、集合选择、Agent执行、补丁捕获与验收、完整request wall time。

记录input/cached-input/output/reasoning-subset等真实provider字段。缓存是子集时不重复相加；input-cached的差只有在字段语义确认后才计算。无终止usage为null，不能填0。

美元只有在用户允许读取且能够使用对应版本/套餐的可验证计价时计算，保留价格日期、来源和组成。订阅内用量不等于API按量账单。否则主表使用token/时间/本地模型调用量，不说“省了多少钱”。

完整资源成本不能遗漏本地GPU/RAM、context提取和预计算；未知项明确。worker累加时长不是用户等待时间。

选择器使用正文token预算与最终计费用量分开。展示质量—成本曲线，主运行点在校准阶段固定，不能挑final曲线最好点作为预先策略结果。

### 20.4 不确定性

按修复族的配对bootstrap或合适的成对方法报告区间；样本很小、仓库很少时明确范围，退化全平区间不叫确定无差异。

少数仓库无法支持广泛“跨仓库稳定泛化”。单个未见库的结果称为该库迁移观察。

比较“质量非劣且成本下降”必须有事先定义delta与相应区间，不能用p>0.05表示质量一样。只观察到均值改善而区间宽，写 `GAIN_OBSERVED_NOT_ESTABLISHED` 或自然语言等价表述。

不必强制实现IPS/DR、复杂序贯检验或显著性平台。最优先是有效分母、真实配对和不夸大结论。

## 21. 门控与模型的真实验证，防止“跑通但没用”

以下三类缺一不能声称完整学习系统：

**排序训练有效：**真实预训练权重上的有效优化、保存重载、预测对照，不只是固定分数mock。

**门控确实基于有效数据：**真实N/F/R反馈、无未来特征、独立校准、与常量策略比较。模型退化/全回退要公开，不用synthetic win labels伪造可分性。

**端到端已连接：**新模型/门控版本实际影响推荐、完整技能包和真实Agent调用；至少有冻结H的真实启动与patch记录。

R分支若被gate合理地从未选中，可以用显式R smoke验证线路，但它不加入H收益分母。不能为了显示R调用率而降低阈值覆盖测试。

模型“被正确加载”与“对Agent有帮助”分开。新方法全部失败也不能改成只报离线Recall。

数据标注/资格控制器可能已经看过参考修复；被测Agent必须使用独立上下文，不能继承控制器会话、摘要、记忆或子Agent工作记录。来源角色不同不等于统计独立，只有明确隔离与冻结能支持有限的无泄漏表述。

## 22. 资源编排与工作量控制

### 22.1 开始时估计完整工作量

先用已有记录和少量开发启动估计：平均请求时间、输入/输出用量、训练显存、索引时间、测试环境成本。

建议在资源计划中计算：

```text
排序执行标签开销 ≈ 排序开发任务 × 比较集合数 × 重复数
门控拟合/校准开销 ≈ 对应任务 × 3个动作 × 重复数
主确认开销 ≈ final任务 × 5个条件 × 重复数
产品smoke单列，不混入确认
```

例如门控18题、确认12题、每格2次，仅后两部分即108+120=228次任务执行，还不含排序标签采集。该算例只是工作量估算，**不是承诺228次足够证明泛化，也不是执行配额**。

完整研究不是原来几十分钟的两次smoke。不要因Goal运行时间长就谎称完成，也不要为了快结束直接退回12道短JSON题。

### 22.2 优先节约而不破坏比较

离线评分/小型标签质检先筛选实现错误，昂贵Agent仅用于必要数据和确认。索引/模型可持久缓存，但查询处理和初始化归属真实记录。

先完成ranker，再freeze R采集gate；避免R不停变动导致gate数据全部重跑。核心实验串联，独立工程任务可并行。

重模型训练与Agent执行竞争同一设备时排程，记录测量条件；不得因新方法运行在空闲机器、基线运行在拥堵时段制造性能差异。

### 22.3 预算不足与继续执行

在尚未启动的确认之前，可以按现有资源缩小预定任务数并记录研究级别；不能基于已观察胜负删掉任务/条件。保留主比较的完整性，宁可少一些独立任务也不偷偷移除R+或F+让H显得有利。

如果不可用的是真实API/设备/数据权限，交付明确恢复入口。一个合同可以继续执行，不需用户重发各阶段Goal，但不能假装在本工具调用之外后台长期运行。

| 阶段 | 操作 | 必须产物 | 自动推进条件 |
|---|---|---|---|
| M0 | 起点/分支/资源盘点 | 运行基点、资源计划、保护范围 | 合法环境与复用路径明确 |

| M4 | 集合选择与开发消融 | 同K对照、预算策略、R版本 | 优化正确，实例可解释 |
| M5 | 固定R采集N/F/R，拟合gate | 真实反馈、gate模型、校准报告 | feature-time隔离、预算点冻结 |

这是一个Goal的内部里程碑，不是让用户按M0…M8逐次授权。普通修复不退回“待批准”，但大幅改变研究问题需要明确报告，不自行把目标替换成另一个平台。

每一阶段尽量交付代码/数据/真实结果，不扩展文档仪式。一个review-index、一个结果入口和一份模型/数据说明足够组织工作。

## 24. 必需测试与边界用例

### 24.1 上下文与数据

- dirty源码快照正确，未把HEAD旧内容代替当前；
- 配置改变触发缓存失效；同输入稳定输出；
- 包/CLI来源与facts能够对应；不执行不可信setup.py；
- target/reference/未来提交不出现在在线特征与训练query；
- 修复族/衍生对/重复运行不跨分区；
- 同功能多个正例不被误设负例，unknown不填0。

### 24.2 模型与选择

- tokenizer、模板、mask、分数位置与真实推理一致；
- pairwise loss独立算例、梯度、优化器、重载；
- “不去重”与“去重”、“生成”与“验证”、网络禁止与在线依赖等反例；
- 相同分数稳定tie-break、空候选、全冲突、证据缺失、模型缺失；
- 小池穷举与优化实现一致；预算不超限；不能把字符串顺序当优化分数；
- 非单调/负增益例中允许停止或回退，不盲目塞满K。

### 24.3 Gate

- N/F分支没有重模型构造/forward；缺重模型仍可fallback；
- gate输入不含后置特征，归一化仅来自fit；
- R版本改变后旧gate兼容性被拒绝或明确降级；
- 单类别/无差异数据不崩溃、不输出伪校准高置信；
- 缺成本/usage、模型失败、unsupported仓库时有清楚语义；
- 多运行/共享缓存的计时不重复计算或省略。

### 24.4 Runtime与旧版本兼容

- 原生/固定/强/replay/assist旧入口不被破坏；
- 新auto不会绕过历史qualification、文件策略、可信检查或源工作区保护；
- selected→mounted完整包对应；缺资源不静默删包；
- patch新增/修改/删除正确，Agent自行commit不丢patch；
- 原history/UNKNOWN/负结果内容不变；records-only可重算；
- 当前测试不污染冻结目录；源码/数据敏感信息不入Git。

轻量fixture与mock用于测试异常路径可以，但不能作为真实模型训练/任务收益证据。

## 26. 验收层级：完整系统不等于“最强效果”

```text
publication: PUSHED_DRAFT_PR | PENDING
```

### 完整技术交付必须具有

- 仓库事实提取与真实同信息量对照；
- 真实排序模型训练、重载与测试，不是规则冒名；
- 能改变/保留实际集合的预算优化与回退；
- 由真实动作反馈拟合的前置gate，或明确数据不足导致的退化；退化不能称“学会了自适应”；
- 真实R/H到补丁的闭环；
- 冻结后的主比较及至少一个未见仓库的有限检验；
- 全部当前必要CI通过、旧事实不被改写、正确GitHub交付。

若核心训练没有执行、只有单库旧数据、没有独立校准或没有真实H测试，不能将整轮描述为已验证的完整“最强版本”。保留已实现模块，明确剩余阻塞，而不是下调标准。

### 提升不作为强制完成条件

实现和评测完整但没有收益，可以结束并继续native默认。若R好而gate无效，只支持R的特定观察；若gate只节省重模型调用却增加总时延，不宣称整体更高效。

若有收益，仍需与F、N、R比较并给出适用范围。不能把“首次观察到”说成稳定工业上线、论文创新、SOTA或上游采用。

未经新的明确授权，不自动默认晋升、合并或发布。完成后停止，交出数据和决定，不再自动启动RL或第四个算法层。
