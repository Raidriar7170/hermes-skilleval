## 0. 本轮最终应当交付什么

交付一个明确命名、默认不晋升的新 R 配置，完成：

```text
公开请求 + 修复前/当前源码
    → 有界读取相关大文件，提取可追溯事实
```

## 5. M1：有界读取关键大文件，而不是无限增大 max_file_bytes

### 5.1 两层读取

第一层为便宜定位：目录、配置入口、请求中显式路径/符号、已有源文件结构。按确定性顺序定位候选，不执行 setup.py、不导入目标包、不读取 Git 后续历史。

第二层对相关源文件做**有界扫描和片段提取**：

- 大文件允许按行/块流式扫描，扫描字节、耗时、命中数和输出字节都计入独立预算。
- 优先提取与请求符号、入口和相邻接口相关的声明、函数片段与必要上下文；不能总取文件前128KiB。
- 在明确的解析预算内可用AST；对更大的文件先定位窗口。窗口不能独立解析时，作为原文片段，不伪造AST关系。
- 输入若被硬上限截断，明确记录未扫描区间。预算是保护边界，不保证找到文件末尾所有符号。
- 保留否定、条件、版本限定与函数签名，不能只摘一行让原义改变。

新增预算须区分：枚举项、实际扫描总字节、单文件扫描字节、解析字节、输出片段数量、输出token。给出基于实际文件的有限默认值；不要以一个 `max_file_bytes` 同时承担所有职责。

### 5.2 缺失不再简单等同全局失败

建议表达如下语义，名称可与现有结构协调：

| 状态 | 含义 | 路由处理 |
|---|---|---|
| usable | 关键请求事实有可追溯依据，仍可能有非关键遗漏 | 可继续实验性 R |
| partial | 有部分事实，但关键覆盖不确定 | 不将未知当反证；按冻结策略回退或限用已知事实 |
| unavailable | 请求明确需要的关键路径/符号无法取得，或安全/格式不支持 | 清楚回退并记录原因 |

不能把所有 missing 删除、把 supported 永久设True或将partial叫完整。关键性必须由公开请求、入口依赖和实际定位关系推导，不读正确补丁猜“关键文件”。

模型输入、路由记录和报告都保留该状态与依据。Context v1 与新语义有版本隔离，不能静默改变旧Gate特征含义。

### 5.3 缓存与来源

每个片段记录相对路径、行号/字节范围、原文及来源身份。命中窗口确实对应输入源码；不存在的行号、全文未读却声称全文hash验证均不可接受。

缓存身份覆盖请求、预算、源码快照及提取版本；预算外区域变化的不可观测性如实披露。无法可靠检测相关变化时宁可重提取，不使用不可信缓存。

源仓库并发修改要报告，不自动恢复。敏感文件、符号链接、历史参考目录和隐藏测试仍排除。

## 6. 必须检查“最后送进模型的token”，不只检查摘要JSON

沿真实 `representation → inputs → model.forward` 路径记录：任务、上下文、技能元数据、证据、指令与模板的token预算及截断。

重点检查：

- 支持判断的新指令是否真正保留到token化结果，而不是写在字符串前缀后被四段重组丢弃。
- 结构分隔符由程序生成；用户请求中出现同名 `[TASK]` 等文本时不应破坏解析。优先传结构化sections，而非反复对自由文本split。
- 已读取的关键函数不能再被摘要固定前缀截断丢弃；展示“源片段 → 摘要 → 模型可见片段”的映射。
- 空闲段预算可以按冻结规则借给仍被截断的必要段，不让关键上下文被切掉而总输入尚有大量空位。
- 请求的否定和限制被截断时必须记录；不能用残缺请求作出已支持结论。
- 文本支持所引用的决定性证据必须在此次scorer实际可见输入中。标签作者读过全文，不代表模型也看到了全文。

同一输入协议用于拟合、校准和运行时。改模板、token预算、模型、adapter或证据表示时，旧校准器不得继续无条件复用。

## 7. M2：先定义“支持”，避免再次训练错问题

本轮支持目标是：

> **在已知运行约束下，这份技能原文是否提供了对某项公开需求具体适用的操作、检查或实施指导？**

它不是“技能单独能完成整个issue”，也不是“最终补丁成功的概率”。通用工作流可以提供有效指导，但只有“认真调试”“认真验证”这样的空泛表述，不能被当成对每条需求都有特定帮助。

使用下面的标注语义：

| 标签 | 判据 | 对数值学习的处理 |
|---|---|---|
| SUPPORTED | 有原文片段，能说明具体帮助；无已知必要条件冲突 | 文本支持正例 |
| NOT_APPLICABLE | 已读信息明确指向另一任务/格式/操作，足以判当前不适用 | 文本支持负例 |
| CONTRADICTED | 原文建议与需求/环境有明确且有作用域的冲突 | 单列冲突，不能只靠低分处理 |
| UNKNOWN | 证据不足、歧义、关键文本不可见、标签审核不一致 | 不能当负例填0训练 |

SUPPORTED另记 `support_role=procedure|implementation|verification`，用于解释，不默认给不同role发明不同成功率。

每个标签至少有：任务/修复族、原请求片段、技能身份、原文片段、适用步骤、约束状态、标签来源、未确定因素。能替代的多个技能都可为正例；不是gold ID的技能不自动是负例。

举例只作为标注规则：

- “项目同时有API与CLI，要求两入口一致”与明确检查两入口行为的技能，可具有verification支持。
- “输出report”与不相关的漏洞报告技能，不因共有report一词得到支持。
- “保留重复记录”与“去重”需要检查各自作用域，不能因相同单词计正分，也不能忽略原文中的do not。

## 8. 支持标签如何获得，而不再要求用户逐条授权

优先使用公开请求、修复前源码事实、技能原文和明确约束。允许在已有授权范围内用模型辅助标注，但必须标 `model_judged_text`。

标注器不能看运行时排序/支持分数、选择结果、候选补丁、隐藏测试结果或最终臂胜负。标签冻结早于它们所评估的支持分数和执行结果。

用程序验证引文存在与来源；对SUPPORTED/CONTRADICTED等关键标签执行一个独立上下文的复核过程。不同判断不一致时先保留UNKNOWN，不让同一scorer自证正确。

独立上下文复核、模型一致和引文存在，不等于人工标签或事实真值。最终报告必须披露标注来源、分歧数和无法判定数。无需等待人工逐题验收，但不能冒称人审数据。

禁止将旧pairwise中的preferred直接改成1、less-preferred直接改成0。相对更好和绝对适用是不同任务。

合成的否定翻转、打乱证据、假候选仅用于反例/健壮性测试，单列来源，不代替自然任务标签或增加独立修复族分母。

## 9. 数据划分与规模：先做足支持层，不先花钱跑大矩阵

所有已读过的20个原修复族，包括旧final四题，都视为本轮已观察开发材料。旧文件原分区仍不修改，在新manifest里记 `previously_observed=true`。

按修复族而不是按需求—技能行划分：

| 分区 | 用途 | 初始规划参考 |
|---|---|---|
| support-fit | 选择支持输入；必要时内部折叠训练支持模型/小头 | 8–12族 |
| support-cal | 冻结scorer后拟合校准映射与选择阈值；不用于调表示/网络 | 4–6族 |
| support-check | 冻结后诊断支持精度、覆盖、冲突与实际选择 | 4–6族 |

这些不是固定配额，也不是“数量达到即有效”。先复用已有合法资产；缺少互不重叠的族时，可从已支持仓库补少量真实开发需求，不扩第四仓库、不造短JSON题凑数。

关键规则：

1. 原pairwise adapter训练过的8个修复族，不能作为该adapter的独立校准/检查；它们可留在fit。
2. 同一issue、同一修复机制变体、请求改写、同补丁关联PR必须同组。原来的族划分若过细，修订仅作用于本轮manifest并解释。
3. 一个任务的5个技能、多条需求和多次推理不是多个独立任务；每族总权重不因行多而增加。
4. 旧已观察任务即使按组留出，也只能说本轮拟合留出/开发检查，不能说未见仓库或严格盲测。
5. 新增族若被用于挑模型、改标签规则、改阈值，就转开发，不再作为独立确认。
6. 每族按统一规则覆盖候选，而不是只标最容易成为正例的技能。报告各类标签、未知、skill ID分布和族数。
7. 确认任务的补丁测试只给可信验证侧；路由层不能从reference路径、时间戳或task ID获取答案。

可在现有五技能池完成主修正。它只支持小目录的机制结论，不代表大规模技能发现研究。

## 10. M3：把 rank_score 与 support_score 真正分开

### 10.1 排序通道

冻结现有encoder、pairwise ranker adapter和相应模型身份。`rank_score`只用于同请求内的相关性排序，不直接进入绝对支持阈值。

若集合目标需要0–1的relevance，优先用冻结的秩变换，例如候选数n>1时 `1-rank/(n-1)`；n=1单独定义。它是排序代理，不叫成功概率。

这个变换使共同平移rank logits不改变其排序贡献。它是对旧选择目标中的分数使用方式的显式修正，需单独说明，不隐瞒为纯工程重构。

### 10.2 支持通道

明确实现 `score_support(requirement, context, skill_evidence)`，有自己的目标描述、版本、输入模板、模型身份和输出字段。

可以共享同一个冻结底座来省内存，但必须用针对支持任务的输入和独立校准；不能仅把原排序输出重命名为support。支持通道的标签目标始终是第7节的文本帮助。

建议首选最小路径：保留现有底座/adapter作为固定scorer，使用支持专用输入产生原始 `z`，然后依据绝对支持标签拟合含截距的轻量映射。

例如：

\[
 p_{text}(y=1\mid z)=\sigma(a z+b).
\]

这里是需要拟合并验证的映射，不是先验真理；a、b、模型/模板与数据身份一同保存。不能声称sigmoid天然等于已校准概率。[E1]

排序logit共同平移的单元测试，只能要求“排序通道与独立支持通道的连接不被污染”。改变support scorer本身的数值尺度会使其校准失效，不能要求使用旧校准器仍然数值不变。

## 11. 校准与必要的局部训练：有判据地推进，不盲目增加epoch

### 11.1 冻结scorer的首选路径

在support-fit内部按族分折，检查支持专用输入的正负分布、排序可分性、negation反例和证据可见性。确定输入协议后再处理外层support-cal。

最终校准映射在support-cal拟合，support-check只做冻结后检查。support-fit用于输入设计或支持scorer训练；不得因为底座这次没有更新，就把它过去训练过的任务当作独立校准数据。

校准映射与阈值选择可在support-cal内部按族交叉拟合：用折外预测选择暂定阈值，再用全部support-cal拟合最终映射并冻结。样本足够时也可按族拆成映射拟合与阈值选择两部分。采用哪种方式事先固定；数据太少时标暂定/不足，不能以行数很多掩盖只有一两个任务族。外层support-check保持不参与选择。

映射是监督拟合：使用绝对标签的加权二元交叉熵或等价的正则化logistic目标。未知不参与二元拟合，族权重受控；如过采样类别，校准和报告必须恢复自然抽样权重。

先用低自由度、有截距的sigmoid映射，不默认小样本isotonic、高自由度MLP或复杂不确定性模型。校准数据与训练过scorer的任务族必须分开。[E1]

### 11.2 何时允许额外pointwise支持训练

若fit内部的样本外诊断确认raw支持分数缺乏区分性，且已有足够、可复核的自然正负标签，则允许基于**同一公开底座**训练一个独立支持adapter/小头。

- 目标是绝对文本支持，不再用纯pairwise分差代替。
- 旧rank adapter不变；新support adapter另存，明确调用哪个权重。
- 先固定输入协议与标签；超参数只在fit内部选择。不能看完support-check再训练。
- scorer训练、校准拟合、最终检查的数据角色分清；可采用fit内部按族交叉拟合，不能用自身训练预测作独立校准成绩。
- 记录真实梯度、参数变化、权重保存、独立重载分数及准确训练耗时。真实拟合器只保存JSON时，也需独立重载与预测一致性检查。
- 数据仍不足时不伪造标签、不用epoch数量替代任务量；允许明确DATA_SIGNAL_INSUFFICIENT。

这是本轮唯一允许的额外训练，不是重开Ranker V3或门控训练。若简单校准已足够，不为了简历出现LoRA再强行训练一次。

### 11.3 阈值的选择方式

先在协议中给出可解释的目标：控制错误支持，同时保留有原文依据的适用技能。支持阈值不能根据补丁成功率、非空比例或“H终于选了R”来调。

在support-cal上导出阈值—支持精度—召回—接受量曲线。选择规则和并列处理固定；例如在预先写明的开发精度目标下选择覆盖更高的阈值。具体目标在看support-cal得分之前写入配置。

同时报告正例接受来自多少修复族、多少技能；1/1精度不能包装成可靠90%或95%保证。小数据下可称“开发阈值/暂定校准”，必须保留区间与标签质量限制。

若没有满足规则且具有正例覆盖的阈值，返回 `NO_VALID_OPERATING_POINT`。不得为了进入执行阶段偷偷改目标。可以完成rank-only能力，但支持分支须标未验证，不默认使用。

不能把旧0.8直接改成0.05；也不能把某个阈值的全部拒绝自动视为校准良好。

## 12. 支持层的检查不只报准确率

至少输出：

| 指标 | 解释 |
|---|---|
| Precision/recall of accepted SUPPORTED | 对冻结标签的判断质量，带正例与族分母 |
| 正负类别分布与常量基线 | 排除“全拒绝”看起来准确的假象 |
| UNKNOWN率与accepted-UNKNOWN数 | 未标注/不明确样本不能被隐式变成已知真值 |
| 冲突接受数 | 先检查来源和作用域，不将模板词面翻转当唯一判据 |
| Brier/log-loss与分箱预测/标签比例 | 仅对有标签集合描述；不单靠一个分数认证概率可信 |
| 每族、每技能结果 | 暴露小样本与目录偏置 |
| token可见证据率 | 接受结论是否确由模型可见原文支持 |
| 单条/批处理、冷/暖成本 | 新支持推理和校准不是免费 |

对support-check里预测接受但标签UNKNOWN的样本，可以做冻结后的盲态复核并单列；不能据此回改标签后只报更新过的有利成绩。

报告 `p_text` 的含义和局限：它最多是对当前标注任务的支持估计，**不是P(代码修复成功)、P(技能充分)、因果增益或跨仓库可靠度**。

## 13. M4：同 K 选择，先隔离支持判断的贡献

主开发比较仅保留三个条件：

| 条件 | 行为 |
|---|---|
| N+ | 原生渐进选择；获得与其他臂相同的公开上下文 |
| B2 | 冻结ranker + 新上下文，相关性Top-2；无绝对支持过滤 |
| C2 | 同一ranker、同一候选池与上下文；经新支持判断后选择恰好2个技能 |

B2不是原研究的S，不使用S的名字冒充同一条件。它的作用是控制底座、adapter、上下文与候选，单独检查支持/集合选择是否值得。

保留原始S或old-R作离线诊断即可，不自动增加为第四、第五个昂贵执行臂。原未训练+context表现较好的现象可作开发参考，但本轮不同时换ranker以求收益。

C2复用已有精确小池枚举，只作必要的语义修正：

- relevance来自冻结的秩代理；coverage来自受校准支持字段，两者不混用。
- UNKNOWN不计确定覆盖；CONTRADICTED按有依据的硬约束处理。
- 每个技能提供某项具体帮助即可成为候选，不要求单独覆盖整条issue。
- 五份技能的正文/资源不同，不强迫出现去冗余收益；保留明确等价判据，不靠余弦高就删除。
- K=2、候选上限、预算与目标系数在开发执行前固定，不逐题修改。
- 若不足两个合法受支持技能，保留有依据的回退。不能填一个无依据技能凑K，也不能把单技能运行叫同K。

**回退仍计入全部预定任务结果。**C2回退原生时实际暴露可能是全目录，不受两技能集合预算约束；报告actual count和fallback，不把它算成严格同K因果样本。另报实际两技能子集只能辅助解释，不能删掉回退任务后重算主胜率。

变量K的已有路径可保留作为显式实验入口；本轮无需重新优化它。开发结论不能从同K直接推广到任意预算和技能数量。

## 14. 非空选择的验证标准：不是“返回两个ID”

对于每个真正走C2的实例，能回答：

1. 哪项公开需求得到了怎样的帮助，依据是哪个技能原文片段？
2. 相比B2是换了集合、只换了顺序，还是完全相同？
3. 实际物化的是不是相同版本的完整包？排序如果不影响加载，就不解释为排序干预。
4. 有记录时Agent是否读取相关材料？挂载不等于读取；没有读观测就标未知。
5. 补丁行为、可信检查和成本是否改变？改变是否可能只是Agent随机波动？

强制的集成验收是：在**事先按输入/环境资格选择的开发任务**中出现有依据的真实非空R分支，且该路径实际完成模型评分、完整包物化和Agent调用。优先覆盖不止一个修复族，不依靠仅手造张量测试。

不能事后不断挑题直到满足这一点。若预定开发任务仍全部正确拒绝，则说明当前数据/技能场景不支持有效激活；保留这一诊断，标支持分支未完成有效验证，而非放宽阈值伪装完成。

真实补丁质量改善不是软件完成条件。一个实际C2任务失败也必须保留：它能验证执行路径，但不能证明方法有效。

## 15. 开发执行规模与公平性

在看本轮模型/任务结果前，按实际资源从support-check任务选定约4–6个合格修复族，尽量跨现有两个可用仓库。资格依据为可安装、需求明确、可信目标和相关回归，不是预计C2能赢。

建议N+/B2/C2每格2次独立执行，约24–36次；这是资源规划示例，不是重试配额。资源不足可在执行前减为每格1次并标smoke级别；执行后不得因结果不理想增加某一臂重复次数。

控制同一任务的源码、请求、环境、技能全集、Agent模型/effort/权限和时间预算；轮转或随机化臂顺序，避免把服务时段全部绑定到某种方法。

所有臂获得同一份source-grounded事实摘要。用于支持选择的额外模型分析不要当公共事实偷偷塞入C2的Agent prompt；确需额外提示则单列处理因素。

每格独立源码快照和上下文；不得传入其他臂补丁/最终输出。参考修复与隐藏测试仅在可信侧。旧确认记录不能直接并入本轮胜率。

这是一轮开发机制验证。新的跨仓库确认、Gate数据采集和产品默认晋升需要后续单独决定，不由本轮自动展开。

## 16. 局部处理执行混淆，不重建验证平台

复用现有候选补丁导出、操作级文件策略、独立重建与加载来源校验。旧临时路径UNKNOWN不回写。

对本轮任务，在启动前披露允许的源码/测试/fixture目录和临时调试目录。临时产物应放进隔离的明确scratch位置，而不是任务源码树。

不要以“它是临时文件”为名，事后静默删掉候选patch的一部分来过验证。如果非法路径出现在已捕获完整patch，保留patch与原因；任何事后敏感性重验另列。

支持层未知、上下文缺失、策略拒绝、重建失败和功能失败分别记账。Unknown不填0，不删去；阈值/校准不得读这些最终质量字段。

## 17. 新 R 与旧 Gate：禁止修改hash来假装兼容

本轮改变context、support、representation或selector语义，会产生新的R版本。旧Gate来自旧R反馈，不再是新R的有效门控模型。

必须做到：

- 新功能通过显式实验policy/config启用，维持native默认。
- 新R身份必须包含context/输入版本、rank与support模型身份、校准器系数/阈值、证据策略和选择配置。不能只绑定原rank adapter而漏掉本轮决定性变化。
- 旧Gate/model/freeze记录字节不改；不得只把其r_version字段换成新hash。
- `auto`遇到新旧R不一致时清楚回退，报告版本不匹配/待新反馈，不称新Gate通过验证。
- N/F与旧兼容路径不加载重模型；测试用真实调用计数与无重依赖环境确认。
- 同时保留requested policy与realized action。成本计数包含先执行支持评分后再回退的所有工作。
- 旧公开记录可离线重算，使用冻结来源，不让新版源hash导致历史结果被“重新生产”。

本轮可以形成一页“下一次Gate采集的条件”，但不能自动执行。先证明R值得研究，再花预算学习什么时候调用它。

## 18. 必须有的关键回归与反例

不要求固定测试数量；测试覆盖实际风险，不靠重复assert凑数。

| 类型 | 核心用例 |
|---|---|
| 分数语义 | rank logits共同平移不改变排序/ordinal relevance；不能影响独立support值 |
| 分数来源 | 禁止将rank字段直接作为support概率；scorer/模板/adapter变化使旧校准失效 |
| 标签边界 | UNKNOWN不参与二元负例拟合；preferred不自动为SUPPORTED；重复族不跨分区 |
| 校准 | 有截距映射真实拟合/重载；仅单类/没有可用阈值时不伪造校准成功 |
| 证据可见性 | 引用不存在/被截断的关键证据不能认证SUPPORTED；分隔符文本不破坏段结构 |
| 大文件 | 预算内能找到文件中后部相关函数；超过硬预算如实partial；不执行目标源码 |
| 缺失分级 | 非关键文件被跳过不必全局失败；明确关键输入缺失不能伪装usable |
| 约束 | 保留/去重、只读/覆盖、可选/必需网络、否定和作用域反例 |
| 选择 | 支持候选能进入非空集合；全UNKNOWN/明确冲突仍可拒绝；同K不足记录回退 |
| 精确优化 | 小候选枚举与独立暴力参照一致，只证明代理目标最优 |
| 路径 | 新配置真的进入support新实现；旧配置/历史记录不被重解释 |
| 版本 | 新R不能误用旧Gate；原生便宜分支重模型构造与forward为0 |
| 可信执行 | 新增文件、Agent提交、已有用户修改的patch边界；检查空集合不认证成功 |

真实模型测试与mock测试分开。没有权重时可运行软件测试，但不能以mock输出代替校准/真实R分支通过。

## 19. 结果表与成本：重点比较有意义的变化

最终只需要三张主要表：

**表A：输入与支持。** 按族列关键证据读取/可见、标签来源、冻结阈值、support接受/错收/漏收/未知；旧法与新法在相同数据上的变化。

**表B：选择与执行。** N+/B2/C2的requested/realized policy、选中/物化/已观测读取技能、目标与回归结果、回退/未知理由、全部尝试。

**表C：成本。** 上下文扫描/呈现、检索、rank、support、校准预测、选择、Agent、重建/检查的真实时间；实际input/cache/output用量和未知费用。

指标分三层解释：

- 文本标签上的precision/recall不等于Agent成功率。
- 正确的非空集合不等于相比B2更有效。
- 重模型调用减少不等于总耗时/费用下降；先评分再回退不能把评分成本归零。

重复按修复族汇总，不当作独立任务。若所有方法同分，可描述，没有统计差异不等于非劣/等价。小样本区间退化时解释原因，不展示虚假的确定性。

输入+输出token如作总量须标口径，缓存输入是输入子集，推理输出不是默认额外叠加。美元不可测则null，不拿字符数代替真实账单。
