## 0. 唯一问题、唯一主比较

**在配置正确、拥有同一套历史经验的原生 Codex 上，额外提供简单检索得到的候选技能路径，是否改善实际修复，或者暴露出一个具体、值得继续研究的发现／适用性／成本问题？**

主比较只有：

```text
NATIVE：正常原生 Codex + 完整冻结经验库，自行选择或不使用
ASSIST：完全相同条件 + 一次便宜的 Embedding/MMR 候选提示

相同任务、相同修复前 base、相同执行模型和可读资产
    → 各自独立新会话，正常完成修复
    → 完整原补丁在干净 base 上重建
    → 统一目标行为与保护回归验收
    → 功能结果 + 经验使用证据 + 完整在线成本
    → 只决定一个下一步问题，或者暂不开发额外 Router
```

本轮不是训练算法的 Goal，而是判断是否存在算法需求的有限实证步骤。**实现、配置、技能读取次数或 CI 通过均不能替代 16 格真实运行与验收。**全部持平、原生更好、没有技能读取，都允许作为完成后的结果。

## 4. 先恢复公平的原生能力，不改变任务难度

继承第一阶段实际可用客户端及模型作为首选：记录是 `0.155.0-alpha.16.4 / gpt-6-sol / high`，但启动前必须核对本机真实版本和可调用性。[S2]

服务不可用时，只在正式采样前选定另一套可用、适合正常修复的官方配置，记录理由并对两臂统一冻结。不得为制造差距换弱模型，不将新旧配置分数合并。

原生运行不得包含旧四工具分段、中间研究 JSON 输出或反复宿主提示。保留 base 的项目说明、正常工具和原有技能，不让实验工作目录继承 Hermes 开发 Goal。官方事件输出与强迫模型返回研究 JSON 是不同的事情。[O1, O3]

### 4.1 修复系统技能正文访问

先读取实际 `skills/list` 或等价发现结果，逐项核对名称、描述、正文路径及所需引用／脚本资源。不能只证明用户技能可读。

在仍受保护的状态目录中，仅暴露版本对应的系统技能资产。若该版本支持子路径精确只读例外，使用它；否则采用受支持的独立只读资产挂载／发现方式。**不通过放开整个 `/state`、复制认证状态到可读目录或权限绕过解决问题。**

修复后用与正式任务相同的工具权限验证：从实际列举路径能读取正文及必要资源；凭据位置仍被拒绝；没有同名重复注册、失效路径或用户真实技能混入。无害 canary 可用于拒读检查，不打印真实凭据。

声明哪些系统技能仅文件读取通过、哪些实际工作流未验证；资源可读不保证依赖外网的工作流在离线场景可用。

### 4.2 两臂能力必须对称

HOME、CODEX_HOME、系统技能、用户经验库、目录、项目说明、工具网络、正常子任务能力、模型和推理档位保持一致。正常子任务若可用不额外禁用；若无法保留，记录共同限制。

工具网页检索／外网为防未来修复泄漏采用共同限制；服务认证通路不与工具互联网访问混为一谈。保留完成任务的预装依赖和公开仓库材料。

**无法恢复可信的系统技能访问时先修此接线。真正不可恢复则报告基线受限，不花完 16 次运行后称为公平原生比较。**这不是允许扩建一套权限系统。

## 5. 记忆固定为 skills-only，不再作为前置阻塞

所有正式会话使用实验状态目录，按本地受支持配置同时禁止自动记忆的使用和生成；保留系统技能、正常项目指令。不要依赖仅清空某个文件夹来假定记忆关闭，核对有效配置。[O2]

这里控制的是跨任务信息，不清除或禁用正常服务端 prompt cache 来制造费用优势。缓存用量如实分列，运行顺序交错。

### 6.1 先锁身份，阻断答案混入

先登记三个互斥角色：

按 issue/PR、base/fix 身份和近重复修复分组。近重复检查可在隔离可信侧使用 patch，只向选题／提取侧返回排除理由；不暴露目标解法。文本相似度只是筛查线索，不能冒称证明无泄漏。

本轮默认是**静态、跨问题迁移的小型试验**。不承诺严格按时间先后回放；源修复时间未知时单列。不同版本经验是可能的迁移风险，不隐瞒，更不以 issue 创建日期代替经验可获得时间。

### 6.2 有限的数据扩展

先用已有30个源问题。确需补充某仓库经验时，允许按元数据固定顺序增加最多30个独立源问题，总详细源问题不超过60，每题最多2条轨迹。新增依据只限仓库覆盖、来源可用和独立问题，不依据正式题答案、运行胜负或“能救回HTTPX”的需求。

原作者 resolved、局部测试、退出错误、未完成分别保留；不同 patch 不等于不同机制或干预增益。历史轨迹只读取公开动作、观察与合法结果，不运行其中的任意历史命令，不使用私有推理作为训练材料。

按需投影／分块读取并记录实际网络量；429退避、断点恢复属于工程修复。不为了少数样本下载全库镜像或全部模型。

## 7. 经验库：目标12条，按来源覆盖，不按测试答案拼凑

默认目标 **12条**，两仓库各约6条；有充分独立来源且在提取前登记时可扩至最多16条。不是必须达到数量才能执行；不足时以真实规模运行并限定结论。

每个目标仓库争取至少4条有具体来源的经验，覆盖不同公开维护机制。一个来源问题默认最多贡献一条独立技能；确有多个条目也按一个源机制统计。不要把同一轨迹拆成许多相近技能制造选择难度或数据多样性。

这不是保证每个 pilot_task 都有适用经验。**不得为了目标题特制技能，也不得因为库里没有适用经验就删掉该任务。**研究需要分清内容缺口与选择缺口。

第一阶段四条技能可保留在历史目录；本轮如纳入新库，合并重复来源并重新确认事实边界。它们不能全部作为跨仓库实验库的主体。

### 7.1 固定经验模板

```yaml
name: 独立、稳定且可被原生发现的名称
description: 简短说明工作类型、主要适用前提和必要边界
source_issue_ids: [仅经验来源]
source_trajectory_ids: [实际记录]
source_revisions: [固定版本]
source_outcome: 作者最终标签与局部观察分开
scope: 适用仓库/版本/机制，以及尚不确定的迁移范围
procedure: 2至5项有来源支持的检查或操作
verification: 源案例实际做过的验证，不捏造全套通过
limitations: 失败、未知、版本与反例边界
license_and_attribution: 数据及原仓库许可和来源
```

正文以300–600 tokens为写作目标，必要原文放references；不能截掉否定、条件或限定来凑长度。库内原文与references对两臂完全可读。

来自失败轨迹的局部经验可以保留，但标明其证据不足；不得改写成“验证成功的修复技巧”。原始成功也不证明其中所有操作都必要。没有具体内容时不生成“认真检查、运行测试”的凑数条目。

本轮使用固定模板与现有模型转换，最多4批初始内容转换；不用新训练或复杂蒸馏器。来源核对和文字修补只纠正事实、命令、许可与描述，不依据正式结果反复优化触发率。所有实际模型调用和重试另外计量。

### 7.2 冻结顺序

**先冻结源身份和目标身份，再由看不到目标解法的上下文构建经验库；冻结完整库和选择方式之后，才允许正式运行。**

内容核对要回答：来源是否支持、适用条件有没有被夸大、命令是否绑定历史版本、是否与别条实质重复。核对方可以是独立模型上下文；必须标明不是人工gold。

这一轮不运行每条技能源任务来“认证技能”，也不生成当前目标题的诊断测试。这会重新扩大成经验验证平台。

## 8. 四个新任务：资格挑选，不挑失败、不挑适用技能

每个仓库先按固定种子 `20260926` 和稳定 instance_id 排序登记3个环境候选，共6个。使用前两个资格通过任务，形成2仓库×2任务。第三个仅是正式采样前的资源备用。

资格基于公开维护问题、合法base、现有安装与作者检查可恢复；不根据预期原生成败、候选提示分数、技能是否必然适用选择。避免同一修复的近重复任务。

可信侧验证：base暴露目标问题，参考修复通过必要目标与保护检查，包导入路径正确；只返回资格结果。参考patch和官方test_patch在被测工作区中不可见。

优先原版作者harness及测试解析器；允许安装、路径和参数化选择器展开等有限接线修复。将原作者标签数和完整JUnit用例数分开。发现需要重新定义大量题意的任务，按冻结前资源资格记不可用，不进入裁判改造项目。

不足四题时保留有限队列结果，不无限找题。已经开始正式采样之后，不因失败、全部成功、无技能读取或ASSIST无优势启用备用题。

四题是本项目未用于该比较的新问题，不保证基础模型从未在预训练中见过；不称公开数据绝对无污染的独立盲测。

## 9. 两臂精确定义：只改变一条候选导航信息

| 项目 | NATIVE | ASSIST |
|---|---|---|
| 原始题面、环境信息 | 相同 | 相同 |
| 原生客户端、模型、推理档位 | 相同 | 相同 |
| 系统技能和目标仓库原有技能 | 正常可用 | 同样可用 |
| 本轮完整12–16技能及references | 全部可用 | 全部可用 |
| 完整技能目录catalog.md | 同一内容、同一逻辑路径 | 同一内容、同一逻辑路径 |
| 自动记忆使用／生成 | 关闭／关闭 | 关闭／关闭 |
| 主动寻找／拒绝经验的自由 | 保留 | 保留 |
| 宿主额外提示 | 无 | 最多3项现有技能名称、原description、路径 |
| 检索／编码准备成本 | 不承担 | 按本次实测计入 |

公共说明只说：历史经验可查阅，但当前需求与实际版本优先；不必为实验使用技能。不要让NATIVE只知道一个模糊文件夹，而ASSIST获得详细解题计划。

NATIVE 与 ASSIST 使用同一用户提示前缀；ASSIST仅在同级文本末尾增加固定格式的导航块。**不要用 `$skill-name`、原生显式技能消息类型或自动展开技能正文的格式。**本轮测候选路径提示，不测宿主强制激活。

候选块示意：

```text
Optional entries in the available experience catalog:
- Name: <original name>
  Description: <verbatim original description>
  Path: <same readable path in both arms>
These entries are optional. Inspect and judge applicability yourself;
you may ignore them or search any other entry in the full catalog.
```

不附相似度分数、额外适用性分析、成功标签、目标测试、自由根因说明或“最佳技能”保证。Top-3不是权限白名单；不得禁止Agent查看其他技能。

没有BASE臂，因此本轮不能单独回答“给这份经验库比不给是否更好”。没有普通等长提醒臂，因此候选提示的局部作用也不能完全分离为领域知识与注意力效应。

## 10. ASSIST实现：固定的便宜检索，不发明新方法

复用已有真实冻结文本编码器和MMR组件，优先已存在MiniLM资源；先确认模型文件及 tokenizer 身份，不使用hashing/mock代替。

索引内容只用每条技能的 `name + description`，不索引目标答案、来源issue ID、resolved标签或隐藏参考patch。原生启动时也能发现这些元数据，正文对两臂按需可读。

查询使用未加候选块的原始任务题面和两臂都可见的仓库名称／语言。查询字段及序列化冻结；不调用LLM生成任务根因，不读取尚未开始的目标执行结果，不加入旧HTTPX失败总结。

一套固定选择规则即可：

\[
q_i=\max(0,\cos(e_{task},e_i)),\quad
score(i|S)=0.7q_i-0.3\max_{j\in S}\max(0,\cos(e_i,e_j)).
\]

按分数依次选至多3条；分数不为正则停止；平分用稳定技能ID排序。全部库项都可被检索，不设置隐藏的“正确仓库技能白名单”。长输入使用已有完整分块编码方式，或开发时明确固定截断范围；不要静默遗漏尾部条件。

skill元数据向量的离线构建可复用且单列。每格ASSIST的查询编码、必要模型初始化、候选选择和渲染在线计费。可以实际共享只读向量缓存，但不能把查询结果或测试会话记忆跨格共享。

此方案名为 `ASSIST_METADATA_MMR`，不是旧PR55关系查询R，也不声称本轮提出新的神经排序算法。若现有编码器缺失，先恢复既有合法资源；不可恢复则明确方法不可执行，不能结果出来后改为另一个检索器并混算。

## 11. 两次无害预演，然后直接进入正式任务

不重跑第一阶段的两个修复问题。开发使用不含正式答案的fixture：

1. 实际原生入口发现并读取系统技能／实验用户技能资源，验证正确路径、公开事件与隔离；不以隐式必须触发为验收。
2. ASSIST导航块不自动展开正文、完整目录仍可读、候选可被拒绝；计时覆盖从父进程入口到结束。

默认2次非修复会话，每次最多180秒；配置失败后的针对性复测保留旧记录和变化原因，不能重抽直到触发后只报成功。

另用构造输入、延迟注入或空工作进程做计时单元测试，不调用真实目标修复来“测试会不会漏计”。修好即继续本Goal，不另开新探查版本。

## 12. 计时边界必须从父监督器最外层建立

这是第二个必须在正式运行前修好的已知问题。第一阶段 `run_smokes.py` 在进入运行函数之前已经读任务、投影字段并算冻结哈希；那些旧成本没有测量，不能补造。[S2, S4]

新入口从拿到最小attempt描述符后、读取单题数据或创建用户状态之前立即记录单调时钟 `t0`。**父监督器先建计时，再派发worker；不能在已完成准备后才进入计时装饰器。**

计入本次在线：任务JSON读取与投影、逐格绑定检查、源树／用户状态复制、原生技能准备、ASSIST必要查询编码、客户端初始化、模型与工具服务等待、全部生成和工具执行、最后输出、进程停止与原候选捕获。

以下是一次性离线／可信侧成本，单列不混入：数据下载、经验提取、镜像拉取构建、训练来源核对、离线skill向量构建、环境资格、最后的可信候选重建和独立验收、公开报告导出。两臂使用镜像已就绪场景；不追补第一阶段冷启动账单。

默认每格总预算900秒。子步骤只接收**同一个绝对截止时间或由它计算的剩余时间**，不得再次获得900秒。预留15秒结束和捕获空间；实际结束开销超出则如实记录，不将时间裁剪成合格。

在所有异常路径的finally保存 `t0/t1/elapsed`、实际开始的模型/工具状态与预算合法性。阶段时间用于解释，总时间由最外层决定，避免漏掉阶段后整个成本变未知。相关计时属于同一进程时钟；重启后不能把不同boot的单调时钟直接相减。

token至少分输入、缓存输入、输出及供应方可提供的总量，缓存输入是子集，不重复相加。日志逐次快照若为累计值不能再次求和。金额无账单留空；编排、技能生成、CI token不算被测Agent在线用量。

## 14. 16次真实修复：独立新会话，不是同前缀分叉

每个task使用相同base与原始problem statement，NATIVE和ASSIST各从独立新会话开始。技能元数据从启动就参与上下文，因此不能称为共享可观察前缀，更不能声称控制了隐藏随机状态。

按固定种子在每个任务、重复块内交错两臂；不要让某臂永远先运行。两次重复共享任务但不共享修复历史、技能写入、workspace或scratch。对已缓存静态资产的实际复用如实记录。

只用共同任务说明及ASSIST规定的导航差别。不得把Goal、源轨迹标签、正确技能ID、隐藏检查内容发给修复Agent。

正常一条原生任务跑到结束或截止，不每四个工具停顿，不中途提醒“你还没看技能”。原生可以自行再次查看或不查看经验；宿主不追加第二轮候选。

一个方法辅助检索失败不阻断另一方法：ASSIST在可用时回退为同库原生，保留错误、开销、实际导航及分母；绝不把回退成功写成候选导航成功。

有效尝试开始后不额外抽一份覆盖失败；可恢复时仅续接原会话、原工作区与剩余预算。没有可信恢复则保留UNKNOWN。只有能确认未产生任何生成／工具动作的服务拒绝，才可作为启动工程重试，并完整记载。

全部真实调用完成后再向方法开发侧开放隐藏功能成绩；如运行期看到公开自测失败，不据此改经验或排序。允许普通运行器故障排障，不允许追分。

## 15. 功能验收：原生自测不等于最后结果

捕获完整原始patch，在干净base复建，恢复作者测试资产并应用统一的官方test_patch／harness；不使用Agent改写的目标测试代替可信检查。继承已有补丁、模式、路径和导入验证，不新建测试生成器。

每格分别记录作者FAIL_TO_PASS／PASS_TO_PASS标签结果、完整JUnit计数、skip、环境异常和候选身份。不能直接把不同解析器的参数化nodeid数相加；确实因原作者解析器有约定，保留其口径和完整用例表，不改语义追分。

```text
有独立、有效且属于本轮范围的目标/保护失败 → FAIL
所有必要目标/保护有效完成且通过          → PASS
无可信候选、环境/检查未完成或范围不明     → UNKNOWN
```

文件policy、技能触发、是否建议正确、成本、协议资格都不改写功能标签。超时若仍有候选可以验收，同时保留超时事实。

发现有限安装/导入/重建问题可在原候选上修复验收并保留过程，不新增Agent样本。语义性测试更正应对称、单列后验，不能覆盖冻结主表。不要把本轮再次转成测试合同研究。

## 16. 使用证据：目录可见、正文进入输入、主动读取分开

从公开事件中记录：

- 原生目录中系统技能、用户经验是否可发现，有无截断、路径或解析警告。
- 是否读取catalog、搜索名称／描述、读取技能正文或references。
- ASSIST实际给出哪些条目，是否被读取／忽略，是否另选目录外的其他条目。
- 是否有公开可见的适用性采用／拒绝理由，以及后续代码／检查的对应行为。

正文自动经原生机制进入上下文与显式 `cat SKILL.md`不是同一种证据；无法观察时写 `UNKNOWN`，不要把无cat当作未使用。不得读取或输出模型私有推理。

正确解决但未用经验，不判漏召回。读过经验但失败，不自动判误用。一个技术细节相同也不能证明技能是代码正确的原因。

技能覆盖问题单独解释：同库不代表库里有当前所需信息。可以在主结果冻结后，依据公开题面、当时源码与技能内容做覆盖核对；不得修改库、重新检索择优、为旧HTTPX生成“tuple检查”技能然后追认胜例。

## 17. 两张结果表和一份差距解释

### 表A：功能与完整成本

每个任务各列两次原始结果、PASS/FAIL/UNKNOWN、协议有效性、完整在线秒数、输入/输出/缓存用量、ASSIST额外准备、目录/技能读取和回退。

任务等权主差值：

\[
\Delta=\frac{1}{n}\sum_t\left(\bar Y_{t,ASSIST}-\bar Y_{t,NATIVE}\right).
\]

4个任务是4个任务单位，不是16个独立样本。先报逐任务胜／负／平／未知；缺失不填0或1，可给缺失最坏／最好界，注明不是置信区间。不用这个规模宣布总体显著性、严格非劣或全领域等价。

不要只对成功子集报成本节省。列出所有质量和成本，纯成功子集仅作附表并说明选择性。额外读了技能、少了一次搜索、某次提前结束，均不单独构成完整效率收益。

### 表B：候选提示与后续行为

每格记录原候选名称、是否在双方完整目录、正文可见证据、后续行为、功能结果、至少一个竞争解释。技能不适用、没有适用经验、原生不用也修好都保留。

### 差距解释

选实际最有信息的至多3个案例：导航可能有帮助、发生退化、没有作用各一个；没有某类则不编造。只做保存记录分析，不调用新修复、oracle提示、测试生成或模型训练。

经验来源、单个候选建议与目标修改之间的联系应引用实际原文和事件。不把同类命名当机制证据，不把模型自述当唯一因果证据。

## 18. 下一步决策只允许选择一个问题

以下是项目投入决策，不是统计显著性阈值：

| 实际观察 | 允许的阶段结论 | 后续候选方向 |
|---|---|---|
| 两臂功能/成本接近，未见明确差距 | 当前范围未发现需要额外导航的证据 | 暂不训练通用Router |
| ASSIST在至少两个不同问题上有反复的发现差异及功能线索 | 有多任务小样本导航线索，因果仍有限 | 只研究候选发现／目录选择 |
| 原生读到经验但在不同问题上误用同类明确前提 | 有待验证的适用性问题 | 再设计条件化适用性研究 |
| 两臂正确，原生搜索/回读总体明显更昂贵且计时完整 | 存在成本研究线索 | 质量约束下的低成本候选导航 |
| 库里缺乏信息，或建议的是无关经验 | 当前内容覆盖不足 | 先研究可迁移经验表示，不训练Router |
| 改好挂载或description后问题消失 | 配置问题得到修复 | 使用原生机制，不称算法创新 |
| ASSIST更差或提示不兼容经验 | 额外导航可能带来损害 | 保留退化，不调到获胜 |
| 运行/环境/计时大量未知 | 尚无能力差距结论 | 仅列具体接入限制 |

单一胜例只支持局部候选问题，不能自动触发数万条蒸馏和新训练。全部没有技能读取也可能是任务不需要；不能强制改描述让下轮必须调用。

ASSIST是便宜检索提示，不是已经发明的新算法。即使本轮ASSIST有观察优势，也只能说“在同库条件下额外导航可能值得研究”，不能宣称超过Codex整体能力。
