# Hermes Goal：建议模式的真实代码修复效用回放

> 激活本文后直接开发和执行，内部阶段连续推进，不等待下一份 Goal。
> **主线：固定一条用途明确的技能建议策略，真正交给隔离代码 Agent，通过实际补丁与外部检查比较它和简单方法。**
> 不再要求“文本适用性精度先达到 90%”才允许开展本轮实验；源码隔离、环境就绪、文件权限、可信验收与资源边界仍然必须满足。
> 范围内持续授权，不逐阶段申请批准，不设置固定工程尝试次数。实验重复次数是研究设计，不是工程排障次数上限。

---

## 0. 一页执行合同

本轮要完成的路径：

```text
四个已准备过的真实维护任务
    → 恢复并核对执行环境、源码与可信检查
    → 冻结 N / F2 / T2 / J2 四种技能提供方式
    → 保存同任务各策略的真实选择与完整技能包
    → 每种方式两次全新隔离 Agent 执行
    → 捕获原始补丁，在干净源码副本重新应用
    → 同一组目标检查与受保护回归
    → 比较任务结果、实际技能读取、失败类型和成本
```

默认规模为 **4 个任务 × 4 种方式 × 2 次独立执行 = 32 次计划修复执行**。这是一轮探索性回放，不是新的独立盲测，也不是保证得到提升的任务。

**核心交付必须包含真实执行。**仅修 Docker、增加入口、输出推荐 JSON、重算旧标签或得到 CI 绿灯，不算完成本轮效用研究。资源确实不可用时交付部分结果，但不得标为真实修复比较完成。

本轮不训练模型、不拟合新校准器、不收集 Gate 数据、不增加仓库或技能，不自动进入下一轮。

## 2. 与旧 Goal 的关系：改变研究问题，不篡改旧规则

旧研究回答：“经过高精度支持过滤的 C2 是否成立？”

本轮回答：“未被认证为高置信支持、但用途明确的技能建议，是否改善受限代码 Agent 的实际输出？”

新实验不以以下条件为启动前提：

- 旧 C2 必须有阈值。
- A/J 的文本精度、Brier、AUC 或覆盖先达到某个成绩。
- 新建议必须与固定技能不同，或者必须被弱标签判为适用。
- 旧 check 的严格支持资格必须由 0/120 改成通过。

但必须满足：真实目标环境与源码可用、可信目标/回归检查成立、隔离与文件策略有效、模型/技能身份正确、实际调用权限和额度可用。

**本文件明确授权新的隔离修复实验，覆盖先前“禁止新增修复 Agent”和“满足 C2 高置信触发才运行”的本轮限制。**不覆盖任何系统安全规则、账户权限、隐私限制或旧实验的结论。

旧阈值、旧 `policy_accepts`、旧 UNKNOWN、旧预测锁定和旧 0/40 记录原样保留。新结果另存，不将本轮的 32 次填进旧矩阵。

## 3. 持续授权与非目标

允许自动进行：本项目源码读取和局部开发；已有公开资产定位；固定来源重建；必要公开依赖取得；隔离容器准备；本地冻结排序模型推理；已有授权 Agent 调用；补丁捕获和验收；回归、安装、正常 Git 提交/推送并更新同一 Draft PR。

不重复申请阶段、计划、安装、测试、普通修复或推送授权。工程失败要换用有依据的排查方法，不机械无限重试。不得承诺真实系统无法提供的权限。

不做：

- 不重新训练 A/J、原 rank、文本模型或 Gate；不调新损失、阈值、动态 K 或 RL。
- 不增加新的任务库、标签研究、解析框架、权限平台、前端或持续评测服务。
- 不购买算力/额度，不访问原公司服务，不修改全局代理、Codex 配置、技能或 hooks。
- 不把补丁应用到用户真实工作区，不提交第三方上游 PR，不合并、ready、发布、force push 或设置 auto-merge。
- 不通过降低隔离、让任务读取凭据/裁判文件、启用自由网络或关闭验证使实验“终于能跑”。

现有额度不足可以暂停并保留可继续的进度。不要默默购买资源；不要在结果出现后缩减不利条件来获得完整成功。

## 7. 恢复执行环境：解决实际引用，不改研究语义

上轮只确认“裸 SHA 可解析、命名引用不能解析”，未确认完整底层原因。[S1][S2]

本轮必须实际调查并恢复要执行的四个任务环境，不需要为了表面整齐重建上一轮全部 24 个环境。

优先步骤：

1. 读取当时请求的基础引用、平台、RepoDigests、实际镜像 ID、源码和依赖资产记录。
2. 区分注册表清单/多平台索引摘要、平台镜像清单摘要、本地配置 ID，不把任意同形 SHA 当作同一对象。[E2]
3. 若官方固定引用可重新取得，按原内容与平台恢复；若使用本地资产，必须能对应到已固定来源与配方。
4. 需要本项目专用标签或局部解析兼容时，只在本轮隔离命名空间处理，保留原引用与实际解析对象映射。
5. 重新检查指定源码导入、依赖、必要入口和执行/验收环境；环境就绪不等于 bug 已修复。

不得改用 latest、另一个 Python/平台、任意本地镜像或假的 `environment_known=true`。不能删除全部镜像/缓存或执行全局 prune。

相同配方重建后若镜像身份确有变化，查明并记录新旧差异。不能为了匹配摘要修改旧事实。四臂必须共同使用重新固定的同一任务环境；若依赖或源码语义变化，明确为新的探索性环境，而非旧环境的字节级复现。

只修复本轮实际会用到的解析/准备路径；不再建设通用镜像证明系统。恢复不出合法环境时准确报告，不以无限猜引用替代诊断。

## 8. 建议资格与执行安全分开

本轮不调用旧 `supported` 入口来取得执行许可，也不把 `policy_accepts` 手工置真。

分别保存：

```text
recommendation_mode: advisory
support_certified: false
selection_source: native | frozen_fixed | frozen_text | frozen_joint
recommendation_status: SELECTED | FALLBACK_NATIVE | UNAVAILABLE
execution_readiness: VERIFIED_FOR_SCOPE | BLOCKED | UNKNOWN
execution_authority: PROVIDED_BY_THIS_BOUNDED_STUDY_ONLY
```

这是语义示例，字段名可适配已有结构，但不能复用“已认证支持”状态代表普通建议。

对建议评分：只使用来源正确、可读取的请求/技能与有限公共上下文。上下文 `partial` 或 `unavailable` 表明自动摘要不足，并不自动说明 Agent 不能读取实际 base 源码；如字段仍真实可读，可原样附限制并评分。不得伪造 `usable`、凭标签补上下文或为 J 添加参考修复信息。

对实际执行：四臂都必须有已核对的 base、依赖、候选源码定位、隔离、文件策略与可信检查。文本评分可以不确定，执行边界不能未知。

路径逃逸、来源/模型错配、凭据暴露、裁判泄漏、已知禁止的工具或危险执行要求仍阻断对应操作。不得将这些问题重新命名为“只是低置信建议”而放行。

## 9. 修复资格：重用资产，但必须在实际执行环境复验

上一轮资格 JSON 只是入口，不是代替当前环境实测的凭证。

对每个固定任务：

- 在真实 base 上运行预先固定目标检查，确认确实失败；基础受保护回归通过。
- 在可信参考环境上运行同一目标/回归，确认对应行为通过。
- 核对检查文件、base 清单、Python 导入路径和依赖；参考版本额外依赖不能只让某个臂获得。
- 目标义务须能由原公开请求、接口约定或对应版本文档推导。不要添加只有裁判知道的正确答案。
- 公开记录可信检查的实际数量、内容范围与参考来源类型。基本 CRUD/CLI smoke 不能写成全仓库完整回归。

旧检查资产缺失时先从已有合法记录恢复；确需重建控制器检查时，在查看本轮建议和补丁前固定并说明它是重建版本，不冒充原字节。

对 #344 的较新参考版本，只使用它证明公开行为可实现，不给 Agent 后来的仓库，也不以候选代码接近参考 patch 作为成功条件。

对 #400 明确参考由控制器编写，允许行为正确但实现不同的候选。

## 10. 冻结清单与统一实验预算

在首次正式 Agent 启动前固定：

- 四任务 base、公开请求、可信检查、环境和文件策略。
- J 候选、底座、tokenizer、双轴模板、上下文处理与长度预算。
- T 的冻结向量化器/权重与原始适用分数；F 的旧每库/default 配置；完整十技能包。
- 四臂候选排除规则、K、无技能时行为、共同发现方式与呈现顺序。
- 被测 Agent 的模型/服务、实际版本可见信息、推理强度、每次时限、上下文限制、并发与资源。
- 运行顺序、重复处理、主指标、未知处理与成本统计。

执行 Agent 与本轮开发 Codex 可以使用不同配置。优先沿用现有合法且可用的被测配置；源码默认值不保证服务仍支持。必要时在任何正式结果之前确定可用模型，四臂保持一致，不为让技能显得有用刻意换弱模型。

建议沿用每次 600 秒、并发 1、每臂 2 次、运行顺序 seed=7170。32 次若全部耗满，仅 Agent 部分可达 5 小时20分；提前估算已有额度，不把这轮承诺成几十分钟任务。

工程排障不受固定次数限制；**正式重复方案冻结后不增加重复来追求获胜**。资源迫使缩减时优先保留四臂对称性并记录原因；不能查看某臂较差后取消它的第二次。

## 11. 锁定建议：不让弱标签决定谁能被推荐

四种方式使用相同的公开请求和同一份仓库事实摘要。摘要不含任务标签、机制 ID、参考 patch、裁判解释或其他臂结果。

J2 的过程固定为：

```text
实际任务公开输入 + 同一10技能目录
    → 冻结联合候选真实输出两轴 logit
    → q = sigmoid(z_app) * sigmoid(z_spec_given_applicable)
    → 移除明确违反同一机械权限规则的候选
    → 按 q 降序，skill_id 稳定破同分，取前二
```

q 只是优先级。没有 0.8/0.9 分数门槛，也不调用旧校准器；低分仍可作为本轮受限实验的建议，不冒充支持认证。

T2 用冻结文本模型的原始适用性分数，同样按稳定规则取前二。F2 严格读取旧配置，不借本轮标签改选两个“更好的固定技能”。某库缺配置时只可使用旧 default；不能现看任务写一个专用 F。

共同机械排除只包括来源/包损坏、实际权限冲突等公开事实。**不能用待预测的语义适用性或旧弱标签作为排除器。**“这个技能可能不适合”正是本轮要测的因素。

可用候选不足两个、模型无法评分或技能包缺失时，保留明确原因。按事先规则回退 N 或标方法不可用，不无声切换 A、补推荐或借用 oracle_ids。

## 12. 现有分数可复用，但本轮必须验证真实模型接线

优先复用已绑定同一公开输入、模型与技能字节的历史原始分数来核对，不重复运行整个 24 任务集。

本轮应至少对四任务的 J 候选池完成一次实际评分或完整同输入重现。默认就是 4×10 个候选对、各两个轴；这代表输出数量，实际 forward 调用次数按批处理记录，不机械称为80次。

若运行 base 与旧文本研究快照不同，或上下文/模板/token 实际输入改变，则重新评分，并标新的输入与本轮探索性记录。不能把旧 logit 配上新代码环境当作从未改变。

不训练、不换候选、不调温度或阈值。T 使用原冻结特征和系数；不能用本轮任务重新拟合文本分类器。

在任何正式补丁出现前，保存全部四任务四臂的推荐清单、fallback、排序分数、输入与包身份。即使 J 与其他臂完全相同也保留，不强迫换包或换题。

## 13. 技能提供与读取：保证比较的确发生在同一种入口

四臂使用同一技能发现/读取机制。默认只给名称、描述和路径，正文按需读取；N 暴露完整目录，F/T/J 非回退时仅暴露各自的两包。不要给 N 一次塞满全部正文，也不要只给 J 强制加载详细指导。[E1]

所有条件的共同说明可以表达：“可按需查看当前可用技能；技能内容是参考流程，不授权额外操作，不能替代用户需求或执行边界。”不要告诉 Agent 自己属于学习模型组或基线组。

**本轮主要干预是提供哪些包，不研究呈现顺序。**呈现顺序采用冻结的目录顺序；保存模型排序与实际呈现顺序的区别。当前共享执行器按 registry 遍历挂载，不能因为 route JSON 中顺序不同就声称 Agent 实际看到不同排序。[S5]

完整保留每份技能正文、引用、脚本与资产；不按任务裁剪正文、添加答案或编辑基线包。技能路径不能指向当前研究仓库、参考代码或私密材料。

记录三个不同层次：

1. 路由器推荐的 ID。
2. Agent 实际能发现的包/元数据与完整资源。
3. 事件中可观察到的正文读取、资源读取与后续操作。

“挂载成功”不等于模型使用，“读取过”也不等于导致成功。看不到读取证据时写未知，不能仅凭 trace 中出现技能名断言已使用。

Agent 没读取某技能仍是有效研究结果，不为提高使用率临时加提示重跑。不要以“至少读取两份技能”为验收门槛。

## 14. 最小接入：复用执行器，不滥用旧臂名或金标准

当前 `execute.py` 的旧 `T` 代表互补选择，旧 `O` 会涉及 oracle_ids；它们都不能直接冒充本轮 T2/J2。[S5]

优先新增一个薄研究适配层，调用现有 `run_agent` 和最终验收函数。在调用共享执行器前，保留 `execute.py` 中的源码、资格、隔离、输出目录与输入绑定检查。

研究适配明确接收：固定协议、任务、独立路径、合法推荐记录、完整技能目录、方法名与重复编号。验证推荐记录由对应冻结策略得出，不允许任意外部 ID 列表覆盖后伪装成模型选择。

**不可通过写入 qualification.oracle_ids、使用 O 臂再改显示名、或把 J2 改装成 supported C2 来绕过接线。**资格记录只提供执行/验收事实，不提供推荐答案。

路由不成功时行为要明确。不能碰到异常就悄悄换 native，然后把结果记作 J2 成功。

所有臂显式配置相同的临时调试目录、文件权限和验证路径。现有某些策略才启用 scratch 的分支不能造成 J2 特有的额外可写目录。

## 15. 隔离与防泄漏必须保留

每次正式执行使用新的会话、独立工作目录和干净 base 副本；无其他臂补丁、历史对话、总结或跨任务记忆。

被测 Agent 不得读取：参考修复、可信隐藏检查、当前标签文件、已保存分数/结果、Goal复盘、其他臂事件、GitHub未来历史或宿主目录。

资格控制器与路由评分器、执行 Agent、最终裁判的数据可见范围分开。共享宿主的实际边界如实披露，不宣称密码学隔离。

技能与目标源码可能含可执行脚本，执行仍受统一网络和文件规则约束。模型服务所需通信沿用已隔离的授权通道；目标工具环境不能因此获得自由联网、Docker socket或凭据读取。

原生 N 的个人/全局技能污染也要排除；使用本轮专用隔离配置，不修改用户全局技能。不可用强制降权限或删除安全规则来获得成功结果。

源码快照路径、模型资产、验证资源和日志路径不能互相嵌套形成可见性旁路；输出/临时目录只能由本轮管理。

## 16. 文件策略与补丁验收：不再把正常临时文件算进源码

四臂得到同一份明确的可新增/修改/删除规则，包括合理的正式测试数据位置。临时调试材料写入独立 scratch，不进入源码补丁。

必须保留完整原始候选 patch。禁止先丢弃被禁止的变化再把剩下补丁当作“原补丁通过”；策略拒绝与功能失败分开记录。

结束并确认进程停止后：

```text
独立保存原始候选差异
    → 校验文件操作与路径边界
    → 在新的干净 base 应用同一 patch
    → 核对重建源码与候选修改一致
    → 从候选源码加载目标模块/CLI
    → 运行固定可信目标与回归
```

Agent 自己新增的测试可以保留作为补充，但不能替换控制器固定检查。目标检查、Junit/JSON报告、测试入口不能被候选改写或提前伪造。

空补丁可被正常记录，但在 base 已红的目标上不应凭 Agent 的“已完成”文本算修复成功。无需强迫模型为了非空而改无关文件。

## 17. 调度、重复与恢复

生成一个冻结的运行清单：每条包含任务、臂、重复编号、唯一run_id与预算。按固定随机种子在任务/重复块内轮换四臂，避免永远让一种方法先执行。

两次重复是两个新会话，不共享修复过程。提供方无法固定采样种子或真实模型快照时如实记录；相同名义seed不被描述为完全配对的随机轨迹。

启动前基础设施失败可按原输入与预算修复后重试，所有尝试留痕；不能重命名为新独立样本。是否进入模型生成必须从实际事件判断，无法确认时标未知。

已启动后的超时、未修好、策略拒绝或模型错误，不重新运行直到获得通过。保留每次最终补丁；不得只保留两次里最好的一次。

临时网络/服务问题可暂停同一清单，恢复后从未完成位置继续，不重跑已完成格。持久化进度，不要求用户重新写Goal。

环境或安全边界异常时先暂停受影响任务/臂，排障后重新核对；不把持续坏环境中的失败当成算法负例堆满32次。

## 18. 不可再增加的实验启动条件

正式执行的必要条件仅为：

- 任务资格与实际执行环境已验证。
- 方法、输入、资源包与执行预算已固定且可用。
- 当前账号合法授权可调用，隔离与证据可见范围有效。
- 有可运行的共享执行及外部验收路径。

**不能再要求：**校准阈值非空、文本精度90%、已知覆盖10%、弱标签Top-2全对、推荐不同于F/T、或者预测一定会成功。

J2只有非空建议、尚无可靠精度认证正是本轮研究对象。没有支持认证，不等于没有隔离研究授权。

另一方面，若 J2 的实际评分/挂载仍未实现或权重不可得，则其方法状态是不可用，不能用手选两技能或原生代替后宣称四臂完成。

## 19. 评价：以补丁行为为主，不再以弱标签为启动裁判

主结果为：固定目标检查通过，且受保护回归没有新增失败，同时补丁和执行过程符合既定机械边界。

每个运行至少分开记录：

| 层次 | 例子 |
|---|---|
| 调用状态 | 未启动、已启动、超时、执行器异常 |
| 技能提供 | 正常两包、原生目录、明确fallback、挂载失败 |
| 补丁完整性 | 已捕获、缺失、重建失败、候选源码不一致 |
| 文件策略 | 通过、违反新增/修改/删除范围 |
| 行为验收 | 目标/回归各通过多少、失败/错误/跳过多少 |
| 综合结果 | 成功、功能失败、策略失败、未知、未运行 |

基础设施未知不是已知功能失败。主表保留完整计划分母，另给可验收范围；未知不得通过删除提高成功率，也不得直接当功能失败混入准确率。

对已启动但无候选补丁的模型超时，可列为超时未成功；验证设施失败则列未知。执行前不可用列未运行。定义在看补丁前固定。

旧适用性/特异性标签只在主结果锁定后作解释附件，不能改标签、按标签过滤任务或用它覆盖实际验收。

## 20. 比较口径与小样本边界

主要产品比较：**J2 对 T2，以及 J2 对 N**。F2为额外的固定方案对照。不能只挑 J 赢而基线明显较弱的一列作总结。

每臂最多8次计划运行，但独立任务只有4个。至少输出：

- 每任务×臂×重复的完整结果。
- 每臂成功/功能失败/策略失败/超时/未知/未运行数量。
- 任务内两次重复的均值或分布，再形成机制级配对胜/负/平/未知。
- J/T/F 实际集合相同率、fallback、正文可观察读取情况。

相同技能集合不能因为某次采样恰好成功就归因为选择算法；不同集合也不自动证明技能造成成功。只在全部主表之外做机制解释，不只报告 J 确有改选的子集。

四机制不足以支持稳定泛化、生产收益或部署保证。默认不依赖显著性检验作晋升；如给区间，以完整任务为单位并说明退化/宽区间，不把32个调用当32个独立问题。

本轮比较的是“提供哪组技能”的整体策略，不单独证明训练损失、仓库上下文或J双轴乘积的因果贡献。要隔离这些，需要另行设计，本轮不追加。

## 21. 成本必须包含建议开销，但不编造在线账单

分别记录：公共上下文处理、环境恢复/准备、J模型加载/评分、T计算、包准备、Agent输入/缓存输入/输出、执行耗时、补丁重建与验收。

J在正式修复前统一计算一次、两次重复复用时，分开给出：实际研究总开销；首次推荐耗时；缓存复用行为。不能把预计算当作免费在线路由，也不能把同一次真实计算在总账里重复收费。

如按“每个独立用户请求都会重新推荐”估算调用侧开销，明确为带假设的派生估计，不声称已经测得这一在线时延。

冷启动与暖运行分开。共享环境准备成本单列，不只记在某个臂。输入token、缓存token、输出token分别报告；供应方没有完整用量就保留null。

Goal开发token不是算法在线成本，美元费用没有可信账单则未知。不能只因输出token少就断言总费用下降；也不以累计任务秒数冒充用户墙钟等待时间。

不改变并发来使某臂更快，不为得到速度优势换服务、缩预算或让参考解进入提示。

## 22. 接口、回归与安装

建议使用现有 `hermes-maintain` 下的薄研究子命令，或一个调用已安装共享模块的脚本。以下仅为新增职责示例，最终命令必须实际验证：


- J 双轴身份与乘积正确，排序/同分稳定，不能接无特异性监督的旧候选。

在仓库外干净wheel环境运行轻量入口和records；实际模型与修复环境按明确外部路径使用。至少一个本轮正式执行经新安装入口/已安装执行模块完成，不以仅源码目录下可运行冒充可安装。
