# Hermes Goal：冻结后的独立验证与条件式真实修复对照

> 激活本文后直接开发并执行，内部阶段连续推进，不等待另一份 Goal。
> **本轮主线：冻结已有模型与决策规则，在没有参与之前修改的新任务上校准、锁定并检查；条件成立后，完成预先选定的小规模真实修复对照。**
> 不继续堆叠算法，不重新训练 LoRA 或 Gate，不把旧数据上的后验阈值当成新任务有效性的证明。
> 范围内持续授权，不逐阶段申请批准，不设置固定工程尝试次数。实验规模、资源预算、隔离、保密与实际系统权限仍然有效。

---

## 0. 本轮到底要回答什么

回答三个按顺序递进的问题：

1. 已冻结的 A 适用性模型与 J 任务特定排序，在新的自然维护需求上表现如何，是否只是记住某些技能普遍适用？
2. 只在新校准集拟合并选择的阈值，放到不参与选模、改规则或选阈值的新检查集，是否仍有足够的精度、覆盖和非空选择？
3. 若这些条件成立，受支持的技能选择真正进入代码 Agent 后，与原生方式、固定技能、便宜文本和原排序相比，是否改善补丁质量或成本？

本轮不是“保证得到正提升”的任务。必须形成完整、可复算的验证结果；不能把没有收益伪装成收益，也不能在资源与条件齐备时只交付另一份计划或空接口。

**“完成独立检查”与“检查支持方法有效”是不同结论。**检查否定方法，也属于有效研究结果；缺少新检查数据、模型未运行或只重算旧记录，不属于完成独立验证。

以下新任务招募、分区、阈值锁定、独立检查、五臂修复比较和实验专用迁移路径，是本轮要求；不能称为仓库已经完成的功能或已有成绩。

“独立”在本轮指：**新检查机制未参与此前训练、开发选择、校准或实现调整，最终预测与决策在读取检查标签前固定。**它不代表人工真值、不代表不同模型家族标注、不代表底座预训练完全没有见过公开 issue，也不代表统计上完全独立同分布。

持续允许：读取本项目和合法公开来源；创建隔离工作区；下载必要公开源码与依赖；准备现有类型的容器；调用已授权本地模型和已有 Agent 服务；在新校准数据上拟合低维映射；运行测试与本轮预定实验；提交、正常推送同分支并更新 Draft PR。

不重复申请计划、阶段、安装、标注、正常修复或重跑批准。普通失败先定位原因并继续，不要求用户再发下一份 Goal。

严格不做：

- 不新购 GPU、API 额度或付费服务；公司旧连接不构成持续授权。
- 不改全局代理、Codex 配置、全局技能、hooks 或审批机制；不绕过客户端权限。
- 不改旧模型参数、旧 Gate、原 rank、旧训练／校准／检查标签和历史结果。
- 不训练新的神经网络、门控或文本分类器，不调 LoRA 超参数，不扩展动态 K 或在线强化学习。
- 不增加第四个仓库、新技能目录或新的通用实验平台。
- 不向用户真实工作区应用候选补丁，不向第三方上游提交修复。
- 不 force push、不合并、不 ready、不自动发布权重／包，不设置 auto-merge。

本轮允许新的 Agent 实验，**覆盖前一 Goal 的“不得新增修复 Agent”限制**；但只能按后文规定的触发条件、名单和统一预算执行。

未声明的新付费支出一律禁止；现有额度不足时缩减尚未冻结的计划或交付部分结果，不掩盖未完成。

## 3. 范围与推荐规模

优先限定在已有三个来源：`simonw/sqlite-utils`、`wireservice/csvkit`、`simonw/csv-diff`。沿用当前完整的 10 项技能包，不添加无关技能制造检索困难。

默认计划：

| 数据用途 | 推荐规模 | 用法 |
|---|---:|---|
| 原有任务与原四条 cal | 仅作工程调试与污染排查 | 不进入本轮新研究分母 |
| `cal_new` | 12 个新的独立修复机制 | 拟合固定形式的校准映射、选择阈值 |
| `check_new` | 12 个与 cal_new 及历史不重叠的机制 | 最终一次协议检查，不参与调参 |
| `repair_subset` | check_new 中预先合格、预先固定的 4 个机制 | 条件成立后五臂、每臂2次真实执行 |

12＋12 是任务量建议，不是统计有效性的保证。每任务 10 个技能会得到 240 行新配对，但独立单位仍是任务／修复机制，不是 240 个任务。

在接触本轮标签、分数和修复结果之前，根据实际公开来源、资格和现有资源确定可完成规模并记入协议。低于建议规模时明确小样本限制；不得通过看完分数后追加有利任务补齐。

默认修复矩阵为 `4 × 5 × 2 = 40` 次真实执行。这是预定实验设计，不是限制工程排障次数；也不是要求先消耗完40次调用。只有触发条件满足才启动。

不要把一次 prompt 的 token 上限等同于整个 Goal 的费用上限。用已有运行日志估算准备、标注、推理、Agent 与验证耗时，保留未测字段为 null。

| 阶段 | 实质工作 | 完成依据 |
|---|---|---|
| V0 | 固定范围、旧资产与比较策略，补好最小新数据入口 | 可运行实验协议及历史污染排查入口 |
| V1 | 招募真实新需求、机制去重、环境预检、分区 | 新名单与全部排除理由 |
| V2 | 盲于模型结果的弱标注，校准／检查隔离 | 来源明确的标签及可见性记录 |
| V3 | 新 cal 真实评分、映射拟合、阈值锁定 | 新 calibrator、完整选点依据、锁定身份 |
| V4 | 新 check 固定预测、揭示标签、独立重算 | 全任务结果、覆盖／风险／基线比较 |

新cal没有阈值时，仍应在合法、可读取的新check输入上运行已冻结的原始分数与建议排序，并完成这些指标；supported接受保持空或未建立。不得让“严格接受前提不足”错误阻断所有离线区分能力检查。无法评分的输入则如实保留原因与覆盖分母。

## 5. 冻结什么，哪些变化仍然允许

### 5.1 第一次冻结：方法冻结，先于新数据分数

固定：

- A：当前适用性目标选中的 lambda=0 / epoch 3、底座版本和 adapter 身份。
- J：当前任务特定目标选中的 lambda=1 / epoch 3，仅作为原始优先级次要对照。
- 原 rank 的参数、输入长度和排序方式；不把 J 悄悄替成 B2。
- 当前上下文提取器、正文／代码处理、token预算与指令模板。
- 完整技能目录、正文和资源文件，当前固定技能 F 配置。
- 已拟合的便宜文本、技能先验、skill-only 基线及其特征转换，不在新任务上重拟合。
- 环境要求的语义、已知冲突处理、K=2、fallback 策略。
- 新校准映射形式、加权方法、阈值选择条件及统计定义。
- 用于 Agent 修复的实际模型、版本可见性、推理设置、并发、每次任务预算和验证方式。

如果本地缺少某个已冻结基线的可用模型，只能按原 fit 数据、原参数确定性还原并核对；不能在新 cal/check 上训练出一个“替代基线”。

### 5.2 冻结不等于禁止新的校准拟合

本轮神经网络权重与分类器不训练；**允许在 cal_new 上重新拟合已声明形式的校准映射与选择阈值**。这正是研究步骤，不是偷改模型。

第二次冻结在 V3 完成后：固定所有新映射、阈值、预测公式、比较方法、检查名单和修复名单，然后才正式评分 check_new。

默认不拆成多个很小的校准子集：同一 cal_new 可用于固定映射拟合和预定选点，所有这部分指标都叫校准内结果；其泛化必须用完全独立的 check_new 检查。不能将 cal_new 拟合后的数字当成测试表现。[E1][E2]

### 5.3 A/J 语义保持原样

```text
A 分数：sigmoid(z_app)，支持阈值使用该候选自己的校准映射。
J 分数：sigmoid(z_app) × sigmoid(z_specific|app)，只称任务特定优先级。
```

A 不读取第二轴来挑技能。J 不称联合修复成功概率，不由于新 check 中某项成绩更好就升级成主模型。

## 6. 历史污染排查：排除的不只是旧四条 cal

扫描已有任务清单、fit/model-dev/cal/check、历史真实修复矩阵、案例、技能生成来源和已用于调试的请求。

建立一个紧凑的 `previously_seen` 索引，至少包含仓库、issue/PR、来源revision、请求摘要、机制、相关修复与观察用途。只用于数据排查，不进入预测特征。

同一个 issue、同一修复 PR 的多个引用、同一实现错误的改写、同一 base/patch 的派生任务，都不能跨历史与新集或跨 cal_new/check_new 作为独立机制。

同样的通用操作如“CSV输出”不自动等于相同修复族；应检查具体错误机制与修复依赖。也不能因 issue ID 不同就断言不相关。

明确被看过、用于调整代码／模型的任务留在开发资料；疑似重叠可保守排除并说明。查不到完整旧记录时披露查重范围，不能声称百分之百无污染。

所有新任务默认是**已有仓库中的未参与本项目开发的机制**，不是“未见仓库泛化”。底座模型的预训练污染无法由此排除。

## 7. 新任务招募：真实需求，不能按预期结果挑题

先构建真实候选池，再按可执行的预定顺序筛选。可按来源列表稳定排序后用 seed=7170 作仓库内确定性抽样；具体规则写入 protocol，一次固定。

合格条件仅基于：

- 来源可追溯、有清楚的用户需求，而非为 Hermes 特意编写的短题。
- 具有可获得的合法源码版本，代码与请求对应，不含未来实现。
- 处于现有 Python CLI／数据维护与固定技能目录的合理范围。
- 可从公开输入提取足够事实；来源、许可、依赖与基础运行条件可处理。
- 与历史及其他新任务没有实质机制重叠。

不能按“A高分”“J比固定选得好”“reference技能能赢”“原生容易失败”“标签刚好填满两技能”筛选。

公开需求含修复提示时保留原文并披露；不要删除提示使原生更难，也不要把参考修复中的新事实补入题面。issue 后来被编辑过时记录抓取内容及更新时间，不冒充历史原始版本。

优先使用明确修复前的提交。仅仅在issue创建前的快照不一定对应可复现bug；文本研究可以披露该限制，修复实验则必须另行完成资格验证。

## 8. 分区与名单冻结

所有自然机制整体分入 cal_new 或 check_new；同任务的10项技能必须在同一区域。[E3]

先按来源／操作类别做与标签无关的平衡，不能看到模型分数后换seed；默认三个仓库在两部分均有覆盖。来源不足时记录实际分布，不创造技能或复制任务凑数量。

先保留候选招募清单，再提交分区清单；对每个候选记录纳入或排除原因，避免只留下最终好看的任务。

在模型分数未知时准备修复资格，从 check_new 中按预定顺序固定4个修复机制及备用顺序。备用只能在正式预测前因客观资格失败替换；查看预测、支持数量或修复结果后不能替换。

`check_new` 的标签可以由独立控制步骤预先生成并封存，也可以在所有最终预测锁定后才生成。无论哪种方式，选模、拟合、阈值选择与策略开发都不得消费它。

本轮控制器可以为资格读取公开请求，不等于“无人见过测试题”；应记录哪一步访问了什么，禁止把隔离程度夸大为真正的第三方盲测。

## 9. 环境与输入预检：在模型计算之前完成

复用已有位置过滤、片段提取与环境探测，不再加一套框架。

在固定10技能、固定源码和当前使用scope下，逐任务确认：

- 公开请求、源码版本、完整技能包、关键片段与token可见性。
- 候选模块来源、目标版本、依赖兼容、必要入口与基础能力。
- 受限网络与文件权限；技能作为指导阅读，不代表所有文档示例都必须执行。
- 真实冲突、不满足、未知和当前用途不需要的条件分别记录。

环境探针配置可扩展到新任务的具体版本，但要求语义不能因某任务失败而放宽；用显式模块/能力字段描述，不靠 task_id 尾号自动猜测能力。

依赖取得与目标源码运行分开：下载阶段允许必要公开网络，实际目标运行继续隔离，无凭据、无用户主目录、无Docker socket挂载。不能执行 issue 或技能文本提供的任意shell命令。

资格招募阶段可以因来源缺失、明确不适用范围或不可准备环境排除候选，必须在标签／分数未知时依预定规则处理，并披露整个招募分母。

**名单冻结后**出现未知环境或token缺失，保留该任务为资格拒绝/未知，不删除后重新缩小分母。可按原配方修复下载或缓存问题，但不得改变任务本身来让它通过。

## 10. 标注：继续区分弱标签与实际修复效果

沿用原两轴含义，不新增有利标签体系：

- 适用性：`APPLICABLE / NOT_APPLICABLE / CONFLICT / UNKNOWN`。
- 条件特异性：仅在适用性已知为正时判断 `TASK_SPECIFIC / GENERAL_WORKFLOW / UNKNOWN`。
- 非适用行对“适用且任务特定”联合事件为0，但其条件特异性轴本身不是0标签。

每个新任务标注全部10技能，不只标模型Top-2或某一个gold技能。允许多个可用技能、无任务特定技能或合理通用工作流。

使用至少两个相互看不到输出的标注上下文。只提供固定公开请求、相应仓库事实与完整技能内容；不提供分区、方法名、预测、阈值、参考补丁或胜负结果。

沿用原证据结构：请求片段、技能原文、具体适用步骤、前置条件、不确定原因。逐轴分歧按预定规则合并为UNKNOWN，不用第三轮追问直到同意某个模型。

同一模型的两个上下文仍是同源弱监督，不能写成两位人工标注者或两种独立模型家族。不要求用户现在人工签字；缺人工复核时主表必须标“相对弱标签”。

标注盲审可以检查缺字段、错引原文等机械错误；在查看预测前完成修正。查看方法分数后不修改标签以提升成绩，事后勘误另存并保留原表。

UNKNOWN不当负例，也不让推理程序读取UNKNOWN来决定拒绝；未知接受数只能在事后评价时计算。

## 11. 数据与代码可见性，简单但有效

不要再建设审批系统或复杂证据平台。复用现有独立进程、工作区和文件路径隔离：

| 步骤 | 可以看到 | 不能用于决策 |
|---|---|---|
| 方法开发 | 旧任务、旧结果、接口夹具 | 新check标签/胜负 |
| 任务资格控制器 | 公开源码、必要环境、可信参考与验收 | 被测Agent的待生成结果 |
| 标注器 | 公开输入、技能内容 | 模型预测、分区、参考补丁 |
| 校准器 | cal_new输入、标签、固定模型分数 | check_new标签与分数 |
| 检查评分器 | check_new公开输入、冻结系统 | check_new标签、解释性标注 |
| 修复Agent | 修复前代码、公开请求、相同工具与对应技能 | 参考补丁、可信隐藏检查、其他臂产物 |
| 最终评价器 | 已锁定预测、标签、可信结果 | 不再修改方法 |

任务ID与机制ID用于对齐和统计，不能作为模型预测特征。标签中的 `quote_refs`、解释、目标类别也不得进入在线公共输入。

仅凭同一个进程里写了“不要看”不叫隔离。提供独立参数、明确输入文件与断言即可；披露控制器仍可能接触的资料，不宣称密码学盲测。

## 12. 必须保留的离线对照

在同一新检查名单、同一目录上输出：

| 方法 | 本轮可做的操作 | 主要用途 |
|---|---|---|
| 冻结底座 | 同输入推理；单独新cal映射可选且预先声明 | 区分后训练贡献 |
| A 原始值 | 冻结模型推理 | 适用性区分能力 |
| A 新校准值 | 只在cal_new拟合固定形式映射 | 概率与接受决策的跨集验证 |
| J 原始乘积 | 冻结联合候选推理 | 任务特定排序的次要检查 |
| 全局／技能先验 | 读取旧fit确定的比例，不重拟合 | 检查类别或技能先验捷径 |
| 便宜文本模型 | 固定向量化器、词表、权重与超参数 | 主要竞争对照 |
| skill-only | 冻结、不读取新请求特征 | 负对照，不当任务理解成果 |
| F 固定技能 | 原有每库或default的固定两个技能 | 固定工作流是否已经足够 |
| B2 原rank | 保持既有模型、候选全集、K=2 | 原排序对照 |
| C2 原rank＋A支持过滤 | 同B2排序、同目录，按新cal锁定的A门槛过滤 | 当前支持学习的主运行策略 |

N 原生选择在后面的执行比较中评估，不凭空给它制造离线AUC或概率。

便宜文本模型作为重点基线，也使用相同cal_new和固定映射形式产生一份独立校准对照；它保留自身分数与阈值，不能使用A的阈值。映射不是重新训练文本分类器。

J保留原始优先级，不重新搜索联合事件校准或新的技能组合目标；A、J和便宜方案各报告对应目标，不把无辅助特异性输出复活为主策略。

若某冻结基线确实不可还原，显式缺失；缺少关键便宜文本或固定基线时不得宣称胜过竞争方法。

## 13. C2 的确切含义：本轮只验证一个候选策略

为避免一边验证一边另造算法，本轮 C2 固定为：

```text
固定原rank对10项技能排序
    → 应用所有方法共用的已知权限/环境冲突规则
    → 用冻结A＋cal_new映射对每项技能作适用性判定
    → 按原rank顺序取前两个合格技能
    → 不足两个时回退原生N，清楚记录原因
```

C2不改用J排序，不变动态K，不为凑两项加入不被接受的候选。回退N是完整策略的一部分，必须进入总分母，不冒称K=2。

B2使用同一个原rank与公共冲突规则，取前两个可用候选，不做A过滤。其可用候选不足两个时按同一事先约定回退N。

纯过滤常常不改变Top-2，这是允许的。必须报告B2/C2相同率、发生变化的任务和实际加载包；不能为了增加变化率强迫换包。

J的离线次要结果不能自动成为本轮C2的升级选项。需要改策略时留到后续，不用新检查集选择“哪个路线最好”。

## 14. 新校准：先有资格，再评分，再锁定

校准前先检查结构上是否可能满足原规则：独立机制数、已知行数、映射正负类数、输入完整性与环境事实。必要条件失败时不假装找到了操作点。

沿用适用性校准与选点标准，启动时核对旧配置实际值并写入新protocol：

```text
mapping: positive-slope sigmoid scaling with intercept
min_axis_groups: 3
min_each_class: 3
target_precision: 0.90
min_accepted_groups: 3
min_accepted_rows: 6
min_known_coverage: 0.10
max_unknown_acceptance: 0
selection: highest eligible known coverage, then higher threshold
```

上述是样本内经验选点条件，不是安全保证或行业标准，不因本轮结果放宽。

A采用固定候选的原logit，真实处理本轮公共输入，记录模型、tokenizer、上下文和环境身份。批量准备的输入直接用于forward，避免预检时一份、评分时另一份。

仅cal_new标签进入映射拟合与阈值选择；拟合后保存完整曲线、选点、原始分数与校准分数。阈值为空也写入最终锁定对象，不允许从旧四条cal借阈值补上。

概率拟合遵守既有加权目标，评价权重另明确，不能把不同权重下的训练loss当成同一评价loss。需要数值修正时先在旧夹具验证，查看新check后不得为提高指标更换拟合方法。

## 15. 旧输入白名单与新任务迁移：必须有实验专用路径

当前严格支持对象只接受校准对象登记的公共输入及环境绑定。这对历史重现合理，但不能通过以下方式“完成新任务验证”：

- 把旧 0.3743495561 阈值对象的白名单扩成新check输入。
- 为了通过身份检查，将旧 `input_identity` 或 `environment_binding` 改写成新值。
- 在运行时读取check标签来生成新的accepted标志。

新增**实验专用冻结策略评价路径**，复用现有评分与资格函数，不放松原生产/旧记录路径：

1. 使用在cal_new上产生的新映射与阈值；明确这是拟检查策略，不是事先认证的新任务能力。
2. 模型权重、tokenizer、模板、提取器版本、目录和决策目标绑定到冻结策略。
3. cal_new具体输入摘要保存在来源字段；check_new输入单独绑定到预先固定的评价名单。
4. 对每个新输入重新检查源码、token与实际环境，不要求它等于任何cal输入。
5. 输出分别表示 `policy_accepts`、`input_eligible`、`execution_authority` 与证据等级；`policy_accepts=true` 不等于已证明泛化或拥有执行权限。
6. 修复执行只能由本Goal授权的隔离研究控制器启动，不能自动晋升普通 `auto` 默认。
7. 名单外输入、错误策略身份、错环境、错模型或未知关键条件仍拒绝。

这是为了使固定决策能够被真正测试的新研究接口，不是宣布旧严格支持条件已经对新任务成立。旧CLI和旧calibration对象继续遵守其原始范围。[S4]

## 16. 第二次冻结与检查执行

在 `check_new` 预测前固定：

- 代码与模型合同、所有原始基线。
- A/便宜文本的新cal映射与各自阈值，J的原始公式。
- 原rank B2、C2、F、T2具体选择算法。
- 数据名单、修复名单、排除规则、重复方案、指标、费用单位与执行触发条件。

先生成所有方法在所有check任务上的公开输入、原始预测、排序与最终接受决策，保存后再由评价器读取封存标签。

检查标签不能参与预检或在线拒绝；不适用是待预测的结果，不是可提前读取的过滤事实。来源中明确的系统权限冲突可以用公共事实拒绝，但必须与模型弱标签分开。

检查集不要求事先具备“至少三个正例组”才能查看结果；没有正例、接受为零或结构失败，都是有意义的结果。不得以标签不方便评价为理由更换检查集。

检查完成后不得自动重拟合、换checkpoint、改context预算、改K或挑另一条表现好的主路径；旧check也不能补入新cal。

## 17. 指标：明确分母，不靠单个漂亮数字选赢家

### 17.1 主要文本指标

在check_new上分别报告：

- 固定阈值的已知接受精度、已知覆盖、正例召回、未知接受数与接受机制数。
- A原始／校准Brier和log-loss；组宏AUC及可计算的机制数。
- C2实际Top-2的已知不适用比例、UNKNOWN比例、接受项精度、选满K比例和回退率。
- B2/C2、F/C2、T2/C2的集合差异与任务级风险／覆盖取舍。

校准池的接受精度不自动等于最终Top-2精度：原rank的再次截取可能改变被选子集，必须单列最终选择结果。

J另报联合事件预测及任务特定P@2/R@2。没有任务特定正例的任务仍进入P@2分母；其R@2未定义，记录数量，不删除后只报告有利题。

### 17.2 分母与权重

优先复用当前经过核对的机制组加权函数：机制等权，组内父任务等权，父任务内配对等权，已知标签遮罩后按规定归一化。保存一次实际权重和各指标定义。

同时报告未加权原始计数。不能把39已知行、40全配对、4任务组等不同分母交替使用而不说明。

缺少分数的结构拒绝不是预测负例：概率指标只在有分数且有标签范围计算，必须并列披露预测覆盖与整个冻结名单的失败/未知数量。

无人接受时precision为null，而不是1；回退暴露全部技能不能算严格Top-2；UNKNOWN不填负例，已知冲突/不适用与标签不确定分开。

### 17.3 不确定性

使用以修复机制为重采样单位的配对bootstrap描述主要指标和方法差值，同一机制的10技能及全部重复一起保留，不把每行独立重采样。

固定seed和重采样次数，建议沿用1000次。没有接受的重采样必须记录；全部真接受导致零宽经验区间不代表总体精度100%。

本轮小样本只支持有范围的观察。点估计达到0.90不写成“至少90%保证”；不显著不等于等价，CI通过不等于非劣或泛化。

Brier不是纯校准指标，AUC不是准确率；单列校准曲线、排序和实际选择，避免混成一个总分。[E1]

## 18. 何时允许进入真实修复阶段

在第一次协议冻结中固定以下内部触发标准，不在check结果出来后修改：

1. 新cal产生非空阈值，模型、输入规则、环境与决策绑定检查通过。
2. check_new固定阈值的经验已知精度达到0.90，已知接受覆盖达到0.10，至少3个机制、6个已知接受行，未知接受数为0。
3. 实际C2 Top-2选择的已知精度也达到0.90、未知被选数为0；不能只用全部通过阈值的池子掩盖最终集合问题。
4. 预选修复子集中至少2个机制具有真实非空的完整C2集合，其中至少1个与B2实际提供的包不同，才值得开展干预比较。
5. 预选任务具有可信修复资格、隔离资源可用、预测与弱标签记录无完整性问题。

这些是**允许开展有限探索性执行的经验门槛**，不是部署安全认证，也不是独立精度下界已超过0.90。

修复名单虽然事先固定，是否执行整批仍依赖本轮文本检查结论，所以修复结果属于该触发条件下的后续机制验证，不是无条件外部验证。原始check主表应在触发决定之前完整锁定；不得把“触发后执行的少量任务”外推成所有维护任务的收益。

检查不满足时，完成全部离线表、失败分析和公开交付，修复阶段标 `NOT_RUN_WITH_REASON`。不要把最低要求改到刚好通过，也不要再筛一批使C2非空的任务。

通过时不需要用户再次批准，继续V5；不以“这只是独立验证”作为跳过已授权实际执行的理由。

J不参与这个主触发条件。J离线某列较好不能替代A/C2失败后继续启动另一套任务。

## 19. 预选修复任务的资格与防泄漏

修复名单应在看check预测与标签之前准备：

- 固定修复前base、公开问题描述、可信参考修复与目标行为。
- base在目标检查上出现明确失败；同一组检查在可信修复上通过；受保护回归在合格基线上通过。
- 验收需求能从公共问题、接口约定或对应版本文档推导，不能依赖只有裁判知道的义务。
- 候选最终检查在干净base上应用实际patch，确认真正导入候选源码而非系统已修复版本。
- Agent自写测试只能作为补充，不能取代预先固定的可信目标与回归检查。

准备参考补丁的控制器与被测Agent使用不同上下文和目录。技能、仓库记录、Git历史、缓存或搜索工具不得带入未来修复、隐藏测试或其他臂结果。

合法base的目标bug本来就会失败，不是环境不合格；安装、导入、权限失败却不能借“bug存在”算成模型修复失败。

没有合格参考/验收的自然请求可以保留在离线适用性检查，不能拿简化JSON题补充为实际修复。

## 20. 五臂真实对照：一个矩阵，清楚归因

在预先选定的相同4个任务、相同执行Agent和预算上比较：

| 条件 | Agent获得的技能方式 |
|---|---|
| N+ | 完整相同目录的原生渐进发现，不一次塞满所有正文 |
| F2+ | 原fit/dev冻结的每仓库或default固定两个技能 |
| T2+ | 已冻结便宜文本模型按适用性分数选Top-2 |
| B2+ | 冻结原rank Top-2 |
| C2+ | 同B2顺序经过A新阈值过滤，取两个；不足则回退N |

“+”表示五臂的执行Agent获得同一份公开仓库事实摘要、基础说明、工具和权限。N不必与其他臂同K，但它是产品默认对照；F/T/B/C实际非回退时才属于同K比较。

主算法比较C2−B2，实用价值比较C2−F2/T2/N。不同目的分别解释；不能只挑C2赢的一列。

每任务每臂默认2次完整执行，运行顺序按固定随机种子轮换。模型供应方不支持控制seed时记录，不假装同seed保证相同采样。

不能取消中途看起来要输的任务；不能保留多次尝试中的最好补丁。工程启动前故障、已启动超时、策略拒绝、验证失败与未知分开，全数保留。

只在C2发生变化的子集做机制分析属于次要分析，不得取代包含回退、相同集合和失败的完整主表。

## 21. 不新增“无效训练成本”，但要完整记录在线成本

记录以下真实阶段：上下文提取、环境准备/刷新、模型加载、检索/重排、支持评分、集合决定、Agent执行、补丁重建、目标/回归验证。

离线新cal拟合和实验准备是一次性研究成本，不平均摊成看似极低的在线延迟；反之也不要把所有镜像下载成本塞给某个臂。

共享缓存要公平。记录冷启动、暖运行与复用边界；S/B/C如果使用预先计算快照，必须单列其本应承担的路由计算，不能当成免费。

记录实际输入、缓存输入、输出tokens和供应方实际可见用量；缺失为null。没有可信价格或账单时费用未知，不能从Goal token总量推断算法成本。

C2在重模型之后才回退N时，已经花掉的评分开销必须保留。此轮不训练或使用新Gate，不宣称前置门控省成本。

累计任务秒数、单任务端到端时延与并发墙钟时间是不同指标；样本只有几次时不报稳定p99。

## 22. 补丁效果与统计表达

主要补丁结果为：目标检查通过且受保护回归没有新增失败。保存所检查范围，不称全仓库完全正确。

每臂报告成功、失败、未知、未启动，保留所有计划和实际启动分母。未知不算胜负中的失败，也不通过删除它提高成功率。

同一机制两次执行先形成机制级观察；不要将重复调用或JUnit用例数当成独立任务数。报告配对胜/负/平/未知与每任务重复分布。

最终比较即使有点估计提升，也先标小样本真实维护回放；没有足够依据不写稳定增益、生产流量、线上用户采用、统计显著性或泛化保证。

弱标签检查与补丁效果有可能相反。保留“文本看似适用但执行无帮助”“检索不同但补丁相同”等案例，不修改标签来解释胜负。

## 23. 冻结后的错误处理：既不僵死，也不边改边宣称独立

普通安装、网络缓存、进程启动问题，可在原方法、原任务与预算不变时修复并重试，保留失败记录。这不要求另起Goal。

如果发现只是排序无关的展示错误或统计实现算错，可以修复并用同一已锁定预测重算，保留旧错误与更正说明，不产生新模型预测。

如果发现影响输入、标签、模型、阈值、实际可见技能或运行预算的实质缺陷：停止受影响的确认分支，记录已暴露任务和结果；修复后这些题只作后验诊断。不能把改过的方法在同一题上重新跑完再称原独立实验。

新的独立任务不能因为性能不好而临时启用备用名单。真正需要再次独立研究时交付明确原因，不在本Goal内无限循环“换集直到成功”。

## 24. 必须通过的回归

至少覆盖这些行为；测试数不是交付目标：

- cal/check/historical组重复或同源修复拆分被识别；行重排不改变结果。
- 新check标签变化，不影响cal映射、阈值、固定F或预测阶段的选择。
- 预测输入严格排除标签、解释、gold/ref、split与机制ID等非公共特征。
- 没有新cal操作点时仍输出完整离线比较，不能盗用旧阈值。
- 原严格支持拒绝新输入的行为保留；新实验路径只接纳冻结评价名单并验证真实事实。
- 同一模型但模板/context/registry/环境要求变更时，不复用原logits或映射身份。
- A单轴、J双轴监督、原rank排序和C2过滤顺序与冻结合同一致。
- UNKNOWN不当负例，零接受precision为null，组数不被十技能行或重复执行放大。
- C2只有一个合格技能时回退，不用被拒绝技能凑K；回退不能记成K=2成功干预。
- 实际Agent暴露的包与保存选择一致；完整资源保留，不因不同方法改正文。
- 环境未就绪、错源码或无法重建补丁时，分别记录拒绝/未知，不冒充功能失败。
- 纯records/协议检查不加载Torch、Transformers、PEFT；真实模型路径不回退hashing/mock。
- 从干净wheel在仓库外运行新入口，原历史records仍保留旧语义。

至少有一次实际A新输入推理与新校准对象的新进程重载；原输出重载一致不冒充第二批泛化验证。
