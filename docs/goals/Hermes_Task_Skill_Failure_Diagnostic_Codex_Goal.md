# Hermes：任务—技能—失败机制诊断

> **完整 Codex Goal｜研究条件优先，不启动 ASI v3 大规模训练。**
> 本轮只回答：当固定 Coding Agent 遇到真实功能困难时，现有技能库能否提供有用的额外指导？
> 先区分任务难度、技能内容覆盖、候选检索和实际使用问题，再决定下一轮值得训练什么。
> 连续实施，范围内持续授权，不逐阶段确认，不设置固定工程排障次数。

---

## 0. 一页合同：这一轮不是再做一个控制器

唯一主线：

```text
旧 train/dev 的真实失败及技能内容盘点
  → 小规模、按公开规则确定的新开发任务池
  → 固定 Agent 的原生难度探测
  → 决策前可见信息对应的技能知识检查
  → 同状态 N / G / K 的真实续跑
  → 功能差异、普通提醒对照和失败机制解释
  → 决定继续研究任务、技能内容，还是选择算法；本轮不自动进入下一研究
```

三个核心问题：

1. **需要帮助吗？** 原生 Agent 在完整、相同预算下是否真的存在功能失败，而不只是初始源码有 bug？
2. **现有技能可能帮什么？** 冻结技能正文中是否包含与当前可观察困难直接相关、版本适用的操作或检查知识？
3. **实际帮到了吗？** 同状态下明确提供这份技能，相比原生继续和普通提醒，最终功能是否改善？

主比较是实验中**固定选出的现有技能 K**对 **N：不额外指导**和 **G：普通提醒**的功能差异。
K 的选择是开发侧的内容诊断，不是新训练的路由算法，也不保证它是库中真实最优技能。

**本轮不训练任何 gain、wait、LoRA、Gate，不新增动态策略、技能生成器、RL 或完整六臂矩阵。**
可以完成一项有价值的负结果诊断；不能拿“工程全部通过”或“少花了 token”替代功能结论。

## 4. 阶段 A：只看旧开发侧，找出具体问题

读取 v2 train/dev 的 native、collection、任务来源、功能检查和原补丁；不重新运行旧最终矩阵。

至少检查：

- 旧可信原生功能失败，例如已报告的 `sqlite-utils-fix-60811e7`；实际定位后核对，不预设失败原因。
- 两个技能功能退化对照及其真实 no-op 分支。
- 预先按任务 ID 顺序取两个功能持平案例作为控制；不要只看坏例或好例。

每例用一张短表说明：公开义务、实际失败断言、对应源码行为、当时可见错误、原技能及其是否针对问题。
区分：功能代码错误、公开测试/调用方式错误、依赖/基础设施错误、任务歧义、证据缺失。

旧原生失败而后续 no-op 成功，要明确标为**原生恢复或随机性差异**，不能把原失败永远当成技能分支的零基线。
已有记录缺少会话或源码资产时，只作历史诊断，不伪造同状态续跑。
阶段 A 不调用新修复 Agent，不用旧失败的参考修复去制作本轮指导。

## 5. 现有十项技能：检查实际正文，不只看名字

沿用现有目录及实际注入载荷：[S3–S4]

```text
configs/conditional-applicability-v1/skills/
configs/adaptive-skill-intervention-v1/payloads/
```

启动时以实际注册表为准，核对目录和载荷映射。
逐项检查真实来源、版本、正文、固定截断后的指导内容；文件名/description 相似不等于正文包含所需知识。

输出一张十行左右的 `skill-capabilities.md`：

| 内容维度 | 需要写清楚 |
|---|---|
| 使用对象 | 使用某 CLI/API，还是调试/修复它的内部实现？ |
| 实际知识 | 接口语义、数据不变量、失败复现、定位步骤、边界检查等 |
| 版本条件 | 文档年代、源码版本、依赖能力；未知就写未知 |
| 实际载荷 | 原文有而注入片段没有的内容，单列为载荷缺口 |
| 不覆盖什么 | 例如会使用 add_column，不等于讲清迁移回滚的实现错误 |
| 来源强度 | 文档改编、外部工作流、作者补充；不能混称独立官方技能 |

编制时抽查的 `sqlite-schema` 确实是依据版本化公开文档适配的操作技能，包含列/外键等 API 用法。[S3]
**这只是一个来源事实，不代表已证明它对具体修复没有用。**全面内容覆盖要由本轮实际阅读确定。

不因发现缺口而在本轮改正文、重写专家指南或加入第十一项技能；把明确缺失的知识列为后续内容研究输入。

## 6. 新任务池：小、公开、可解释，不只换一批同样简单的题

默认最多 **8 个实际执行的新开发机制**，全部是开发诊断，不设置新的训练/最终测试集。
可先登记最多 12 个公开来源条目，其中 4 个仅作来源/环境不合格的机械备用。
取最先满足公开资格的 8 个；不能因为前面的任务原生成功，就把它从正式池删除并替换为“更难”的备用。

任务类别及顺序在本轮 Agent 结果出现前固定，建议四类各两项：

1. 多接口/多模块行为一致性与错误传播。
2. 参数组合、类型/空值边界与兼容性。
3. 导入导出内容/往返一致性与流式处理边界。
4. schema、事务、约束与失败后的数据保留。

优先使用现有三仓库。若在来源准备阶段确认这些类别的未观察机制确实不足，允许最多一个额外的公开 Python 数据/CLI 仓库：
必须能用现有容器、pytest 和补丁接口轻量接入，不能为它新建测试平台；选择理由在首次新 Agent 调用前固定。
若仍不足，使用真实较小规模，不能拼接多个需求或改写同一故障充数。

不换弱模型、不降低原生预算、不隐藏已有文档/工具、不人为制造错误，不选择“这个技能特别容易赢”的最终任务。
可以按公开机制选择自然挑战；不能声称这些选择代表所有 Coding Agent 业务。

## 7. 任务资格：初始 bug 和 Agent 的困难分开

每个任务具有：公开问题/行为来源、固定 base、明确的任务题面，以及相同版本可运行的目标和保护回归。
初始 base 应在真实功能目标上失败；可信参考或合法实现应通过；至少检查一个来源支持的关键边界与错误行为。

不只验证“文件存在”“命令有 help”或某种参考实现专用命名。
来源存在重大冲突时，在任何 Agent 执行前明确澄清并标衍生题；不能执行完才选更好看的解释。

参考修复与隐藏测试只供验收准备方使用，不进入修复 Agent、技能选择上下文或指导载荷。
若运行时无网络，任务相关的正常公开文档应以同一只读方式供所有分支访问，不能只给 K 私有文档权限。

资格流程不能通过后，只能使用预登记备用并保留剔除理由；不得将基础设施错误称作真实功能困难。

## 9. 原生探测：先固定状态，再知道终端结果

对所有登记任务执行两条独立原生轨迹，使用相同中性分段/续跑机制和总预算。
两个重复都保留，不能第一条成功就跳过第二条，也不能第一条失败就反复抽到失败稳定。

运行时按可见事件登记候选检查点，隐藏终端判分不能决定截在哪一轮：

- 优先第一个与任务功能相关的公开失败/矛盾结果后的已完成轮次边界。
- 没有该事件时，记录首次交付前的 E2 状态，明确它是收尾状态，不冒称功能卡点。
- 两者均不存在时不强造错误；E0 只可作单独注明的任务起点控制。
- 采用已实现的快照和前缀；共同状态至少保留 90 秒原任务预算，不能为达到这一数值补送时间。

90 秒是本轮事先定义的可执行尾程筛选条件，不是收益阈值；任务池执行前可根据已知接口成本固定另一值。
选定后不根据哪个分支赢来修改它。

原生轨迹结束后才运行可信目标与保护回归，输出：

```text
每个任务的 base 资格
两次 N 的 y_functional / UNKNOWN
自然公开错误类型与检查点数量
每个候选检查点的可见状态和剩余预算
原生失败是否有明确的功能结果支撑
```

**公开测试失败不等于最终功能失败；初始源码失败也不等于 N 失败。**三者不得混写。

## 10. 选择诊断状态：失败分层与成功控制同时保留

在开始任何技能分支之前按冻结顺序确定面板：

- 最多取 3 个至少有一次原生功能失败的不同机制，每机制 1 个状态。
- 再取第 1 个两次原生均功能通过、且有合法状态的机制作成功/退化控制。
- 机制选择按预先任务顺序，不按失败严重性、技能预测或可期待提升排序。
- 对机制内的状态，优先使用第 1 次原生轨迹依第 9 节登记的合法状态；没有则第 2 次；不挑哪一次更容易被技能救回。
- 不足 3 个失败机制时不使用更多容易成功的机制填满 4 个状态。
- 没有成功控制时照实报告范围，不能因此把所有失败机制当作总体任务分布。

这是**按原生难度分层的开发诊断**，不是随机总体测试。失败分层的结果必须和成功控制分别报告。
即使条件化选择基于原生失败，后续仍需新的、同状态的 N 尾程参照；不能将用于筛选的原生失败当作永远为 0 的对照。

若全部 8 个任务的 16 次原生运行都通过：完成任务/技能内容诊断，标 `NO_NATIVE_FAILURE_OBSERVED`，不再自动启动整套 24 条尾程。
这只能说明当前池没有观察到终端困难，不能证明整个任务域没有挑战或技能永远无用。

## 11. 建立“任务—可见困难—技能原文”对应表

为每个选定状态建立一张短的 `knowledge-map`，只用该状态之前真实可见的信息：

```text
public_requirement                     # 公开要求
visible_obstacle                       # 当前错误、矛盾或尚未验证的行为
obstacle_evidence                      # 工具输出/源码/公开文档中的具体位置
hypothesized_missing_knowledge          # 假设，不直接当事实
nonknowledge_alternatives              # 搜索路径、测试不足、实现失误、纯随机性等
skill_id / source_version
relevant_actual_payload_passage        # 实际注入片段中真正存在的文字
scope_match: direct / partial / none / unknown
version_match: supported / conflict / unknown
observed_previous_use: yes / no / unknown
```

注意：

- “代码没有正确处理某边界”不自动意味着“Agent不知道相关知识”。
- 没观察到阅读，不等于基础模型没学过；不能读取私有思维链来推断知识状态。
- API 使用说明与内部实现修复是不同层次，但使用说明可能帮助定义预期行为，不能一律判无用。
- 文档正文含某内容，但实际固定载荷截掉了，应分别报告内容库覆盖与实际输入覆盖。
- 此表是有来源的分析假设，不是训练标签，不生成新的几百条弱标注数据集。

## 12. 本轮 K 的选择：为诊断内容，不让旧 Router 再拦住实验

对选定状态，允许分析者在**完整现有十项技能**中选择一份最有公开依据的指导 K。
可以用 Codex 的隔离分析上下文辅助，但输入只包括公开题面、当前可见状态、固定源码/文档和十份技能正文。
不要提供参考修复、隐藏测试正文/输出、后续源码、原生终端隐藏反馈细节或任何分支结果。

若同一协调者已经看过这些答案，应由新分析上下文执行内容选择并保留其实际输入；这只是可见性控制，不宣称双盲或没有模型预训练污染。

选择依据依次是：

1. 与可见困难对应的具体操作、数据不变量或定位/检查方法。
2. 版本与前置条件不冲突。
3. 对当前公开要求具有可说明的针对性，而不只是技能名字相似。
4. 依据相当时按既有 registry 顺序稳定打平。

记录其他候选为何未选，特别是“任务相关但没有对应操作”的情况。
先锁定 K、选择理由、实际载荷和消息模板，再执行任何 N/G/K 尾程。

本轮不运行 gain/wait 预测来决定启动资格，不要求 90% 精度、10% 覆盖或正增益阈值。
K 不是“oracle 最优技能”：分析者也可能选错；报告为“公开证据选定的现有技能”。

可以记录原冻结检索前两项与 K 是否重合，作为检索覆盖诊断；不新增一个完整路由实验臂。
K 不在前两项且观察到帮助，只能提示候选召回可能是后续研究方向，不能直接证明在线路由必然胜出。

若没有任何现有技能具有有依据的适用内容，记录 `NO_SUPPORTED_EXISTING_SKILL`；不随便选无关技能、不临时生成指南。
该状态可以运行 N/G 的普通提醒对照，K 标未执行/无适用载荷，不能记成 K 失败或 K=no-op 的成功。

## 13. 三种续跑方式：只改变额外指导

| 条件 | 当前续跑消息 | 后续行为 |
|---|---|---|
| N | 原共同中性继续消息 | 原生继续，无控制器额外指导 |
| G | 同一中性消息＋已冻结的普通检查提醒 | 原生继续，不追加其他指导 |
| K | 同一中性消息＋第 12 节冻结的现有技能载荷 | 原生继续，不追加其他指导 |

每个有合法 K 的状态三臂各执行 2 次；不足的状态/动作保留分母和原因。
三臂都有继续分析、修改、测试的机会，不让 N 保持旧错误补丁不动。
原生技能目录、工具、文件权限、公开信息可访问范围始终相同；N/G仍可自行阅读技能。

K只使用继承的实际固定载荷，不在前面添加“真正错误在某一行”或额外解题提示。
不因选择了更相关技能就给更强 system 权重，不把文本注入变成新执行工具。
G使用已有一般提醒，不含领域知识或参考答案；记录长度差，不填无意义文字伪造等长。

比较的是“显式提供这段指导”的整体作用，包括内容、注意力和长度的共同影响；小样本正差不自动隔离出纯知识因果效应。

## 14. 同状态与相同预算：继承能力，不重复造平台

复用现有 Session、官方历史分叉、源码/scratch快照与功能验收。[S4,R1]
每组尾程的起点保持：

```text
同一可见对话前缀、已完成轮次
同一完整源码与必要临时状态
同一执行模型、推理配置、工具和正常信息访问
同一起始剩余预算
同一中性续跑和停止规则
```

分叉历史不自动克隆文件系统或隐藏随机状态。描述为“相同可观察前缀下的随机执行对照”。
已经消耗的原生时间不再发给尾程；源码复制、注入和运行开销继续计入原剩余预算。
普通续跑重启本身可能改善结果，因此 N 必须实际续跑，不能拿筛选原生轨迹代替。

若实际可见历史/源码无法恢复：保留历史诊断，标该状态不可执行，不把重新解题冒充同状态。
不能为修复一个状态缺失而扩建新会话框架或修改未公开会话格式。

## 15. 运行顺序、重复与结果释放

在任何分支标签出现前固定每个状态的 N/G/K × 2 名单和运行顺序，使用稳定种子做交错/随机顺序。
避免某一臂总是在热缓存、空闲时间或最新模型配置下运行；实际共享服务波动仍须披露。

保存每次启动、完成、中断和实际输入。已经启动的研究样本不按输赢补采。
工程错误未触发模型采样时可修复同一保留格后继续；触发后中断则保留 UNKNOWN 与原输出，不假称没执行过。

每个状态全部已登记尾程完成后，再做隐藏目标与回归评价。
后验解释可以查看终端错误，但不得反向改变本轮 K、任务、载荷、检查点或重复数。
完成一个状态后即使发现很好的技能，也不能拿它替换后续已经冻结的 K。

## 16. 功能评分：复用 v2，不再定义新的奖励

继承：

\[
y_F=\mathbf 1[\text{有效目标检查通过且保护回归无新增失败}].
\]

普通文件策略违规与时间/token不改变 y_F；裁判污染、非法参考信息或真实运行证据缺失应单列无效/UNKNOWN。
完整原候选在干净 base 重建后检查，不删除额外修改再测一份“更合规”的补丁。

主要对比：

\[
\widehat\Delta_{K-N}(s)=\overline y_F(K,s)-\overline y_F(N,s),
\quad
\widehat\Delta_{K-G}(s)=\overline y_F(K,s)-\overline y_F(G,s).
\]

逐重复保留功能救回、退化、双过、双败和未知；重复只是随机执行编号，不宣称共享隐藏 RNG。
主表必须能还原每份补丁的 target、regression 和 y_F，不只给一个合并“效用”。

若 K/N 两者都成功，不能因为 K 更快就记为功能救回。
若筛选原生失败，但本轮 N/G/K 都成功，记为“续跑可恢复、技能增量未观察”，不是 K 救回。

## 17. 信息/行为跟踪：只收能够支持解释的证据

每状态给出三层事实：

1. **可供指导的内容**：K实际载荷包含什么与困难相关的文字；哪些预期知识缺失或版本不适用。
2. **实际暴露**：该载荷确实进入续跑输入；三臂后续可见技能读取和主要操作。
3. **最终行为**：源代码改了什么，是否纠正了公开要求对应的行为，外部检查怎样判定。

可记录“注入后使用了该API/增加了相应边界检查”作为过程线索；不能据时间先后直接证明因果关系。
不读取私有思维，不逐token监控，不新增大模型自动判分或轨迹摘要服务。

对表面正例还要解释：是领域规则得到应用、测试方法更合适、一般提醒也有效，还是目前看不清。
解释失败允许 `UNRESOLVED`，不能为了面试故事硬认领知识缺口。

## 18. 小样本报告：优先逐状态事实，不制造漂亮置信区间

第一张表应为：

| 机制/状态 | 探测 N 两次 | 可见困难 | K与依据 | N尾程 | G尾程 | K尾程 | K−N | K−G |
|---|---|---|---|---|---|---|---|---|

每个尾程单元显示通过/失败/未知/计划数，不删未知。失败分层与成功控制分开，不合成总体部署成功率。
聚合时先对同状态重复求均值，再按机制等权；不能将 24 条分支当 24 个独立任务。

只有至多 4 个机制、每臂 2 次，主报告给原始计数与观察差；不以不稳定区间或单个救回来认证泛化。
全持平时直接写观察差为0，不把退化 bootstrap 的 `[0,0]`解释成总体等价或零不确定性。
未知存在时给成功率上下界和配对可用范围，不能以已知部分代替全计划。

这轮全部属于探索性开发诊断，不命名为 independent test、benchmark SOTA或学术首创验证。

## 19. 必须给出的诊断结论，而不只是又一次 NOT_ESTABLISHED

| 观察到的情况 | 允许的研究判断 | 不能推出 |
|---|---|---|
| 原生池全通过 | 当前设置未观察到可检验终端困难；停止大分支 | 所有技能无用或所有代码任务太简单 |
| 原生失败，K库内无相应知识 | 存在候选库内容覆盖缺口的来源依据 | 临时生成答案就是算法创新 |
| K比N好，G也同样好 | 额外提醒/继续检查可能足够 | 专业技能知识独有收益 |
| K比N与G均好 | 在指定状态有技能特定帮助线索 | 已证明学习式路由、时机或总体泛化有效 |
| 筛选N失败，重新续跑N/G/K均成功 | 原生恢复/随机性/额外正常续跑解释力强 | 用原始失败作零基线宣称技能救回 |
| N/G/K均失败 | 当前指导未解决困难，可分析内容/应用/推理限制 | 单靠更大控制器就一定解决 |
| K导致原本成功的N失败 | 真实功能退化，需要保留 | 删除“坏技能案例”再训练 |
| 有选择差，但功能全部持平 | 当前可观察决策差没有已测功能价值 | 特征/等待已突破 |
| 运行/判分未知 | 证据不足 | 当功能失败或零增益填充 |

若K效果不佳但载荷覆盖很弱，建议下一轮研究技能内容；若有有依据的有效技能未被原检索召回，可建议候选选择研究。
这些都是后续建议，不在本 Goal 内启动新的训练或新任务大矩阵。

**“信息增益”在本轮仅是有来源的新增指导与行为差异的通俗表述，不是计算了熵、互信息或证明模型内部知识增加。**
