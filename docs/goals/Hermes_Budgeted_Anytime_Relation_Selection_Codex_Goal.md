# Hermes：预算内的渐进式来源关系选择

> **完整 Codex Goal｜主线：先有可用知识包，再把语义计算分配给可能改变选择的关系。**
> 在同一最终索引版本上，完成可续接关系分析、预算化选择及有限真实修复比较。
> 架构与算法优先；复用既有运行器，不新增模型层、审计平台或大规模训练。
> 范围内持续授权、连续实施、不逐阶段确认、不设置固定工程排障次数。
> 本文的算法、参数与实验安排是新设计，不是已实现能力，也不保证功能收益。

---

## 0. 本轮唯一主线

**让来源关系分析成为可按预算停止的选择过程，而不是全部方法必须等待的全量前置审批。**

```text
固定最终全文本索引、公开要求账本和共同候选
  → 立即生成可用的 MMR 包
  → 用已分析关系与未分析关系的区别，定位可能改变知识选择的位置
  → 小批次请求来源关系；有效行立即保存，只续接缺失/格式错误项
  → 在预算内更新选择，随时返回当前包或明确回退
  → 分别完成等尾程预算内容对照、方法自付开销的整体比较
  → 交付功能结果、算法取舍与未确定范围；停止扩张
```

必须回答三个问题：

1. **计算是否用在需要的位置？** 相比完整关系表、固定顺序精查，按决策影响分配查询能否以更少分析保留有依据的选择？
2. **少量不完整输出是否还会拖垮实验？** 缺失关系、语义不确定、明确不相关要分开；N/MMR不依赖H的完整关系表。
3. **算上开销是否真的有帮助？** 在每种方法各自承担额外成本的同总预算下，功能结果是否优于原生或MMR？

主要终端目标仍为**目标行为通过且保护回归无新增失败**。速度、有效JSON比例、查询数和自己的覆盖函数仅为机制/成本结果。

本轮不是新的等待策略。等待的是关系分析结果，不是重训Agent执行中的wait-value；每个任务仍至多一次外部知识注入。

## 6. 第一项结构改造：基线与关系模型解耦

运行器的依赖应当是：

```text
N：共同执行前缀 → 中性继续
M：共同前缀 → 局部候选 → MMR → 继续
A：共同前缀 → 相同局部候选 → MMR保底 → 有预算的关系细化 → 继续
D：共同前缀 → 同池稠密关系参照 → 继续（仅内容对照）
```

N不调用关系模型；M不等待来源关系矩阵，也不承担A/D专属费用。
A失败只影响A的可用状态和实际预算，不自动清空N/M研究格。
共同前缀或可信验收真正无效时仍可影响所有方法，这是不同于“某个方法专属辅助调用失败”的情况。

先计算并保存M包，再开启A关系分析。M是合法检索结果，不冒称它已获语义认证。
A没有获得可用正关系时可以回退M；包完全相同必须标明，不能宣称发生了不同的关系干预。

## 7. 关系表从“完整矩阵”改成“带缺失状态的稀疏记录”

关系对由以下完整输入身份绑定，而不只是requirement_id/unit_id：

```text
base revision + source span/content identity
requirement text/conditions + public ledger identity
semantic model/effort + prompt/schema version
pair-level source context + role constraints
```

最少区分：

| 状态 | 含义 | 可给出的正覆盖 |
|---|---|---:|
| NOT_ANALYZED | 策略尚未请求这一对 | 0，未作语义判断 |
| VALID_POSITIVE | 来源/角色/适用条件合法的正提议 | 固定类别权重 |
| VALID_ZERO | 明确TOPICAL_ONLY或明确不适用 | 0 |
| SEMANTIC_UNRESOLVED | 模型明确无法判断 | 0，但不是判无关 |
| TRANSPORT_MISSING | 请求过，响应没有提供该行 | 0，保留缺失 |
| FORMAT_INVALID | 行不可解析、ID或字段结构不合法 | 0，保留原始行 |
| REJECTED_PROPOSAL | 引用/角色等不支持该提议 | 0，不把它提升成正关系 |

“0覆盖”只是当前缺乏已接受的正支持，不等于这些状态都代表不相关。
不要生成几百条虚构TOPICAL_ONLY来满足完整性。旧严格函数保留给旧入口；新入口返回稀疏表、覆盖统计和缺失列表。
有效但不喜欢的语义标签、明确UNRESOLVED，不属于格式重试对象。
自动校验只能检查引用/角色/结构，不能因此宣称关系语义一定正确。局部证据核对与功能结果仍独立报告。

+0.10\sum_{i\in A}r_i
-0.10\sum_{i<k\in A}d_{ik}

关系权重沿用现有类别：规范支持1.0、验证方法0.7、前提/矛盾上下文0.6、实现上下文0.3，主题相关/不确定不取得正覆盖。

## 9. 用上下界判断“哪里还有可能改变选择”

为每个关系维护计算范围 \([l_{ij},u_{ij}]\)：

- 已接受正提议：相对于这份固定模型提议，取`[a,a]`。
- 已接受明确零关系：取`[0,0]`。
- 未分析、传输缺失、语义未知或拒绝：默认`[0,1]`；不冒称它们真实无关。

只有由固定角色校验逻辑严格排除的类别，才可收紧上界；默认用1更简单、保守。

将F中的a分别换成l/u，得到 \(F_L(A)\) 和 \(F_U(A)\)。
这是**尚未取得关系标签所造成的目标函数不确定范围**，不是概率置信区间，也没有覆盖语义模型自身犯错的风险。

默认最多24候选、4单元，候选子集总数最多：

\[
\sum_{k=0}^{4}\binom{24}{k}=12951.
\]

可以对这些小集合缓存完整序列化token计数，再计算可行集合的上下界；不引入通用优化求解器。
枚举开销也计入A，不允许为了给A“数学保证”花掉全部修复预算。

本轮A和稠密参照D使用**同一集合求解器**；这样A/D的差异来自关系获取，而不是一个用精确枚举、一个用旧贪心。
保留旧贪心结果作为零模型离线诊断，不因此增加真实实验臂。

## 10. 渐进式算法 A：先保底，再精查可能改变决策的位置

### 10.1 初始值

保存M的合法包`A_M`，作为随时可返回的基线。
尚无可用正关系时，不凭空把来源关系优势写成成立。

每轮对已有关系计算：

\[
A_L=\arg\max_{A\in\mathcal A}F_L(A),
\qquad
A_U=\arg\max_{A\in\mathcal A}F_U(A).
\]

\(\mathcal A\)含空集及所有满足token/单元约束的集合。平分按稳定单元ID次序。
A_L是当前保守评分下最好集合；A_U只是最乐观的潜在竞争集合，不是“最可能成功的包”。

### 10.2 关系请求优先级

优先分析A_M、A_L、A_U之间可能改变覆盖取舍的未分析关系。
一个可直接落地的默认启发式为：

\[
p(i,j)=\frac{w_j(u_{ij}-l_{ij})
\left(1+\mathbf1[i\in A_M]+\mathbf1[i\in A_L]+\mathbf1[i\in A_U]\right)}
{\widehat c(i,j)}.
\]

\(\widehat c\)由实际输入/预期输出长度及已观察的批次耗时形成正成本估计；没有历史值时使用统一正值。
不得从隐藏结果、参考修复或后续代码估计这个成本或优先级。
每三个待请求位置中至少一个分配给目前分析最少的高权重要求，避免永远只分析MMR已选单元。
按要求覆盖轮转时仍保留候选完整池，不把未入当前A_U的单元硬判无关。

这是决策相关的查询启发式，不是已校准的预期信息价值、因果信息增益或学术首创声明。

### 10.3 每个批次之后更新可返回包

逐行提交合法结果，重新计算A_L及F_L(A_M)。
若A_L中存在已接受的正关系，且其F_L严格高于当前同矩阵下的M包，可返回A_L并标`PROVISIONAL_RELATION_PACK`。
否则保留M，标`MMR_FALLBACK`或`UNCHANGED_MMR_PACK`。

**不要求先证明A_L在所有未知补全下都最优，才允许实际运行。**否则会重现“又一层资格门禁导致全部回退”。
如果恰有`max_{B≠A_L} F_U(B) <= F_L(A_L)+epsilon`，可单列`RELATION_OBJECTIVE_STABLE`；它仅在固定模型标签与当前候选域内成立，不证明功能正确。

## 11. 如何停止：计算预算，而不是必须补满矩阵

A的关系分析预算默认：

\[
B_{rel}=\min(60\text{s},\ 0.20R),
\]

R是扣除共同前缀及A实际局部准备之后的剩余方法预算。
同时最多请求48个**不同**关系对，默认每批8对；重试/续接的调用与耗时另计，仍消耗同一个B_rel。
最大48对不是对公开要求账本的截断，没查到的关系明确保持NOT_ANALYZED。

以下任一条件可结束关系获取：

- 墙钟截止或唯一关系对预算耗尽。
- 已接受结果使选择在声明候选域内稳定。
- 全部可请求关系已完成，剩余仅为不可重抽的语义未知/拒绝。
- 暂时服务不可用；保留当前结果并采用事先规定的后备路径。

输出必须始终包含当前合法包/无包状态、停止原因、查询数、各缺失类型和剩余不确定范围。
主动停止的稀疏关系策略是一个完成的决策，不因为没有填满笛卡尔积就标“方法未实现”。
全部回退可以运行并如实报告，但不能据此宣称渐进式语义选择已经展示独立作用。

## 13. “可续接”不能偷偷变成换输入、换模型


再次启动时先核对是否仍有活动请求，不能重叠请求同一格。
相同pair但来源文本、前提、模型或提示改变，属于新输入版本；不得冒充旧结果无损复用。

## 14. 计时：成功、失败、重启都不能丢掉阶段成本

在任何外部调用或重计算开始前写入阶段开始记录，结束/异常/取消均在finally持久化耗时。
方法预算由外层计时器持有，不能只靠内部模型成功返回时才写cost.json。
预算型截止包含该方法自身CPU计算、外部请求等待、重试与取消；离线开发排障和其他研究臂排队另列，不能混作方法性能。
记录实际elapsed、timeout上限、取消完成和usage；不能把reported token的缓存/推理子集重复相加。

发生进程崩溃时：

- 有可验证的同主机时钟/监督进程记录，可恢复已花费时间并继续剩余预算。
- 只有明确的超时上界，可按保守上界收费，标`CONSERVATIVE_CHARGE`，不能叫精确实测。
- 时间既无法测量也无法界定，仅该方法的自身预算结果为未知；N/MMR仍照独立预算运行。

不使用事后拍脑袋补数。研究过程中用于人工审阅/不同实验臂排队的等待不混成Agent活跃时间；所有口径提前固定。
无论语义步骤成功与否，时间已经花掉就不能在回退M时退还给A。

## 15. 两种预算协议：分别回答问题，绝不混表

### P：方法自付开销的整体比较——主要结果

原任务总预算600秒，公共前缀成本p相同，各方法各扣自己的在线准备成本：

\[
T_N=600-p-c_N,\quad
T_M=600-p-c_M,\quad
T_A=600-p-c_A.
\]

c包括该方法实际需要的加载/查询/选择/语义分析及注入准备；索引离线构建按本轮明确的warm-index场景另列。
N不为M检索付费，更不为A关系模型付费。
M与A的相同检索步骤可以物理缓存共享，但每种反事实方法按同一已测组件成本计入自身账本，披露物理复用与计费约定。
两次修复重复共享一个冻结知识包时，不能第二次就把第一次线上准备成本当零；本轮固定按相同可复用组件实测成本收费，不能据结果选择摊销方式。

A可能耗时导致剩余修复时间更少，这是完整方法应面对的取舍，不再给它额外赠时。
A超时后使用MMR是“有实际开销的后备策略”，不是纯MMR时间。

### C：等尾程预算内容比较——机制表

同一个公开前缀，M、A、D各自生成并锁定包，所有候选获得相同原剩余尾程预算`600−p`。
准备成本另外展示，不从本表尾程中扣除，明确这是为了隔离内容选择的诊断性条件。
它**不是600秒内的完整部署表现**，不能用本表的通过率声称P中的整体收益。
不通过缩短N或故意压缩一方解题预算制造难度。

两个协议的研究格、补丁、seed、用量和结果分开。即使包相同，也不把一份不同时间预算的补丁当作两次独立实测。

## 16. 稠密参照D：对照信息损失，不成为全局启动条件

D只用于C内容表及离线关系诊断；N/M/A的P表不依赖D成功。
在A已经锁定包和查询轨迹之后，按固定顺序补充剩余pair，形成同一来源池上的稠密参照。
可复用A已接受关系，这使已知部分完全一致；**D是同矩阵的事后补全参照，不是独立一次全量模型采样或人工oracle**。
D新增关系不得回流修改A包、优先级、截止或P表预算。

默认每状态给D最多300秒辅助分析预算，只用于有限机制对照，不从P表的原生时间里扣除。
同样逐批、逐行保存；不保证完整填满。D未完成时记录缺失，不将它称为完整矩阵基准；其专属C格可标不可判定，不阻断已可运行的M/A/N。
D已补齐的有效语义行可以成为离线参照；语义UNRESOLVED仍是未知，不能因传输齐全就称关系真值齐全。
若D所有可用关系无正支持，明确`NO_POSITIVE_RELATION_SUPPORT`，不能伪称完整关系法有效。

M/A/D使用同一来源序列化方式、token上限与最多4单元。D可以与A持平或更差；全量提议不是真值，不把D当功能成功上界。

## 17. 离线机制检查：先确认渐进查询不只是“少做一些”

使用已观察的宏/cache公开状态和最终索引进行开发，不新增旧修复轨迹。

比较三个获取过程：

- **A：决策相关优先级＋要求轮转**。
- **S：固定关系顺序的同预算分析**，结构、解析和后备规则与A相同，只替换查询顺序。
- **D：稠密补全参照**。

为了避免模型不同采样污染纯查询顺序分析，可以在已封存的同一D关系表上做**隐藏表读取回放**：调度器只能按请求揭示关系，其余看不到。
这只验证查询策略、集合目标和选择保持，不能冒称真实线上模型延迟或真实修复执行。
D不完整时只对明示范围比较，不填未知为零以制造完整oracle。
真实在线A调用、离线表读取、故障注入测试三种记录必须分开。

报告预算进展点（如8/16/32/48已请求pair）上的：关系类型构成、可返回包、与D选择差异、F差及未确定范围。
相同功能可能对应不同包，包重合度不是功能质量；更高F也不是修复增益。

## 18. 关键开发反例与一次实际恢复预演

必须验证以下直接问题，不扩成通用平台：

1. 完整要求账本有336对，返回322对时，322个结构合法结果保留，14个状态为missing，而不是整表丢失。
2. 混合有效/格式错误/引用不合法/明确不相关行，分别处理，不能一个坏ID使所有基线不可用。
3. 只续接缺失或格式坏行；有效零/语义未知不可被“修复成正例”。
4. 同一批次已写部分结果后中断，再启动不会重抽已接受结果，不刷新方法预算。
5. 超时取消后返回MMR或当前包；A成本仍保留，N/M预算不变。
6. 不分析的pair仍在账本中；时间到不要求完整矩阵才能结束。
7. 全无正关系、候选为空、预算为零都有真实可返回路径和清楚状态。
8. 精确小集合枚举检查F上下界；所谓稳定只相对于固定关系标签与候选域。

模拟漏行/中断只用于软件测试，不制造真实算法样本。
另外在合法的一个旧开发状态上运行小批真实关系调用并走完保存/加载/续接入口；不训练、不调用修复Agent，不伪造超时。
如果真实调用恰未漏行，故障注入测试已经覆盖恢复逻辑，不要求真的弄坏服务来获得证据。

## 22. 前缀、资料与时间公平

只从检查点之前的来源生成知识包；隐藏目标/保护结果到该相位固定尝试完成后才释放。

## 23. 成本账本要说明“实测”和“归属约定”

最少分开：离线索引、编码器加载、账本/候选、关系获取、集合求解、包渲染、源码克隆、Agent尾程、可信验收。
同一物理预计算被多个方法/重复复用时，同时记录：实际执行次数、用于比较的charged次数、warm/cold假设。
P表不把“各方法独立计费模拟”伪称各次均重新实际调用了同一个辅助模型。
C表不扣预处理只为隔离内容；其额外时间必须公开，不拿C表声称600秒部署收益。

时间中断与计费未知不能抹掉已有功能事实。若预算是否合法尚不可证实，功能检查可单列，但该格不能进入严格P表的同预算效果主张。
超时有真实原候选时仍在干净base验收；没有运行的格不是功能FAIL。
存在合法的执行/时限结束且候选通过，可照实记通过；语义分析少于目标pair数不是功能未知的充分理由。

## 24. 功能评分：继承已分层语义

```text
候选身份/可信验收完整性不能确认 → UNKNOWN
有独立可信且属于公开范围的目标或保护失败 → FAIL
全部必要目标与保护有效通过 → PASS

```

文件合规、来源关系分数、耗时不改变功能标签。

## 25. 结果必须分三张表

**第一张：P整体功能主表。** 每机制、每臂的P/F/U/计划数、实际尾程预算、功能差A−M/A−N及后备状态。
**第二张：C内容表。** 同尾程预算的M/A/D功能差；明确它不计入同总预算总体表现。
**第三张：获取机制表。** A/S/D查询数、已分析/未知/缺失、实际关系时间、停止原因、包差异及相对于补全表的F范围。

A策略包含后备时，主表按预登记策略整体报告，不只挑真正改包的格；同时单列改包/同包/回退，避免把回退成功当语义模块收益。
只有2个机制，给原始计数与缺失上下界即可。未运行、无效预算或未知保留分母；不把退化bootstrap的[0,0]称为总体等价。
D可能错误，D表只是模型关系参照；离线F保持不等于真实功能保持，不能只展示“95%覆盖保留”而隐去功能全持平。
同源弱核对保留支持/反对/未知与模型身份，不称专家人工真值。

## 26. 允许哪些结论，禁止哪些替代

| 观察 | 可以说 | 不能说 |
|---|---|---|
| A用更少pair得到相同包 | 该状态上减少了关系获取 | 已提升功能或全局最优 |
| A回退，功能通过 | 后备策略可交付 | 新语义选择帮助修好了 |
| P表A功能优于M/N | 小样本同预算下观察到方法帮助 | 大规模泛化、显著性或首创 |
| C表A优于M但P无优势 | 内容线索未抵偿整体开销 | 已建立部署增益 |
| A/D包不同但均通过 | 当前功能比较持平 | 稀疏关系不会损失任何知识 |
| 关系模型失败但N/M正常完成 | 方法专属故障已隔离 | 所有方法都UNKNOWN |
| A少分析后更快，功能都持平 | 效率/可用性改进、功能收益未建立 | 用成本替代功能突破 |
| 全部任务通过 | 当前小型验证没有区分力 | 所有技能永远无用 |

不根据结果自动继续ASI v3、训练控制器或寻找更多能赢的题。完成当前研究后停止。
