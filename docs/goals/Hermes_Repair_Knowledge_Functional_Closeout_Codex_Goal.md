# Hermes：简化知识选择的真实功能干预与阶段收束

> **完整 Codex Goal｜将 PR #55 的 R 接回真实 Coding Agent，用 N／MMR／R 回答功能价值问题。**
> 不新增选择算法，不再建立关系评分大矩阵，不训练模型；复用既有运行器完成有限真实修复。
> 范围内持续授权、连续实施、不逐阶段确认，不设置固定工程排障次数。
> 本文规定的是待实施研究。它不保证 R 获胜，不宣称既有知识包更好，也不授权合并或发布。

## 0. 唯一目标和停止边界

**在相同可观察执行前缀下，检验现有 R 知识选择管线，算上自己的准备开销后，是否比原生继续和局部检索＋MMR带来更好的真实功能修复结果。**

```text
冻结公开任务与当前方法
  → 每个任务生成一个公共执行前缀
  → N：中性继续
  → M：任务局部检索＋MMR
  → R：同候选＋逐要求关系查询＋既有知识包选择
  → 原执行 Agent 实际续跑，捕获完整补丁
  → 在干净 base 上用可信目标及保护回归验收
  → 报告胜／负／平／未知、成本、实际知识内容与限制
  → 整理简历可用事实和面试案例，结束本阶段
```

主要比较为 **R−M**，次要比较为 **R−N**。功能指标只有目标行为与保护回归；关系计数、覆盖分、文件合规、耗时和 token 均不能替代它。

本轮应完成真实尾程和验收，不以关系输出、模拟执行、CI 通过或新的规划文件充当完成。全部持平、R 更差、全部回退，也可以成为完成后的真实结果；不得为了得到正例继续换题、调参或扩大矩阵。

“阶段收束”指结束当前开发主线，不代表正式产品发布、项目永远不再更新或已经取得论文级证据。

## 2. 本轮对上一条讨论作出的两项明确细化

**第一，固定 R 的实际含义。** 本轮沿用“R 查询关系，再由既有选择器形成包”的真实链路。不能临时把 z 直接当知识覆盖权重，写一个免关系模型的 Top-K，然后借用 PR #55 的名称或证据。这样的版本属于另一个算法，不在本轮范围。[S3]

**第二，M/R 同包不作为删题条件。** 上一条讨论提出可优先关注不同包的任务。正式主表若只保留不同包，会变成条件化的分歧子集研究，不能代表预登记方法整体效果。因此本轮先按公开机制和资源资格确定任务，之后即使同包、回退、无明显新增资料，也保留该任务和方法分母；另报分歧子集即可。

同样，不以 N 首次失败作为入组条件；不能从后续结果挑选“可被 R 救回”的题。

## 4. 范围锁定：不做新的方法研究

不改变索引准入、要求账本、特征系数、关系类型权重、包求解器或来源正文来追求胜负。不改用更弱的执行 Agent，不隐藏正常源码/资料，不减少原生预算来制造困难。

可以修复阻碍当前实验的真实接线、计时、线程隔离和验收重建错误。发现会改变方法含义的问题，保留原版本并明确报告；不能无声扩展研究目标。

## 5. 三臂的精确定义

| 臂 | 运行方式 | 在线额外工作 |
|---|---|---|
| N | 固定中性继续消息，不额外注入知识包 | 必要的公共续跑准备 |
| M | 公共状态 → 同版本任务局部候选 → 现有 MMR → 原文知识包 | 局部准备、检索、MMR、渲染 |
| R | 与 M 相同状态/候选 → PR #55 R 关系查询 → 既有关系校验和集合选择 → 原文知识包或MMR后备 | M 的共同准备，配对特征、有限关系获取、选择与渲染 |

R 的配对软分固定为：

\[
z(r,u)=0.50\,v(r,u)+0.20\,b(r,u)+0.20\,s(r,u)+0.10\,c(r,u),\qquad p_R(r,u)=w_rz(r,u).
\]

沿用每第三个请求位置的要求轮转和固定平分规则。软分只决定先查询谁，不写入正关系、不收紧未知范围。[S3]

沿用 PR #55 的最终批次启动修复、现有 CostEnvelope、关系提示及校验。每批是新空线程；不用完整来源核对 J 来决定运行时包。只有真实获取的合法关系进入旧集合目标，不能预装旧参考表。[S4]

最终包使用既有求解器与原系数；R 无可用改选时执行 MMR 后备并保留费用。R 与 M 内容相同，也不能省略该臂或声称发生了新的内容干预。

**R−M 比较的是这一整条知识获取/选择管线的增量作用，包括关系模型及成本，不是单独证明 `w*z` 排序的因果收益。** 本轮不加内部消融来拆它。

## 6. 模型、资料与信息权限

执行与关系模型沿用已记录的 `gpt-5.6-sol / medium`，运行器沿用已安装且可验证的 Codex CLI `0.154.0` 和既有 Docker 环境；编码器沿用冻结 MiniLM 快照。[S4]

这些是既有研究身份，不是要求“升级到最新产品”。开发编排模型可以是用户当前 Codex 模型，但不得静默替换被测执行模型或关系模型。启动时核对真实可用性；不可用先恢复合法已有环境，不能自行换模型继续宣称同方法比较。

所有臂拥有相同正常源码、仓库说明、原生技能目录、公开测试和合法资料读取权限。N 的“不额外提供”不等于禁止其主动查看文档或技能。

使用最终内容准入索引；本轮按 **索引已就绪的 warm-index 场景**比较。离线索引构建时间另列，不宣称冷启动、生产吞吐或官方benchmark分数。

参考修复、隐藏目标/保护测试及其他分支结果只在可信验收侧可见，不进入要求账本、知识构建、R、关系模型或任何修复 Agent 的输入。

## 7. 任务规模：默认4个机制，冻结前最多6个

默认 **4个公开维护机制，每臂2次续跑**。只有在模型实验尚未开始、资源与任务资格均已确认时，才可以一次性预登记为6个；不得看到4个的结果后再扩到6个。

优先恢复已有合法任务资产及其公开来源。可从已有数据源恢复新的公开实例，但不新增benchmark平台、仓库生态或大范围任务搜集。先枚举现有候选，依据下一节的公开机制资格固定有限候选队列。

任务机制优先覆盖不同的行为条件，例如数据保持/缓存语义、边界条件传播、跨函数状态或类型兼容。它们是选题类别，不是对具体任务难度或技能效用的预判；不要按照题目名字自动判定。

尽量含至少2个尚未用于本项目方法开发的机制；若已有资源不满足，可以使用已观察任务，但明确全部为探索性复用，不能假称新盲测。不要将“凑够未见题”变成新项目。

宏/缓存允许作为历史对照使用，不强制再次选入；最终名单由公开资格和预登记顺序决定，不能因为过去通过或失败而入选/淘汰。

## 8. 冻结任务的方法：公共资格、确定顺序、保留同包

先生成 `task_roster.json`。对每个候选记录来源、公开需求、base、机制类别、既往使用情况及资格理由。源标识排序后使用固定种子 `20260924` 排序；每个机制族优先只取一个，避免把同一bug的近重复变成独立任务。

公共资格至少包括：

- 公开需求明确描述功能变化，不只有精确文案、代码风格或纯文件移动。
- 能指出实际行为条件、状态转换、不变量或跨调用关系；不能依据参考补丁大小、一行/多行或隐藏答案选题。
- 合法 base 的资料范围内存在可检索的相关实现、文档或公开测试。这里是可观察内容依据，不要求它必然含有答案，也不要求新关系模型先返回正标签。
- 环境、完整原补丁重建和可信验收在现有基础设施内可运行。

可信验收侧可核对 base 暴露目标问题、参考修复通过、保护检查有效；只向任务选择侧返回资格和非泄漏原因，不提供修复方案。资格通过仅说明测试有区分能力，不证明 Agent 会失败，更不证明 R 有用。

先确定有限候选队列，再按资格取前4个；不足则按实际较小范围继续，不能无限找题。最多额外保留2个**冻结前**资源备用项。正式公共前缀开始后，不因结果、同包、回退或无法产生“好案例”启用备用项。

**不先跑原生终态筛难题；不按 R/M 包差异、Q/J 正例数、后续胜负筛选主表。**

## 9. 验收预检只修本轮必需问题

在新 Agent 运行前，核对每个任务的公开合同、固定目标和保护集合；特别关注历史上出现的无依据文案、输入类型优先级和未执行后置断言。

目标测试应覆盖公开要求中的关键条件，保护测试应检查合法范围内原行为。错误拒绝类任务要测错误类型/类别及拒绝后数据或结构保持，不能只认一段任意固定字符串。必要的差异必须来自公开需求，而不是参考补丁的实现习惯。

允许在冻结前修复少量明显的测试接线或无依据断言，并在所有臂使用同一版本。只返回资格摘要；不让选择器看到隐藏断言或参考代码。

如果任务需要大规模重写可信合同，按预登记资源资格记不可用，不把本轮转成裁判开发。所有资格失败仍留在候选队列说明中。

## 10. 在正式前缀前完成一个薄适配预演

复用已观察开发状态和已有最小资源完成接线，不生成新的开发修复样本，不开启参考Q/J面板。

检查：从状态恢复候选，M实际生成合法包，R按最终修复版启动规则完成一次有限来源获取或合法后备，续跑入口能接收绑定的状态/包/费用。

必要的真实关系预演最多使用一个旧开发状态的一次60秒获取；不能因为没有正支持就反复预演。由此取得的语义行不预装到正式 R 中。软件故障的修复可以继续，所有新增调用另记成本，不计成正式实验收益。

针对真实例外做小测试：多pending时不能以 singleton 绕过规则、47/48额度边界不越界、方法费用不会被退还、未知关系不被改零、N/M不依赖R完成。

预演结果可以是全零或回退；这不阻止正式功能对照。它验证的是入口和合同，不是先保证新方法有效。

## 12. 公共前缀：一次产生，不反复抽有利状态

每个任务只生成一个新的无外部干预公共前缀，所有臂及两次重复均从它分叉。使用既有 `early_checkpoint` 的固定自然边界规则，优先第一次完成轮次中的公开需求相关源码读取或测试观察；不由 R 判断何时最有利。

禁止为获得失败状态人为注入错误、截断必要资料、修改初始仓库或反复重抽前缀。固定600秒总方法预算从本次公共执行开始累计。

若 Agent 在首次可停边界已基本完成，照实记录 `terminal_at_boundary` 或可见完成状态；不能把它换成更难前缀。只要合法可续跑，就仍纳入对照；结果可能暴露任务缺少区分力。

无法取得可恢复前缀时，该任务计划格保留未运行及原因；不要发明状态来补齐。

官方 thread/fork 复制的是会话历史；文件系统、源码、scratch和剩余预算由已有运行器绑定。核对本机实际版本接口，不假设最新文档的所有字段都能使用。[R1]

## 13. 同状态比较必须实际满足的条件

每条分支使用同一截止前的可观察历史、源码及scratch快照、执行模型、推理设置和工具/资料权限。每条运行在独立副本中，不读取其他臂的修改和输出。

未来信息不得进入状态：隐藏验收、参考修复、其他尾程的补丁/成败、后验来源核对结论均不可用。

不能仅重新发送同一道题就称“同前缀”；不能恢复同一会话却忘记复制文件；不能保留已经开始的未来turn。只在既有可核对完成边界分叉。

两次重复共享公共前缀，但后续模型随机路径可以不同；重复编号不代表同RNG。描述为**同可观察前缀的成对实验**，不宣称单次胜负就是精确个体因果效应。

前缀相关性意味着独立机制数为4（或冻结的实际数量），不是24。

## 14. M与R共享候选，R每个重复从空关系表独立运行

每个任务将既有完整账本、合法base索引和公开状态生成的候选冻结。M/R同候选ID、顺序、正文、角色、源版本、tokenizer、MMR、渲染；不能给R额外私有根因说明。

候选含旧实现时保留其角色说明：它展示现状，不保证满足新要求。不能将当前补丁或参考修复回填到知识库。当前 Agent 的diff可以作为可见状态输入，但不伪装为修复前规范。

M可以共享一次确定性的候选准备和MMR物理计算；比较账本按同一实测准备费给每个对应方法/重复记账，并说明复用。

R的**每个任务每次重复独立生成关系**：从空store开始，不复用另一重复、另一策略、旧Q/J或已知成功R包。默认4任务×2重复＝8条新的R获取轨迹，之后分别驱动对应的8条R修复尾程。

这避免“挑上轮最好的R包续跑”。只允许相同本次获取内部的合法缺失续接；有效正/零/语义未知不反复抽到有利。

关系获取可先完成并锁包，再启动该任务对应的尾程；不需要所有任务关系齐全。N/M绝不等待某份完整关系矩阵才被允许执行。

## 15. 知识包是什么，必须讲清楚

M/R载荷统一采用原文片段、路径、版本和角色的既有渲染方式，总计至多1200 tokens、最多4单元；预算包含相同封装。不能截掉否定、前置条件或关键分支以凑长度。

载荷不包含关系模型的自由修复方案、编辑指令、参考答案、胜负预测或“此包已验证正确”的保证。来源关系用于选择，不作为额外的解题计划免费注入。

记录实际内容角色：规范说明、公开测试/验证模式、前置条件、相关实现、主题上下文。实现上下文允许入包，不能一律判无用，也不能说它证明需求已满足。

来源可见性至少分为：`already_visible_in_prefix`、`not_observed_in_visible_prefix`、`visibility_unknown`。不在可见前缀不代表基础模型不知道，更不意味着N不能自行检索到它。

在模型实际输入中确认知识正文出现；目录有文件或“selected=true”不等于已注入。确认失败时保留原尝试、实际输入和可用补丁，不自动重跑新样本。

## 16. 一套主预算，避免再次混成两种实验

本轮只有**方法自付开销的600秒整体比较**，不默认增加上一轮的等尾程C表：

\[
T_{t,a,r}=\max\{0,600-P_t-C_{t,a,r}\},\qquad a\in\{N,M,R\}.
\]

`P_t`是公共前缀实测费用；`C`是该方法的在线准备。N不为检索/关系模型付费，M不为R关系获取付费。R继承M的共同局部准备，并额外计入配对特征、关系调用、求解与渲染。

前缀、源码副本、初始化等费用不得漏计或双计；记录当前运行器已收费字段，再接入额外费用。离线索引单列，不能重复扣费或当作免费冷启动。

与上一轮不同，本轮将为方法需要的编码器初始化、特征准备和公共候选准备补齐前置计时，不借用旧缺失数字。共享的物理预计算记录一次，反事实方法账本按相同实测组件记账；关系获取每重复独立实测。

每条R的完整方法预算包含失败、格式续接、取消和后备成本。不能发现R需要时间更久后调低N/M预算，不能回退MMR时退还R费用。

时间口径沿用已有活跃执行/方法时钟，跨实验排队和人工审阅等待单列。关系模型的服务响应等待属于该方法成本；账单未知就留空，不从token猜金额。

若关系分析花光剩余预算，验收已捕获候选（包括前缀候选），如实记录；不是额外赠送一个600秒尾程。服务错误和预算合法性未知与功能标签分开，不能一律伪装成语义失败。

## 17. 每格运行与失败处理

主矩阵按冻结种子在每个任务与重复内交错N/M/R顺序。R的来源模型独立于修复分支，不能看到先运行的N/M输出。所有方法结果结束前，不向方法开发上下文释放隐藏功能分数。

所有分支接收同一句中性继续消息；M/R再追加同层级知识块。不要给R增加“请务必检查正确”等专属提醒。

每条尾程最多一次显式知识注入；Agent原生自主使用技能不受额外限制。R失败时默认使用当前合法MMR包继续，保留`fallback_reason`、已经花费的时间和实际载荷。

一个臂不可用不阻断其他臂。真正共同状态/验收不可信可影响同任务全部臂，但必须区别于R辅助模型局部故障。

研究格开始前可修复安装等工程错误并继续。开始后中断优先恢复同一会话/候选和剩余预算；无法恢复，保留该格及未知，不重新抽一个结果覆盖它。不得“多跑一次选更好补丁”。

普通工程排障持续授权；实验样本次数不随着排障自动增加。

| 阶段 | 默认4任务 | 冻结前选择6任务时 | 说明 |

| 新公共前缀 | 4 | 6 | 每任务一次 |

基线/参考修复资格测试和重建验收不计成修复Agent样本，但须记录实际工作。没有资源时按已固定任务的实际范围交付，未做项保留，不额外增加来源核对矩阵来充数。

## 19. 可信验收：只回答功能，不让合规再污染标签

每格捕获完整原候选，在干净base重建，安装同一可信overlay，执行固定目标与保护集合。保留候选自改测试与可信测试的边界；不得只运行Agent自己写的测试。

继承现有完整重建能力及必要权限sidecar：Git patch未表达的合法模式信息，应绑定原始capture恢复，不能删除不利文件再验收。只复用现有实现，不开启全平台文件系统项目。

功能标签：

```text
候选身份或可信检查完整性无法确认             → UNKNOWN
存在独立有效、属于公开范围的目标或保护失败     → FAIL
全部必要目标与保护有效通过                   → PASS
其余                                       → UNKNOWN
```

文件policy不进入上式。若policy直接阻止测试，以未取得功能证据记录，而不是将违规自动转换成功能FAIL。合法隔离仍保留，不能为得到分数执行不安全的任意候选。

测试跳过、没收集到、环境崩溃、意外导入旧版本不是PASS。超时但有原候选时仍可验收；不得因为没有“完成”措辞就忽略可检验代码。

单个歧义断言不自动抹掉另一个独立可信保护失败。功能结果、预算有效性、协议偏差、方法后备四个维度分别保存。

## 20. 不再用大规模“裁判修复”拖延主线

功能采样前尽量完成资格与overlay预检。采样后发现测试安装/权限重建问题，可在同一Goal修复恢复原候选，用同一可信检查重验，保留失败记录，不增加Agent样本。

若发现真正的验收语义问题，先保留原判分和受影响范围；只做有公开依据的最小、臂对称后验复验。新结果单列 `POSTHOC`，不能替代冻结主表，也不能将更正后的分差冒充独立确认收益。

算法、包、题面或成本口径若在采样后变化，旧结果绑定旧执行版本。不要为了“最后一次全绿”反复重跑所有格。

无法有限解决的外部阻塞记UNKNOWN，继续其他合法格并交付。保留未知不是已经证明R失败或成功，也不是授权启动下一轮审计。

## 21. 只生成三张核心结果表

### 表一：功能主表

每个任务、每臂列 `PASS / FAIL / UNKNOWN / 计划数`；附实际预算有效性、协议偏差。给出R−M、R−N的任务级均值差及胜/负/平/未知。

每任务两次已知结果全有时，可以用通过比例比较任务级结果；未知不按0或1填，另外给最坏/最好缺失界。重复编号配对的胜负可列，但不宣称共享隐藏随机数。

按任务/机制等权，不让一个题的测试用例多就权重更高。4–6个任务只给原始计数和清楚限制，不制造总体显著性、可靠p95或退化bootstrap等价结论。

### 表二：实际干预与成本

至少包括公共前缀时长、M/R共同准备、R独立获取、包token/单元、与MMR是否相同、注入观察、剩余尾程预算、实际耗时、后备原因。

主表按预登记策略整体报告，包括同包和后备；分歧/非回退子集只是描述性附表。不能只统计R真正改包的成功格。

### 表三：知识—行为案例

对每个任务记录公开要求、M/R实际来源、角色、前缀可见性、后续可观察读取/代码变化与验收结果。不会强制每题写长报告，优先展示差异最大的真实胜例、退化或持平各一个。

没有R胜例就用持平或退化案例解释，不编造救回。单次分支差异叫“观察到的救回/退化”，不称已证明知识是唯一原因。

## 22. 结果如何解释，不再保证任何方法获胜

| 观察 | 允许结论 | 不允许结论 |
|---|---|---|
| R在相同预算下胜过M/N | 小样本条件下观察到R整条管线帮助 | 广泛泛化、论文SOTA或所有模块均有效 |
| R/M同包且都通过 | 同内容和不同准备成本下的结果 | 关系模块救回了任务 |
| R与M不同包，但功能持平 | 选择发生作用，功能优势未建立 | 更高覆盖分证明更好修复 |
| M与R都胜过N | 额外检索/指导可能有价值，R是否必要另看R−M | R的要求级算法已单独胜出 |
| R输给M | 当前R没有理由替代MMR，保留退化原因 | 自动改R系数或任务直到胜出 |
| 全部方法通过 | 当前有限任务缺少功能区分力 | 所有技能永久无用或总体完全等价 |
| R获取失败但后备成功 | 含成本的后备策略交付 | 新语义包改善功能 |
| 关系更多/包更短/更便宜 | 次要机制或效率观察 | 本轮功能突破 |

因默认没有G，R−N胜出也不能单独区分“特定知识”与“额外提醒/关注”的全部贡献。R−M仍可能来自整个关系获取/组包链，而不只是一个排序系数。

保留负结论，不再自动开展新的等待、gain、训练或功能矩阵。
