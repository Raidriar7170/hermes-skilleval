Diagnostic Artifact Drift Check

archived

一句话结论

本阶段补上 semantic drift check，让 committed diagnostic demo artifacts 可以和临时重新生成的 artifacts 比较，同时忽略 generated_at 和本地 artifact path display 这类允许的 volatile 字段。

项目阶段进度

当前阶段目标是 interview-ready / release-evidence packaging：README 的 For Recruiters / 3-minute review path 和 Phase 16-18 release evidence chain 是来源。本阶段把 diagnostic onboarding demo 的再生成一致性补成可验证证据，减少面试或 review 时“demo artifact 是否可复现”的缺口。剩余 gap 主要是是否把 drift check 接入 GitHub workflow 或 PR automation；这会改变 CI/workflow 边界，需要用户确认后作为单独 OpenSpec 阶段处理。

本阶段改动

  • 新增 skilleval diagnostic-artifact-drift-check，比较 expected/actual artifacts 或目录。
  • 对 JSON artifacts 递归忽略 allowlisted volatile fields 和本地路径显示差异，对 dashboard HTML 比较嵌入的 diagnostic payload。
  • 文档改为先 regenerate 到临时目录，再通过 drift check 对比 committed demo。
  • 保持边界：这是本地 semantic artifact drift detection，不是 release approval、PR automation 或 runtime router。
