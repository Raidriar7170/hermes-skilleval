为什么需要 successor

旧实验在不完整的 Round-1 生成阶段终止：第一个 Generator 响应暴露了 16 个候选，后续 exact-host 请求因历史 strict output schema 不兼容而失败；在数据集构建、Reviewer、评分和正式评估之前即停止。历史 Generator schema 的嵌套 const 缺少显式 type，历史 Reviewer schema 还包含未显式类型化的 enum/const 与 provider strict subset 不接受的条件组合。

本阶段没有修补或重解释旧 schema；它建立了版本化 successor schema、递归 fail-closed validator、一次性 synthetic canary 和新的公开收据。

实现与隔离门

  • 所有 const 与 enum 节点显式声明兼容类型；对象闭合并全量 required；递归检查 properties、items 与每个 anyOf[index]。
  • 拒绝 allOf、oneOf、not、if/then/else、$defs、minLength/maxLength 及未知或畸形 keyword 值。
  • 公开入口不接受 private root、repository root、host probe 或 launcher 注入；公开收据目标在 host 调用前检查为 absent、非 symlink。
  • 实际 argv 直接执行 hash-pinned resolved binary；每个角色 process 前后复核 binary authority。
  • JSONL 事件必须严格按 thread.started → turn.started → items → turn.completed 排序，只允许 reasoning/agent_message；每角色恰好一个 final agent message，其 canonical JSON 必须等于 response，三个 thread ID 必须互异。
  • launch_attempt_count 与确认启动的 process_count 分开记录；不可用的 tool/process truth 使用显式 null/status，不伪造为零。
