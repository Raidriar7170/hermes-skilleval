# ASI v2：功能增益与同状态机制复盘

当前为研究执行中的架构说明。最终矩阵、共同状态面板和延迟对照尚未全部完成，以下设计与训练证据不构成功能、表示或等待收益的证明。

## 功能信号：学习相对原生继续的修复差

`functional_outcomes` 只用可信目标检查与保护回归生成 `y_functional`；文件策略和成本另列。`functional_collection` 复用已有执行会话，在完成轮次边界保存可观察历史、源码、scratch、候选正文和剩余预算，分别真实继续 no-op、技能与普通提醒。`functional_pairs` 将同一前缀、同一登记重复下的技能结果减去 no-op；未知不补零，失败与退化不丢弃。

已完成 192 条 train/dev 尾程，191 可评价、1 未知；96 个技能对照有 92 持平、2 退化、2 未知，没有救回。实际训练与独立重载已经完成，但开发增益标签全为零，两套学习模型均不优于零基线。这里证明存在少量动作差异且模型实际拟合过，不能据此说学会了功能救回。数值与原始凭据见 [训练诊断](learning-diagnostic.md)。

## 同状态归因：固定候选后比较动态表示

`functional_features` 与 `functional_learning` 训练独立的 full、task-only 模型；task-only 保留任务、仓库、阶段和预算，去掉动态错误、源码变化与进展。两者使用相同检查点生成的同一候选清单及实际载荷，不能通过重新检索改变比较对象。无等待的 myopic 使用 full 的同一增益权重。

端到端六臂会走出不同自然轨迹，因此最终修复率差只能描述策略整体差异。`functional_panel` 另从预定 N0 第一重复选择公开检查点，在结果出现前锁定共同候选、各模型预测与动作，然后执行同状态动作表。表示证据分为特征实际接入、动作是否改变、预选动作的功能结果是否改善三层；前两层不替代第三层。

## 等待有效性：真实继续到分支自己的未来

等待目标采用任务族留出的功能增益估计，成本与文件策略不进入训练。full 比较当前正增益与非负等待值；只有等待阻止了当前正增益动作，才属于等待影响决策的条件子集。

机制对照保留 NEVER、NOW，并执行 DEFER_SAME 与 WAIT_THEN_FULL：前者延后注入同一份技能，后者允许冻结 full 策略依据本分支后续公开观察选择。两者都从当前状态真实继续，不跳到保存的未来源码，也不增加原任务预算。前者检验固定内容下的时机，后者同时含后续适应，不能混称纯时机效果。若等待敏感子集为空，报告不可识别，不把等待次数当成收益。

## 结果边界与交付

`functional_evaluate` 顺序执行 matrix、panels、delays，全部完成后才由 release 统一进行隐藏验收。`functional_report` 保留计划、已启动、可评价与未知分母，报告全计划成功上下界、任务均值和任务族区间；政策合规、token 与时间只进入附表。相同可观察前缀不等于克隆隐藏随机状态，少量公开历史任务也不能证明不存在预训练污染。

最终必须分别填写功能、表示、等待结论以及研究执行状态；当前这些最终结论仍待冻结实验完成。默认策略保持 `KEEP_EXISTING_DEFAULT`，旧研究记录保留。方法设计贡献不等于学术首创或已验证有效。
