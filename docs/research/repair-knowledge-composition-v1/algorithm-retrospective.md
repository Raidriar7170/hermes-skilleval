# 一页算法复盘：维护知识与缺口组合

本轮研究把“给Agent补什么资料”拆成可检查的来源、内容和选择三个问题。最终功能结论见 [results.md](results.md)，以 H 对同知识库 M 的比较为主；以下函数分数不能替代修复效果。

**旧技能与内部维护约束为什么可能错位？** 旧十技能提供通用工作方式和API资料，而新题包含Ansible内部映射、参数校验及执行状态兼容等要求。这是公开题面与资料内容的层次差异；它不证明旧技能导致失败，也不证明更多内部资料必然有用。历史六补丁的后验验收是独立附录，不能当新方法救回证据。

**单元多表达了什么，是否写成了答案？** 每个base用同一个无任务输入的构建器生成最多40个维护片段，保留完整条件、适用符号、依赖、仓库版本与逐行引用。文档契约和当前实现分开标记；当前guard只是观察，不升级为正确规范。10个base共400单元通过冻结身份与源码原文核验。构建器没有读题、参考修复或隐藏测试，也没有模型生成“修复建议”。代价是覆盖有限：固定组件轮转不保证选到当前问题的关键约束，未覆盖的事实不会手工补成答案。

**H与MMR实际差在哪里？** 两者共享公开状态、24个候选、正文、消息层级和1200 token预算。M以0.7相关性减0.3最大已选相似度选择；H最大化逐要求的最佳覆盖，再加相关性、减成对冗余与可见重复，以正边际/token贪心并比较最佳单项。要求权重依公开状态确定，暴露只表示可见输出重合，不表示模型已经理解。H不宣称全局最优或经典单调子模近似保证。

例如第一个固定状态 `empty-keyed-group-naming/E2`：M选 `[0,2,1,3]`、1195 token；H选 `[19,3,0]`、696 token。在H函数下，M为 `0.245454 + 0.225600 − 0.231493 − 0.016750 = 0.222810`，H为 `0.255317 + 0.148651 − 0.095205 − 0.002083 = 0.306679`。H选到fact-cache初始化、debugger参数校验与配置类型转换的源码片段。它们有真实出处，却不等于本题分组命名的关键知识；较高自定义覆盖值尤其不能解释为更好的修复。

**选择变化是否带来功能变化？** 固定开发设计为8条原生、40条N/G/L/M/H尾程及8条消融，先锁定全部载荷再释放功能验收。功能只取目标行为与保护回归，UNKNOWN保留。实际完成56次研究执行，三个可判定机制的N/G/L/M/H均2/2通过、H−M各0。第四机制因公开合同未确定0/False分类而统一UNKNOWN；四机制总体差异不计算。v1/v2原始验收及保护失败完整保留。继续证据判定UNRESOLVED，确认未执行；不能把选择变化、短包或高函数值当收益。

**覆盖与重复惩罚是否必要？** 第一个状态H-no-gap选 `[5,22]`，H-no-exposure选 `[19,21,3]`，因此两项都确实影响选择。去掉暴露后加入候选21，其公开输出行重合率为0.5；这只是可见暴露度。实际消融中，第一个状态各臂均2/2通过，第二个状态因合同歧义不可判定，因此两项均只报 `DECISION_ONLY`。H超过M的收益 `NOT_ESTABLISHED`；MMR在三个可判定机制上并列，不用成本或引用分数改写主结论。

边界：一个仓库、四个开发机制、每格两重复；三个固定点为E2、一个为E1，不能推论更早干预或未见仓库效果。无新gain/wait训练，默认策略保持不变，无首创或部署收益声明。
