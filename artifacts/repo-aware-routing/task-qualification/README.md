# Public repair qualification evidence

This is qualification evidence for the repo-aware pilot, not Agent success or
algorithm utility. The initial 20 candidates were selected before Agent outcomes.
One final-test candidate failed reference qualification on SQLite 3.40.1 and was
retained as rejected; a new public CLI repair family qualified as its replacement.
The planned admitted allocation remains 8 rank-train / 2 rank-dev / 4 gate-fit /
2 gate-calibration / 4 final-test, including 2 from the unseen csv-diff repository.

The index retains every completed four-cell qualification attempt. Two initial
selectors included same-family target variants in the regression subset; the
variants were assigned to target and both full four-cell checks repeated.
Seven controller-authored tests were subsequently formatted and had unused
imports removed; all seven full qualifications were repeated with final bytes.
Successful pre-format attempts are preserved alongside the final bindings.
No Agent attempts or training actions were run by this preparation controller.

Each cell includes the original image ID, candidate import identity, collection
IDs, exported JUnit SHA-256, and raw JUnit/result SHA-256. Container hostnames were
removed from exported JUnit. `index.json` has no raw host commands or private
paths. `qualification_binding` binds task, trusted files, harness and verifier.
Public evidence includes only minimum tests/requests, records and stack excerpts;
full third-party source checkouts remain external.

```sh
python scripts/repo_aware/recompute_qualification.py
```

This recomputes accepted decisions from JUnit cases and checksums, collection IDs,
installation/canary facts and base/reference case pairing. It does not execute
upstream sources, and hash matching does not replace runtime evidence.

The scope is intentionally bounded: protected regression is the selected public
behavior, not the entire upstream test suite. There is one unseen repository;
this permits a small migration observation, not broad cross-repository claims.
Repository snapshots can share ordinary historical source, so partitioning by
repair family does not establish corpus-level or pretraining decontamination.
Training must use only its allowed public request and bounded base context;
reference commits, trusted tests and qualification records are controller-only.
